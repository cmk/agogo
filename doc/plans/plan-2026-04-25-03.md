# Plan 2026-04-25-03 — `mode=click` metronome + divider-agnostic `bars=N` multiplier

## Goal

Add a per-channel "metronome" output mode that emits a MIDI Note On
per scheduled tick (configurable note, velocity, MIDI channel,
optional N-tick accent), and a mode-agnostic, divider-agnostic
`bars=N` multiplier that emits every Nth scheduled grid event
(with `grid=t1,bars=N` yielding every N bars). No new audio-output
plumbing — the click rides the existing `MidirSink`.

## Context

The cpal output stream is still input-only (`output_stub: [f32; 0]`
hardcoded at `crates/host-cpal/src/cpal.rs:156`); opening the
output side is the marquee deferred work for v0.4. To stay genuinely
small, the click is emitted as a MIDI Note On per scheduled tick
through the existing `MidirSink`. The user's hardware/soft synth
turns it into sound.

Three design pivots from interactive review of earlier drafts:

1. **`dev=` is the routing target; `mode=` is the role.** Don't
   overload `dev=midi|audio` with `dev=click` — click is a *role*
   that will eventually combine with `dev=audio` (audio metronome).
   New key: `mode=clock|click`, default `clock`. Every existing
   `--ch` spec parses unchanged.
2. **Nest output specifics under the agnostic role.** `ChannelMode`
   already names the role abstractly (`MidiClock`, `AnalogPulse`,
   …). The click variant follows suit — `ChannelMode::Click(
   ClickConfig)` — with MIDI particulars (note/vel/ch/accent)
   isolated to a nested `ClickConfig::Midi(MidiClickConfig)`.
   Future audio-sample or CV-impulse click outputs slot in as
   sibling `ClickConfig` variants without touching the agnostic
   shell.
3. **Bar multiplier is mode-agnostic, divider-agnostic, and lives
   on `Channel` not `ChannelMode`.** A channel with `bars=N` emits
   every `N` events from its scheduled tick stream — i.e. every
   `N × period(divider)` master ticks — regardless of mode (clock
   or click). Pre-filter on the scheduled events; renderer sees
   only the kept ticks. The key is called `bars=N` because the
   most idiomatic case is `grid=t1,bars=N` (literal N bars in 4/4),
   but the mechanism is just "every Nth grid event" and the parser
   does *not* gate it on the divider. Useful side effect: `grid=t8,
   bars=3` expresses a dotted-quarter period that isn't in
   `Grid::ALL`.

The per-channel accent counter (for `mode=click,accent-every=N`)
and the bar-multiplier counter (for `bars=N`) are two distinct
per-channel `u32`s owned by `Playhead`, parallel-indexed with
`self.channels`. Both reset on transport stop.

### T2 — `Channel.bar_multiplier`

`crates/core/src/channel/mod.rs` (or wherever `Channel` is declared):

```rust
/// Period multiplier on the channel's grid output. When `Some(N)`,
/// the channel emits every Nth `tick_stream_into` event (a pre-
/// renderer filter in `Playhead::on_buffer`). The name reflects
/// the most idiomatic case (`grid=t1,bars=N` = N literal bars in
/// 4/4); the mechanism is divider-agnostic.
pub bar_multiplier: Option<core::num::NonZeroU16>,
```

Default `None`. `Channel` stays `Copy + Clone + Eq + PartialEq`.

**Why u16, not u32.** `Tick` is `u32` (`time/tick.rs:28`) and the
worst-case period is `bars × Grid::T1.tick_count() = bars × 3840`
ticks (any non-T1 divider has a smaller period and so a smaller
worst-case multiplied period). `u16` caps `bars` at 65,535, so
the worst-case multiplied period is `65,535 × 3840 ≈ 251M` ticks
— well inside `u32::MAX (≈ 4.29B)` with no overflow-check
arithmetic needed. At 120 BPM in 4/4 with `grid=t1`, 65,535 bars
≈ 36 hours; at 30 BPM, ~6 days. NonZeroU16 also saves 2 bytes
per Channel vs NonZeroU32.

Update fixture builders (`zero_channel` helpers in tests across
`channel/`, `out/midi.rs`, `control/transport.rs`, `host-cpal/`) to set
`bar_multiplier: None`.

### T4 — `render_midi_click_block` + dispatch

`crates/core/src/out/midi.rs`:

Add MIDI Note constants:

```rust
pub const MIDI_NOTE_ON:  u8 = 0x90;  // OR with channel 0..=15
pub const MIDI_NOTE_OFF: u8 = 0x80;
```

Add per-tick render helper:

```rust
/// Render a block of click events as MIDI Note On + same-sample
/// Note Off per tick. The same-sample Off keeps stateful synths
/// from holding the note; percussive drum patches ignore the Off
/// and run their own envelope to silence.
///
/// `counter` is read+advanced once per event. When
/// `cfg.accent` is `Some(a)`, the renderer picks `a.note`/`a.vel`
/// whenever `*counter % a.every.get() == 0`. Counter wraps on
/// overflow (saturating-add would freeze accents at u32::MAX).
pub fn render_midi_click_block(
    events: &[ScheduledEvent],
    cfg: &MidiClickConfig,
    counter: &mut u32,
    sink: &dyn MidiSink,
) {
    for ev in events {
        let (n, v) = match cfg.accent {
            Some(a) if *counter % a.every.get() == 0 => (a.note, a.vel),
            _ => (cfg.note, cfg.vel),
        };
        sink.send_at(&[MIDI_NOTE_ON  | cfg.ch, n, v], ev.sample_index);
        sink.send_at(&[MIDI_NOTE_OFF | cfg.ch, n, 0], ev.sample_index);
        *counter = counter.wrapping_add(1);
    }
}
```

### T5 — Spec parser

`crates/core/src/channel/spec.rs`:

1. Add to `ChannelSpec`:
   ```rust
   pub mode: ChannelMode,                       // default MidiClock
   pub bars: Option<core::num::NonZeroU16>,
   ```
   Reusing `ChannelMode` directly avoids a parallel
   spec/runtime type hierarchy. The parser builds the same enum
   that runtime uses; `into_channel` is then a near-trivial copy.

2. New parser keys:
   - `mode` → `clock | click` (any other → `BadValue("mode", _)`).
     `clock` → leave `spec.mode = ChannelMode::MidiClock`.
     `click` → defer until all click keys are seen, then build
     `ChannelMode::Click(ClickConfig::Midi(MidiClickConfig{...}))`
     in a post-loop assembly step.
   - `note` → u8 in `0..=127`.
   - `vel` → u8 in `1..=127` (vel=0 is Note Off — explicit reject).
   - `mch` → u8 in `1..=16`, mapped to 0-based `ch` at the parser
     boundary (so `MidiClickConfig.ch` is always 0..=15).
   - `accent-every` → u32 (NonZeroU32 wrapper after parse).
   - `accent-note` → u8 in `0..=127`.
   - `accent-vel` → u8 in `1..=127`.
   - `bars` → u16 (rejects > 65,535 with the standard u16
     parse error), wrapped in NonZeroU16.

3. Cross-key validation in a post-loop assembly step:
   - **mode=click** requires `note` + `vel`. `mch` defaults to 10.
     If `accent-every` is set, require `accent-vel`; use
     `accent-note ?? note`. Build the nested
     `ChannelMode::Click(ClickConfig::Midi(...))`.
   - **mode=clock** (default) rejects all click keys with
     `BadValue("note", "only valid with mode=click")` etc.
   - **bars** is divider-agnostic — only validates `N > 0` (via
     `NonZeroU16::new`). `bars=N` on any divider means "emit every
     Nth scheduled event"; `grid=t1,bars=4` is the idiomatic 4-bar
     marker case but `grid=t8,bars=3` (dotted-quarter period) is
     equally valid.

4. `Display`:
   - When `mode = ChannelMode::Click(ClickConfig::Midi(cfg))`,
     emit `,mode=click,note=N,vel=V,mch=M(=cfg.ch+1)` and accent
     fields conditionally.
   - When `mode = ChannelMode::MidiClock`, emit nothing for
     the mode (default).
   - When `bars = Some(n)`, emit `,bars=N`.

5. Parser tokenizer doesn't change — it's already key-agnostic.

6. **Renamed**: the click-accent key is `accent-every=N`, **not**
   `bar=N`, to avoid name collision with the new mode-agnostic
   `bars=N` (different rate, different layer).

7. Extend `arb_spec` proptest strategy: 50/50 generate Clock vs
   Click with arbitrary nested fields; populate `bars` only when
   `div == Grid::T1`. The existing `spec_round_trip` proptest
   then exercises Click round-tripping automatically.

## Review

### Design deviations from the plan

- **`bars=N` ungated.** The first draft restricted `bars=N` to
  `grid=t1` so the bar metaphor stayed honest. During planning the
  user pointed out the gate was unnecessary — the per-channel
  counter filter works on any divider, and useful periods like
  `grid=t8,bars=3` (dotted-quarter cadence) aren't in `Grid::ALL`
  so removing the gate is a strict expressivity win. The
  `parse_accepts_bars_on_any_divider` test pins this.
- **`bar=N` → `accent-every=N` rename.** The accent counter spec
  key was originally `bar=N` but was renamed mid-design to avoid
  collision with the new mode-agnostic `bars=N`. Different rates
  (per-emitted-click vs. per-divider-tick) at different layers
  (renderer vs. scheduler-filter) deserve different names.
- **Nested `ClickConfig`, not flat `MidiNote { note, vel, ch, … }`.**
  Earlier drafts placed MIDI particulars directly on
  `ChannelMode::MidiNote` and as flat `ChannelSpec` fields. The
  user flagged that the agnostic role layer shouldn't carry
  output-specific data. The shipped shape is
  `ChannelMode::Click(ClickConfig::Midi(MidiClickConfig{...}))`,
  with the inner `MidiClickConfig` isolating the MIDI specifics.
  Future audio-sample / CV-impulse click outputs slot in as
  sibling `ClickConfig` variants without touching the agnostic
  shell.
- **Self-review near-miss.** The click-key rejection branch
  initially used `Box::leak` to coerce a runtime `&str` to
  `'static` (because `BadValue`'s first param requires `'static`).
  Replaced with a `const &[&str]` array of literals (which
  default to `&'static str`) — same behavior, no leak.
- **`Channel.bar_multiplier` typed `Option<NonZeroU16>`, not
  `NonZeroU32`.** The user flagged that the bars cycle shouldn't
  exceed agogo's playable horizon. `Tick(u32)` and
  `Grid::T1.tick_count() = 3840` give an absolute horizon of
  ~1.1M bars; `NonZeroU16` (max 65,535) caps at ~5.8% of that
  with comfortable headroom (~36 hours at 120 BPM in 4/4),
  saves 2 bytes per Channel, and makes `bars × 3840` fit in u32
  with no overflow-check arithmetic.

### Recommendations

- The `expect("ChannelMode::Click(_) requires a counter slot from
  Playhead")` panic in `render_channel_block` is a programmer-error
  contract: every `Playhead`-driven call site supplies the counter
  via `Some(&mut self.click_counters[idx])`, and the existing test
  call sites that construct `MidiClock`-only channels pass `None`.
  A follow-up could replace `Option<&mut u32>` with a typed
  builder pattern to make the contract structural rather than
  runtime, but that's a larger refactor than this sprint warrants.
- `Channel.bar_multiplier` and `Playhead.bar_counters` advance only
  when the channel actually has a multiplier. For non-multiplier
  channels the parallel-`Vec<u32>` slot is dead weight — a few u32s
  per channel, negligible. If channel counts ever explode (10³+),
  a `HashMap<usize, u32>` keyed only on multiplier-using channels
  would save the allocation; today the parallel-vec is simpler.

### Deferred design tensions (follow-on PR)

User flagged two design issues during local review that pre-date
this sprint or surface as a side effect of it. Both are tracked
for an explicit follow-on plan:

**Decoupled `ChannelDev` and `ChannelMode` admit nonsensical pairs.**
`ChannelSpec::dev` (the routing target) and `ChannelSpec::mode`
(the role) are currently independent fields. The combination
`dev=audio,mode=click` would pair a MIDI Note On payload with an
audio routing target. Today this is a non-issue because
`dev=audio` returns `AudioDeferred` at parse time, but once v0.4
lights up the audio output side, the type system won't prevent
audio + Click(Midi) from co-occurring. Two resolution shapes:
1. Encode routing in the `ClickConfig` variant (`Midi` ↔ MIDI sink,
   future `Audio` ↔ cpal output) and drop the `dev=` key entirely
   — derive the sink from the mode.
2. Keep `dev=` and add a parser-level cross-key validation that
   rejects `dev=audio,mode=click` when the inner `ClickConfig`
   variant is `Midi` (and vice versa).

Option 1 is cleaner but contradicts the earlier "dev= and mode=
are two orthogonal axes" design direction. Worth an explicit
design conversation before v0.4 work that lights up
`dev=audio` lands.

**`bars=N` spec key is a colloquial-but-imprecise name.** The
field semantics are "emit every N grid events," which equals
"every N bars" only when `grid=t1` in 4/4. On any other divider
the name is misleading. Candidate renames that came up in
discussion: `period=N` (precise, generic), `every=N` (clean but
collides with `accent-every`; would require renaming the accent
key too — e.g. `accent-period=N`). Postponed because the rename
ripples through ~6 sites and the choice of new name is
subjective.
