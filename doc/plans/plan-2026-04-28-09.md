# Plan 2026-04-28-09 — Decouple `agogo-cli` from `agogo-host-link`

## Goal

Stop the trend of pulling `agogo_host_link::*` types into `crates/cli/`,
and along the way fold in three trivial CLI-polish items that ride
along on the same files. After this sprint, `cargo build -p agogo-cli
--no-default-features --features core,cpal,midi` is verified by CI as
a regression net (already passes today; the gate ensures it stays
that way). T1 closes the long-deferred "wire snap_intent into the
orchestrator" item by pushing the walk into `host-link` itself rather
than adding a sixth `LinkSession` call site to the cli.

**Note on the `--no-default-features --features cpal,midi` (no core)
build break.** That deferred item from `doc/todo.md` is a separate
concern from this sprint — it's about the `core` feature gate, not
about Link. `time_sched.rs` is pulled in at module scope by the
top-level `Cli` enum and uses `agogo_core::*` unconditionally, so
without `core` the parser doesn't compile. Out of scope here; tracked
for a follow-up plan.

The coupling that exists today (the targets):

- `crates/cli/Cargo.toml:33` — path dep on `agogo-host-link`, gated by
  the `link` feature, which the `run` feature pulls in.
- `crates/cli/src/main.rs:215-216` — `agogo_host_link::Quantum` is the
  type of the top-level `--quantum` flag; **not feature-gated at the
  use site**, so without `link` the parser fails to compile.
- `crates/cli/src/main.rs:398` — `pub(crate) use agogo_host_link::parse_quantum_from_beats;`.
- `crates/cli/src/run.rs:31-32` — five Link types imported at module
  scope: `HostTimeAnchor`, `LinkPhaseSource`, `LinkSession`,
  `LinkSessionHandle`, `LinkWriteConfig`, `Quantum`.

The previously-considered "wire snap_intent into the orchestrator"
deferred item adds *another* `LinkSession` call site to `cli/src/run.rs`
— this plan does the inverse: pushes the snap-walk down into
`agogo-host-link` so the cli has one helper call instead of duplicating
loop logic.

## Tasks

### T1 — Push the snap-walk into `agogo-host-link`

**Problem.** Today `host-link/tests/bidirectional.rs:228-233` is the
*only* call site of `LinkSession::snap_offset_for`. The orchestrator
in `crates/cli/src/run.rs` doesn't walk `args.ch` specs to apply the
delta — production code skips a feature the test suite proves works.
The natural fix is "add a loop to `cli/src/run.rs`," but that adds a
sixth `LinkSession` call site to the cli crate, widening exactly the
coupling this plan is trying to reduce.

**Solution.** Add `pub fn apply_snap_offsets(specs: &[ChannelSpec],
session: &mut LinkSession, channels: &mut [Channel])` to
`crates/host-link/src/session.rs` (or a new `run_helpers.rs` if it
grows beyond the one helper). The helper walks the spec list,
calls `session.snap_offset_for(spec.snap_intent())` per channel, and
applies the resulting `Micro` delta to `channel.offset`.

`cli/src/run.rs` then calls the helper once after the `LinkSession`
is built. The cli's import surface grows by zero — `LinkSession` is
already in scope.

The `ChannelSpec → snap_intent → Micro` accessor is in
`crates/core/src/machine/spec/types.rs:73`; the `Channel.offset` field
is in `crates/core/src/channel/transform.rs`'s `ChannelCommon`. Both
are public and stable.

### T2 — Audit existing link gating + add CI regression net

**What I expected to find.** `cli/src/main.rs:215-216` declares a
top-level `--quantum` field of type `agogo_host_link::Quantum`,
unconditionally pulling Link types into the parser struct. The plan
proposed adding `#[cfg(feature = "link")]` to gate it.

**What's actually there.** The `quantum: agogo_host_link::Quantum`
field at `main.rs:215-216` is **already inside `Command::Transport`**,
which lives under `#[cfg(feature = "link")]` at `main.rs:159`. The
`pub(crate) use agogo_host_link::parse_quantum_from_beats;` at
`main.rs:398` is **already** `#[cfg(feature = "link")]`-gated (line
397). The `RunArgs.link_quantum: Option<Quantum>` field at
`run.rs:80` lives in `cfg(feature = "run")`, and `run` requires
`link`. Conclusion: the cli/Link decoupling T2 was meant to deliver
is **already in place**.

**Verification.** `cargo build -p agogo-cli --no-default-features
--features core,cpal,midi` succeeds with no errors.

**Solution.** No code change to `main.rs` or `Cargo.toml`. Instead,
add a `cli-no-link` CI job to `.github/workflows/ci.yml` that runs:

```
cargo build -p agogo-cli --no-default-features --features core,cpal,midi
cargo clippy -p agogo-cli --no-default-features --features core,cpal,midi --all-targets -- -D warnings
```

This pins the no-link build as a regression net so future PRs can't
silently re-couple the cli to host-link. Without the gate, a
contributor could move a Link import to module scope without the
breakage being visible to CI.

**What this does NOT close.** The `doc/todo.md` deferred item titled
"`cargo build -p agogo-cli --no-default-features` build break" is a
**different** problem — it's about the `core` feature gate, not
`link`. `time_sched.rs` uses `agogo_core::time::*` unconditionally
and is pulled in at module scope by the top-level `Cli` enum (via
`Schedule(time_sched::ScheduleArgs)`), so without `core` the parser
doesn't compile. Fixing that requires either dropping the `core`
feature gate (making `agogo-core` non-optional) or restructuring
`time_sched`'s parser surface to not require core types — both
larger than this sprint. **Tracked for a follow-up plan; explicitly
out of scope here.**

### T3 — Audit residual `agogo_host_link::*` imports in `cli/src/`

**Problem.** After T1+T2, what's left? Grep finds:
`HostTimeAnchor`, `LinkPhaseSource`, `LinkSession`, `LinkSessionHandle`,
`LinkWriteConfig`, `Quantum` at `cli/src/run.rs:31-32`. These are all
constructed inside the `--source link` branch at `cli/src/run.rs:193-227`.

**Solution.** Confirm every remaining `agogo_host_link::*` use sits
inside a `if matches!(args.source, Source::Link) { ... }` block (or
its compile-time equivalent). If a leak is found (a Link type used
outside the link-source branch), either move the use inside the branch
or note it for follow-up. Add a top-of-file comment to `cli/src/run.rs`
documenting the scoping rule: "Link types are only constructed inside
the `Source::Link` branch; if you need a Link type at module scope,
re-evaluate the design."

No code change unless a leak is found — this is a documented audit
pass that closes the architectural loop.

### T4 — Drop `agogo-cli` binary alias

**Problem.** `crates/cli/Cargo.toml:49-51` ships both `agogo` and
`agogo-cli` binaries pointing at the same `src/main.rs`. Per
`doc/todo.md`, external scripts have migrated since v0.1; the
duplicate `[[bin]]` entry is dead weight.

**Solution.** Delete the second `[[bin]]` entry. ~3 lines.

### T5 — Add `#[bpaf(version)]` flag

**Problem.** `agogo --version` prints nothing useful today. The
`#[bpaf(version)]` attribute is the one-line fix from the bpaf-swap
follow-up list.

**Solution.** Add the attribute to the top-level `Cli` parser struct
in `crates/cli/src/main.rs`. ~2 lines.

### T6 — Mark `CvRole` / `DinRole` `#[doc(hidden)]`

**Problem.** `crates/core/src/channel.rs:18-19` re-exports `CvRole`
and `DinRole` at the crate's public surface, but both are forward-
compat scaffolding for v0.2 (DIN sync24) and v0.4 (CV pulse / LFO)
backends — neither has a renderer in v0.1. They appear in `cargo doc`
output as user-facing without any usable behaviour behind them.

**Solution.** Add `#[doc(hidden)]` to the re-exports. When the
respective backends ship, the attribute comes off in the same plan
that lands the renderer.

## Deferred

- **The `--quantum` arg itself doesn't move out of the cli crate.**
  The argv-parsing surface has to live where bpaf is invoked
  (`cli/main.rs`); the goal is *gating*, not relocation. A future
  plan could wrap bpaf in `host-link` and re-export the parsed
  struct, but that's a larger refactor than this sprint's scope.
- **Wire `snap_intent` into the orchestrator** (the deferred item
  from `doc/todo.md` "CLI surface & ergonomics") **is closed by T1**
  — but via a helper in `host-link/`, not as a `cli/run.rs` loop as
  the original deferred entry framed it.
- **The deferred `cargo build -p agogo-cli --no-default-features --features cpal,midi`
  build break** — **NOT closed by this sprint.** Investigation in T2
  found this break is about the `core` feature, not `link`. Adding
  `core` to the feature list (`--features core,cpal,midi`) succeeds
  today, and T2's CI regression net pins that. The actual no-core
  break needs its own plan to either drop the `core` feature or
  restructure `time_sched`'s parser surface.
- **The deferred `agogo-cli` binary alias** — closed by T4.
- **The deferred `#[bpaf(version)]` flag** — closed by T5.
- **The deferred `channel.rs` re-export hub audit** — closed by T6.

`doc/todo.md` will need a sweep after this lands to mark these items
resolved (separate doc-only commit).

- **`compose!` / `ceiling1` body cleanups** stay deferred — wants its

- **Tempo → f64 sweep at `link.rs:68, :160`** is **stale** — the
