# Plan 2026-05-02-08 - Command admission envelope

## Goal

Upgrade the agogo host control bridge from raw command writes to the
v0.2 admission contract: every soft command carries an id, source id,
time domain, deadline, coalesce key where applicable, and a structured
accepted / rejected / late result before it can affect the RT side.

This is the next hard-time steel-thread step from
`doc/versions/version-0.2.md`. The existing bridge already separates
last-value controls from ordered SPSC commands; this sprint makes that
separation observable and deadline-aware without adding a direct
stdio-core dependency.

## Context Read

- `doc/versions/version-0.2.md` makes command admission metadata part
  of v0.2, alongside explicit queue-full, late-command, invalid-domain,
  and unsupported-command-class results.
- `doc/designs/control-plane.md` keeps the bridge shape in agogo core
  or host adapter code: atomic scalars for last-value controls and an
  SPSC ring for ordered operations, read once per buffer.
- `doc/designs/snapshot.md` remains telemetry-only. Admission faults
  may become snapshot-visible later, but control must not route through
  observation.
- `doc/designs/output.md` and `doc/designs/transport.md` point at later
  v0.3/v0.4 work; they do not change this sprint's bridge scope.

## Tasks

### T1 - Admission types + RT buffer epoch

Problem or motivation: `ControlCommand` currently carries only the
operation payload, and successful tool calls return
`{ "accepted": true, "applies_by": "next_buffer" }` without the command
identity or deadline needed by the steel-thread log.

Solution / implementation approach: Add typed metadata around commands:
`CommandId`, `SourceId`, `CommandTimeDomain`, `CommandDeadline`,
`CoalesceKey`, `AdmissionMetadata`, `CommandEnvelope`, and
`AdmissionOutcome`. Track the RT side's current buffer epoch in a shared
atomic; the producer derives the default deadline from that epoch and the
consumer advances it exactly once per callback buffer.

Types / API surface: `ControlCommand` stays the operation enum.
`ControlConsumer::begin_buffer()` becomes the per-buffer boundary call
that returns `ControlParams` and advances the epoch. Existing
`snapshot()` can remain as a read-only helper for tests.

### T2 - Producer admission API

Problem or motivation: `ControlProducer::set_tempo` and `try_push`
cannot distinguish accepted, rejected, late, queue-full, or unsupported
commands. Ordered command loss is visible only as a generic
`BridgeError`.

Solution / implementation approach: Introduce producer methods that
return `AdmissionOutcome`:

- last-value tempo writes use a scalar admission path and coalesce by
  the tempo key;
- ordered controls enqueue `CommandEnvelope`;
- unsupported time domains reject before touching the RT queue;
- explicit deadlines at or behind the current RT epoch return `late`;
- full SPSC queues return `rejected` with `QueueFull`.

Types / API surface: Keep a compatibility shim only where it avoids
unrelated churn in tests. Prefer new code paths to call
`admit_tempo` / `admit_ordered` rather than `set_tempo` / `try_push`.

### T3 - Driver metadata parsing + response JSON

Problem or motivation: `AgogoDriver::handle_call` currently accepts
only tool-specific arguments. It has no way to propagate stdio-core
request identity, source identity, coalescing, or a caller-declared
deadline into the bridge.

Solution / implementation approach: Parse optional metadata fields from
the tool argument object:

- `command_id` defaults to a driver-local monotonic id;
- `source_id` defaults to `"agogo.driver"`;
- `time_domain` defaults to `"rt_buffer"`;
- `deadline_buffer` defaults to the next RT buffer epoch;
- `coalesce_key` is accepted for last-value tempo and rejected for
  ordered tools until ordered coalescing has a real queue policy.

Successful syntactic calls return structured JSON with
`status = "accepted" | "rejected" | "late"`, the command id, source id,
time domain, deadline, and optional rejection reason. Unknown tools,
unmounted driver calls, and malformed JSON arguments remain normal tool
errors.

Types / API surface: The response stays `serde_json::Value` for now so
the adapter remains stdio-core-compatible without importing stdio-core.

### T4 - Consumer deadline drain + docs repair

Problem or motivation: The audio side can pop FIFO commands, but it
does not yet know whether an accepted envelope met its declared
deadline.

Solution / implementation approach: Add an RT-side drain API that yields
either an applicable command envelope or a missed-deadline fault. Tests
drive `begin_buffer()` and `drain_due_commands()` directly; wiring those
commands into `Playhead` transport mutation can stay a follow-up unless
the implementation proves small enough to include without hiding the
admission contract.

Also repair the active crate-level comment in `crates/host/src/lib.rs`
that says the direct `stdio_core::driver::StudioMcpServer` impl is the
next slice. The current next slice is admission metadata; the direct
trait impl still waits on the dependency boundary.

Types / API surface: Export the new admission and fault types from
`agogo_host` so future stdio-core integration can log the same semantic
ids and reasons.

### T5 - Verification

Problem or motivation: The admission contract is easy to fake with a
happy-path JSON response while still silently losing overloaded or late
commands.

Solution / implementation approach: Add property and spot coverage over
the bridge and driver response surface. Keep all JSON parsing,
serialization, logging, and stdio-core-specific adaptation off the RT
path.

## Verification

### Properties (must pass)

| Property | Module | Invariant |
| --- | --- | --- |
| `command_admission_is_total` | `agogo_host::bridge` | Generated valid command metadata always returns exactly one of accepted, rejected, or late; no panic and no silent loss. |
| `accepted_command_has_declared_deadline` | `agogo_host::bridge` | Every accepted scalar or ordered command carries command id, source id, time domain, and deadline. |
| `accepted_command_applies_by_deadline` | `agogo_host::bridge` | A command accepted for a future RT buffer is drained by that buffer or produces a missed-deadline fault. |
| `queue_full_rejects_with_reason` | `agogo_host::bridge` | Saturating the ordered SPSC returns `QueueFull` with the command id instead of dropping. |
| `invalid_time_domain_rejected` | `agogo_host::driver` | Unsupported time domains reject before reaching the RT queue. |
| `last_value_tempo_coalesces_by_key` | `agogo_host::bridge` | Multiple accepted tempo writes before a buffer leave the latest value visible at the next buffer boundary. |
| `control_independent_of_observation` | `agogo_host::driver` | Tool admission succeeds or rejects without any snapshot reader, observation sink, or stdio-core subscriber. |

### Spot checks

| Check | Expectation |
| --- | --- |
| `agogo.tempo.set` with no metadata | Response defaults id/source/deadline and accepts for the next RT buffer. |
| `agogo.start` with `coalesce_key` | Rejects with `UnsupportedCommandClass` until ordered-command coalescing is designed. |
| `agogo.locate` with stale `deadline_buffer` | Returns `late` and does not enqueue. |
| queue capacity one, two ordered calls | First accepts; second rejects with `QueueFull` and preserves the first envelope. |
| malformed metadata object | Returns a precise tool error and does not touch bridge state. |

## Deferred

- Direct `stdio_core::driver::StudioMcpServer` implementation remains
  deferred until the dependency/MSRV boundary is compatible with this
  workspace.
- Applying every admitted ordered command to `Playhead` transport state
  can follow the envelope contract if it expands beyond a local patch.
- Ordered-command coalescing is deferred. The safe v0.2 rule is to
  preserve FIFO ordering for ordered commands and reject ordered
  coalesce requests explicitly.
- Host-time, tick-time, and Link-time deadline domains are deferred to
  the v0.3 clock-domain work. This sprint supports RT-buffer deadlines
  and rejects unsupported domains truthfully.

- Implementation kept ordered-command application to `Playhead`
  transport state deferred. The admission envelope, deadline tracking,
  and missed-deadline drain fault are now explicit; mutating the
  runtime from those envelopes remains the next control application
  slice.
- Local review found two deadline-race issues: tempo admission could
  report accepted after missing its buffer deadline, and the
  compatibility `try_push` shim could map late admission to `Ok(())`.
  Both are fixed in the review-round commit.
- The second local review found that the first scalar race fix could
  publish tempo and then revise the outcome to `late`. The final fix
  keeps admitted tempo pending until the RT buffer boundary consumes it,
  so the bridge no longer rolls back or rewrites scalar admission after
  publication.
- The third local review found that widening scalar deadlines was still
  not truthful, tempo accepted arbitrary coalesce keys, and the
  admission proptests under-sampled `u64` deadlines. Fixed by keeping
  admitted tempo pending until the RT buffer boundary consumes it,
  preserving caller-declared deadlines, rejecting non-`tempo` scalar
  coalesce keys, and broadening deadline properties with explicit
  boundary spot checks for the intentionally bounded drain simulation.
- The fourth local review found two pending-tempo races: back-to-back
  tempo writes could mix a new tempo/deadline with an old generation,
  and producer-side timeout polling could report `late` after the RT
  side had already claimed the update. Fixed by publishing pending
  tempo with an atomic seqlock and replacing timeout polling with a
  claimed-state transition visible to both sides.
- No properties were left `#[ignore]`.
