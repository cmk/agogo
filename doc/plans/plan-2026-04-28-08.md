# Plan 2026-04-28-08 — Distribute kitchen-sink `arb.rs` per type module

## Goal

`crates/core/src/arb.rs` is a 307-line aggregator that holds proptest
strategies for **9 different domain types** plus an unrelated runtime
synthetic-signal generator (`pulse_train`). The kitchen-sink layout
violates the colocation pattern the rest of the workspace (and
upstream `connections`) uses: every type owns its own `arb.rs`, no
aggregating root file. Promote each strategy to its type's submodule;
move `pulse_train` out of `arb.rs` entirely (it isn't testkit).

The cleaner shape after this sprint:

```
crates/core/src/
├── lib.rs                       # `pub mod arb;` line removed
├── testing.rs                   # unchanged
├── time.rs
├── time/
│   ├── conn.rs                  # + `#[cfg(any(test, feature = "testkit"))] pub mod arb;`
│   ├── conn/arb.rs              # NEW: arb_rational_nonneg
│   ├── decimal.rs               # + arb mod decl
│   ├── decimal/arb.rs           # NEW: arb_jitter_sigma
│   ├── grid.rs                  # + arb mod decl
│   ├── grid/arb.rs              # NEW: arb_grid
│   ├── sample.rs                # + arb mod decl
│   ├── sample/arb.rs            # NEW: arb_sample_rate
│   ├── swing.rs                 # + arb mod decl
│   ├── swing/arb.rs             # NEW: arb_swing
│   ├── tbase.rs                 # + arb mod decl
│   ├── tbase/arb.rs             # NEW: arb_tbase
│   ├── tempo.rs                 # + arb mod decl
│   ├── tempo/arb.rs             # NEW: arb_bpm

```

path with `#[cfg(any(test, feature = "testkit"))]` at the file scope.
Add `#[cfg(any(test, feature = "testkit"))] pub mod arb;` to the
parent type's module file.

| Strategy | New file |
|----------|----------|
| `arb_bpm` | `crates/core/src/conn/arb.rs` |
| `arb_sample_rate` | `crates/core/src/conn/arb.rs` |
| `arb_jitter_sigma` | `crates/core/src/conn/arb.rs` |
| `arb_tbase` | `crates/core/src/time/arb.rs` |
| `arb_grid` | `crates/core/src/time/arb.rs` |
| `arb_tick`, `arb_time`, `arb_small_time` | `crates/core/src/time/arb.rs` |
| `arb_rational_nonneg` | `crates/core/src/conn/arb.rs` |

`arb_integer_stc` was already correctly colocated as a private
`fn` inside `crates/core/src/time/conn.rs`'s `mod tests` —
it's small, private, and only used by that one test module. No

Two strategies depend on each other: `arb_swing` uses `arb_tbase`,

imports (`use crate::time::arb::arb_tbase` from
`crates/core/src/time/arb.rs`, etc.) — verbose, but truthful
about the dependency.

Update import sites:
- Internal callers in `time/{conn,tick,tbase,swing}.rs`,
  `channel/{transform,scheduler}.rs`, `sync/{pll,detect}.rs` — each
  switches `use crate::arb::{arb_grid, arb_tick, ...}` to the
  appropriate per-type path.
- External callers (cli, host-link): grep `use agogo_core::arb::`
  and rewrite. From the previous audit:
  - `cli/src/sync_trace.rs` — uses `pulse_train` (handled in T2).
  - No external strategy callers exist today; the testkit feature's
    cross-crate consumers are aspirational. The rename leaves the
    feature gate in place for future use.

Tests that lived inline in `arb.rs` for the strategies themselves
(`arb_bpm_in_range`, `arb_sample_rate_is_standard`,

### T2 — Move `pulse_train` to `sync/pulse_train.rs`

`pulse_train` is a runtime synthetic-signal generator (Hann bell
train, deterministic via PCG-64 seed) used by `cli/sync_trace`,
`sync::pll` tests, and `sync::detect` tests. It is NOT testkit-gated
today and NOT a proptest strategy. It belongs with its consumers.

- Create `crates/core/src/control/sync/pulse.rs` with the function,
  `PULSE_WIDTH_PS`, and the three `pulse_train_*` tests
  (`pulse_train_shape_basic`, `pulse_train_zero_pulses_is_empty`,
  `pulse_train_is_deterministic_in_seed`).
- Add `pub mod pulse_train;` to `crates/core/src/control/sync.rs`.
- Update `cli/src/sync_trace.rs`:
  `use agogo_core::arb::pulse_train` → `use agogo_core::control::sync::pulse_train::pulse_train`.
- Update `sync/pll.rs` and `sync/detect.rs` test modules:
  `use crate::arb::pulse_train` → `use crate::control::sync::pulse::pulse_train`.

`pulse_train` itself is non-testkit (regular `pub fn`); the three
in-file tests stay `#[cfg(test)]`. The `arb_*` strategies the
old `pulse_train` tests *don't* depend on, so no testkit gate
is needed on the new file.

### T3 — Delete `crates/core/src/arb.rs`; remove `pub mod arb`

After T1 and T2, `arb.rs` is empty (only the kitchen-sink file
header is left). Delete it. Remove `pub mod arb;` from
`crates/core/src/lib.rs`.

The `_sample_rate_sealed` / `S048_HZ` defensive references in
the old `arb.rs` exist only to keep the `SampleRate` trait import
warning-free on non-testkit builds. After T1, the `arb_sample_rate`
strategy file imports the trait directly, so the defensive bridge
isn't needed.

## Deferred

- `crates/core/src/conn/boundary.rs` keeps its current shape. Splitting
  by argv/PI/rate categories would multiply the
  `scripts/check-floats.sh` allowlist for no real navigation gain.
- A separate `agogo-testkit` crate is not warranted today (no
  cross-crate `arb_*` consumers). The per-type colocation done here
  is a clean migration target if external consumers ever appear —
  the `agogo-testkit` crate would just re-export each type's
  `arb` submodule.
- Per-type `prop.rs` files for law predicates: agogo currently
  doesn't author its own law predicates (consumes upstream
  `connections::prop::conn` directly). When agogo's own algebras —
  the DSL's grammar laws, machine-spec round-trip — earn law
  predicates, those go to `<module>/prop.rs` alongside `<module>/arb.rs`.

## Resolved decisions

- **Per-type colocation, not a `prop/` aggregating module.** Plan
  follows the Haskell `Test/Data/Connection/{Float,Int,...}.hs`
  shape: each algebra owns its strategies. Upstream Rust
  `connections::prop::arb` aggregates because it's a small crate
  with one clear domain (Galois connections); agogo has multiple
  coexisting domains (time, sync, channel, dsl) that benefit from
  per-type ownership.
- **`testkit` feature flag stays.** The aspirational external
  consumer pattern (downstream proptests that import agogo_core
  arb strategies) survives the reorg — each per-type `arb.rs` is
  gated `#[cfg(any(test, feature = "testkit"))]`.
- **`pulse_train` is not testkit.** Its CLI consumer
  (`sync_trace`) is a runtime command, not a test. Move to a
  regular `pub` module under `sync/`.

## Review

All three tasks landed atomically in one commit (`debt: Distribute
kitchen-sink arb.rs to per-type submodules`). No `#[ignore]`'d
properties added; existing test suite (950 lib + 17 + 17 + 1 doctest)
unchanged in count and behaviour. Both feature configurations
verified independently: default (no testkit) and `--features testkit`.

**Design deviations from the plan.**

- `arb_integer_stc` was already a private fn inside
  `sync/sample_tick.rs`'s `mod tests` (not in the kitchen-sink
  `arb.rs`). It stays inline — small, private, single test consumer.
  The plan's Verification table mentioned a `sync/sample_tick/arb.rs`
  destination; that file is not created. Plan section was edited
  inline before T1 started to reflect this.
- `scripts/check-floats.sh` allowlist entry **moved** with
  `pulse_train` (was `crates/core/src/arb.rs`, now
  `crates/core/src/control/sync/pulse.rs`) — same exception class
  (synthetic-PCM generation through lawful Conn-inverse helpers
  `tempo_to_f64_bpm` / `pico_to_f64_seconds`). The CLAUDE.md
  exception list comment in the script header was updated in
  lockstep.
- `CLAUDE.md`'s proptest discipline section was rewritten to
  codify the per-type colocation rule (was: "shared across crates
  live in `crates/core/src/arb.rs`"; now: "colocated with the type
  they generate, no aggregating root file"). Future strategies
  land in the right place by default.

**Drift caught** (per the gardener rule):

- *None* in adjacent code — the grep for `crate::arb::` and
  `agogo_core::arb::` covered all 11 callsites and all updated cleanly.
  One latent gotcha: `sync/source.rs` had two
  `crate::arb::pulse_train::<S048>` raw qualified-path uses that
  weren't in `use` statements; the build caught those. No other
  weeds noticed in the files passed through.

**Recommendations.**

- A separate `agogo-testkit` crate stays deferred — no cross-crate
  consumers exist today, and the per-type colocation is the right
  migration target if external testkit consumers ever appear (each
  type's `arb` submodule re-exports cleanly).
- `crates/core/src/conn/boundary.rs` keeps its current shape per the
  plan's Deferred section. Not pressing.
