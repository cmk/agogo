# Plan 2026-05-04-02 - GitHub open-source readiness

## Goal

Prepare agogo for a public GitHub repository without taking on the crates.io
publishing contract. The public repo should be safe to browse, understandable
to a new reader, and honest about what works today versus what remains roadmap.

This plan does **not** remove maintainer identity. `Chris`, `cmk`,
`github.com/cmk/agogo`, and maintainer-owned public URLs are acceptable. The
PII scope here is full local home-directory pathnames from a contributor's
machine.

This plan also keeps every crate at `publish = false`. crates.io package
metadata and dry-run publishing are a later release-prep plan, not a GitHub
open-source prerequisite.

## Context

Current `main` is clean and already has useful public-facing pieces: MIT
license, CI, docs workflow, a root README, version roadmap docs, and a working
workspace build. The README is still too internal, and tracked docs still
contain full local paths from earlier planning and review records.

Current full-path hits from the macOS home-directory scan:

- `doc/plans/plan-2026-04-25-05.md`
- `doc/plans/plan-2026-04-27-03.md`
- `doc/reviews/review-00006.md`
- `doc/reviews/review-00023.md`

`doc/notes/` also contains local paths, but that directory is gitignored and
is not part of the public tree unless intentionally published later.

## Tasks

### T1 - Remove tracked full local pathnames

Replace tracked contributor-local home-directory references with repo-relative
prose, a short description of the local source, or an explicit note that the
original was a local planning artifact.

Do not rewrite historical intent more than needed. For review logs, keep the
review finding and the resolution, but avoid preserving the machine-local path.

### T2 - Add a full-tree local-path gate

Extend `scripts/check-pii.sh` or add a sibling script so public-release checks
can scan the tracked tree, not only staged additions.

Required behavior:

- flag macOS and Linux home-directory paths in tracked files;
- ignore the checker's own regex definitions;
- allow explicit exceptions through `.pii-allow` if needed;
- keep the staged-diff hook path fast.

The public release gate should be runnable in CI and locally.

### T3 - Rewrite the root README for public GitHub readers

Replace the current internal-agent-focused README with a comprehensive public
entry point:

- what agogo is: a Rust studio timing/sync engine inspired by multi-format
  clock hardware;
- current status and supported capabilities;
- install/build/test from source;
- hardware-free commands that always work;
- hardware-backed `agogo run` examples for MIDI and audio click;
- feature flags and detached host crates;
- timing accuracy caveats: internal sample scheduling vs best-effort midir vs
  future native timestamped backends;
- workspace architecture;
- roadmap pointer to `doc/versions/`;
- contribution workflow pointer to `AGENTS.md` without making agent workflow the
  opening pitch.

Keep GitHub badges and `cmk` URLs.

### T4 - Document the GitHub/crates.io split

Make the release status explicit in README:

- source builds are supported;
- crates are not yet published to crates.io;
- `publish = false` remains intentional;
- package metadata and `cargo publish --dry-run` belong to a later publishing
  plan.

### T5 - Update open-source checklist docs

If needed, add a short `doc/versions` or `doc/todo.md` note that GitHub
open-sourcing and crates.io publishing are separate milestones. Do not let the
README imply package registry availability.

## Deferred

- crates.io publishing readiness: package descriptions, keywords/categories,
  repository/homepage/documentation metadata, `cargo package --list`, and
  `cargo publish --dry-run`.
- Publishing or replacing the git dependency on `connections`.
- Removing historical GitHub review records wholesale. This plan only removes
  full local pathnames from tracked files.
- Hiding or renaming the maintainer handle. `cmk` is intentionally public.
