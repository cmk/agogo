# Plan 2026-05-03-01 - Apply admitted commands to Playhead

## Goal

Close the v0.2 control-application gap: commands admitted through the
host bridge must reach `Playhead` by their declared RT-buffer deadline
or produce an explicit fault. Plan 2026-05-02-08 made admission
truthful; this sprint makes accepted commands affect runtime state.

The narrow steel-thread target is `agogo.tempo.set` plus transport
start/stop. `locate` and channel reconfiguration are included only if
they can be made truthful without hiding larger v0.3/v0.4 design work
behind a stub.

## Context Read

- `doc/versions/version-0.2.md` requires soft commands to pass through
  the bounded RT bridge, apply at `Playhead::on_buffer`, and keep
  observation out of the control path.
- `doc/plans/plan-2026-05-02-08.md` completed command metadata,
  deadline admission, and `RtCommandDrain`, but deferred applying
  ordered commands to `Playhead` transport state.
- `doc/designs/control-plane.md` keeps the bridge shape as
  read-once-per-buffer atomics plus a bounded SPSC ring.
- `doc/designs/snapshot.md` stays telemetry-only; no command
  application may depend on an observation subscriber.

## Dependency Graph

```text
T1 Playhead command hooks
  -> T2 host RT command applicator
  -> T3 driver truthfulness for unsupported commands
  -> T4 callback and bridge tests
  -> T5 docs and verification
```

## Tasks

### T1 - Playhead command hooks

Problem or motivation: `Playhead` owns tempo-dependent scheduling and
transport state, but the host bridge can currently only expose admitted
command envelopes to tests. Accepted commands do not mutate runtime
state.

Solution / implementation approach: Add narrow RT-safe methods on
`Playhead` for command application:

- update tempo at a buffer boundary by refreshing `SampleTickConn` and
  any internal clock tempo state that must agree with it;
- start or stop transport through explicit command paths rather than
  through a soft-thread `PlayheadStopHandle` only;
- return a typed unsupported result for commands not implemented in
  this slice.

Types / API surface: Keep methods in `agogo_core::control` so
`agogo-host` can use them through the facade without linking to
backend crates.

### T2 - Host RT command applicator

Problem or motivation: `ControlConsumer::begin_buffer()` and
`drain_due_command()` are separate primitives. Callers need one small
RT-side adapter that advances the buffer, applies due commands, and
records missed-deadline or unsupported-command faults without
allocating.

Solution / implementation approach: Add a host-side applicator that
takes `&mut ControlConsumer` and `&mut Playhead<_>` at the buffer
boundary. It applies scalar tempo from `begin_buffer()`, drains ordered
commands until the ring is empty, and returns compact counters/status
for applied, missed, and unsupported commands.

Types / API surface: Prefer a fixed-size `CommandApplyReport` with
integer counters and no heap storage. The report is test-observable and
future snapshot-visible, but snapshots are not required for command
application.

### T3 - Driver truthfulness for unsupported commands

Problem or motivation: A command that reaches the RT applicator as a
known no-op violates the v0.2 contract. Accepted means "will apply by
deadline or fault"; it must not mean "lands in a queue and disappears."

Solution / implementation approach: Keep `agogo.tempo.set`,
`agogo.start`, and `agogo.stop` accepted when metadata is valid.
Either implement `agogo.locate` / `agogo.channel.configure` in T1/T2
or reject them with `UnsupportedCommandClass` before admission until
their runtime semantics are designed.

Types / API surface: Preserve the existing JSON response shape:
`status`, command metadata, time domain, deadline, and optional
rejection reason.

### T4 - Callback and bridge tests

Problem or motivation: A bridge can still pass admission tests while
runtime state remains unchanged. Tests need to drive the same buffer
boundary where the callback will apply commands.

Solution / implementation approach: Add direct bridge/applicator tests
for tempo and start/stop. Add a callback-level smoke test only if it
does not force platform `cpal` dependencies into the workspace gate.
Keep the allocation contract pinned by capacity/no-growth checks unless
an allocator harness is already available locally.

### T5 - Docs and verification

Problem or motivation: This sprint crosses the exact deferred item from
Plan 2026-05-02-08 and should leave the roadmap easy to follow.

Solution / implementation approach: Update crate docs or plan Review
notes for any deliberately unsupported command class. Do not edit
archival plans except to record current-sprint findings in this plan's
Review section.

## Verification

### Properties (must pass)

| Property | Module | Invariant |
| --- | --- | --- |
| `accepted_tempo_applies_by_deadline` | `agogo_host::bridge` | An accepted tempo command changes the buffer snapshot and `Playhead` scheduling by its declared RT buffer. |
| `accepted_start_applies_by_deadline` | `agogo_host::bridge` | An accepted start command reaches `Playhead` by deadline and emits the expected transport state/byte. |
| `accepted_stop_applies_by_deadline` | `agogo_host::bridge` | An accepted stop command reaches `Playhead` by deadline and suppresses future clock output. |
| `late_ordered_command_reports_fault` | `agogo_host::bridge` | A drained command past its deadline is not applied silently. |
| `unsupported_ordered_command_rejected_or_faulted` | `agogo_host::driver` | Locate/channel-configure cannot be accepted into a silent no-op. |
| `control_application_independent_of_observation` | `agogo_host` | Commands apply with no snapshot reader, observation sink, or stdio-core subscriber. |
| `rt_command_application_no_realloc` | `agogo_host` | The per-buffer apply path does not grow preallocated storage after construction. |

### Spot checks

| Check | Expectation |
| --- | --- |
| `agogo.tempo.set` defaults | Accepted for next RT buffer and changes the next buffer's tempo. |
| `agogo.start` then one buffer | Emits/arms running transport state by the declared deadline. |
| `agogo.stop` then one buffer | Emits stop once and leaves clock output silent after the stop buffer. |
| stale `deadline_buffer` | Returns `late` or missed-deadline fault; no silent state mutation. |
| no snapshot reader | Command application still works. |

## Review

- Branch naming used the flat fallback `plan-2026-05-03-01` after the
  slash branch failed under local Git metadata permissions. The plan
  filename remains canonical.
- `agogo.locate` and `agogo.channel.configure` are now rejected with
  `UnsupportedCommandClass` before queue admission. Accepting them into
  the RT queue would be a silent no-op because this sprint implements
  only tempo and start/stop application.
- Host bridge tests initially constructed `AudioIo` and introduced a
  naked `f32` in `crates/host/src/bridge.rs`, outside the PCM allowlist.
  `scripts/check-floats.sh` caught it; the tests now assert bridge and
  `Playhead` state without PCM buffers, leaving PCM callback behavior
  covered in the allowlisted core transport tests.
- During verification, `cargo test --workspace --quiet` and
  `cargo test -p agogo-cli --no-default-features --no-run` were started
  concurrently in one worktree, causing a Cargo build-directory lock
  wait. Both commands completed successfully, but future verification
  should run Cargo gates serially in a single worktree.
- `scripts/review_path.sh` could not infer the next PR number because
  `gh` could not determine the repo in this environment. A later PR
  number check put this branch at `doc/reviews/review-00065.md`.
- Local review found that command-driven start cleared the same
  `PlayheadStopHandle` flag used for teardown, allowing a queued
  `Start` to cancel a pending final Stop. Fixed by separating
  command-staged transport bytes from the teardown latch and adding
  `command_start_does_not_cancel_teardown_stop`.
- A second local review found that draining multiple ordered
  transport commands before one render buffer overwrote the single
  staged byte while reporting both as applied. Fixed by replacing the
  staged byte with a fixed-capacity FIFO and adding
  `ordered_transport_commands_emit_fifo_in_one_buffer`.
- A third local review found that command-driven transport could
  desynchronize `LinkDriven` playheads by bypassing the Link policy
  state. Fixed by rejecting command start/stop outside
  `TransportPolicy::Internal` and adding
  `command_transport_rejects_link_driven_policy`.
- A fourth local review found that the required
  `rt_command_application_no_realloc` verification row did not have a
  matching host test. Fixed by adding the missing test against the
  per-buffer command application path.
- GitHub review found that the boolean transport-apply result
  collapsed unsupported policy, fixed FIFO overflow, and teardown
  rejection into one `unsupported_commands` counter. Fixed by adding
  `TransportCommandApply` and separate host counters for queue-full
  and teardown-rejected commands.
- GitHub review found that command staging after
  `PlayheadStopHandle::request_stop` could be reported as applied even
  though teardown would drop the staged command. Fixed by rejecting
  command staging once the teardown stop flag is set.
- GitHub review found that `TransportState::running` still described
  a teardown-only latch even though command-driven Start/Stop now
  mutates it. Fixed the docs to describe the local clock gate and the
  stronger teardown-stop behavior.
- A later GitHub review found that `apply_transport_start` and
  `apply_transport_stop` docs implied unconditional next-buffer
  effects. Fixed by qualifying the contract to
  `TransportCommandApply::Applied` and documenting that teardown can
  still clear staged commands before rendering.
- Codex review found that ordered commands with future deadlines were
  drained and applied before their declared RT buffer. Fixed by
  retaining a future-deadline FIFO head in `ControlConsumer` until it
  is due or missed, and added
  `future_deadline_waits_until_declared_buffer`.
- During the second GitHub-review round, `cargo clippy --all-targets`
  and `cargo test -p agogo-cli --no-default-features --no-run` were
  accidentally started concurrently, causing the CLI no-run check to
  wait on the Cargo build-directory lock. Both commands completed
  successfully; this repeats the earlier verification note that Cargo
  gates should run serially in one worktree.
