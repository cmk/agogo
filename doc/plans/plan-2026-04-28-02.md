# Plan 2026-04-28-02 — Subcommand `bpm: f64 → Tempo` sweep (audit L-tail)

## Goal

Drop the last public-surface `bpm: f64` (and one paired `quantum: f64`)
storage positions across every CLI subcommand: `RunArgs` was migrated
in PR #32 (Plan 27 / Q3); this sweep finishes the L-tail across
`SyncSub::Trace`, `ChannelSub::Trace`, `MidiSub::Trace`,
`DemoSub::Run`, and the four `LinkSub::*` variants. The transitional
`parse_cli_bpm` helper is deleted; `parse_bpm_to_tempo` and
`parse_quantum_from_beats` move from `run.rs` (private,
`cfg(feature="run")`) to `main.rs` at module level (`pub(crate) fn`)
so every subcommand bpaf attribute can reference them.

**Scope expansion (post-sprint-review):** Closing every subcommand
`f64` argv field also pulled in `SyncSub::Trace.jitter_us: f64` →
`Pico` and `ChannelSub::Trace.delay: f64` → `Micro`, plus the
`channel_trace::TraceArgs.delay: f64` → `Micro` field that backs
the latter. New parsers `parse_jitter_us_to_pico` and
`parse_ms_to_micro` join the parser cohort in main.rs;
`parse_non_negative_f64` is deleted (no remaining users).

After this sweep, every `bpm` / `quantum` / `jitter_us` / `delay`
argv field on every subcommand is typed end-to-end; the f64 lives
only inside the named bpaf parser bodies.

## Dependency Graph

```
T1 (relocate parsers, delete parse_cli_bpm)
  └─→ T2 (enum variants: 8 bpm + 1 quantum)
        └─→ T3 (*Args structs + handler signatures)
              └─→ T4 (constructions + obsolete test deletion)
                    └─→ T5 (verification + check-floats allowlist trim)
```

T1 lands the new parser path; T2-T4 land the type cascade; T5 is the
gate sweep. The whole sweep ships in one feat: commit because the
sites break each other if split (`*Args.bpm: Tempo` requires the enum
variant to supply Tempo, which requires the bpaf parser).

## Tasks

### T1 — Relocate parsers; delete `parse_cli_bpm`

Move from `crates/cli/src/run.rs:51-78`:
- `fn parse_bpm_to_tempo(s: String) -> Result<Tempo, String>` (lines 51-62)
- `fn parse_quantum_from_beats(s: String) -> Result<Quantum, String>` (lines 68-78)

To `crates/cli/src/main.rs` at module level, **`pub(crate) fn`**, where
`parse_cli_bpm` (main.rs:327-340) is being deleted. The bpaf
attribute on `RunArgs.bpm` updates from `parse(parse_bpm_to_tempo)` to
`parse(crate::parse_bpm_to_tempo)`; same for `link_quantum`.
The proptest module in run.rs (lines 456-477) updates its calls to
`crate::parse_bpm_to_tempo` / `crate::parse_quantum_from_beats`.

Why module-level (not a new `argv.rs` module): three parsers (`positive_u32`,
`positive_f64`, `non_negative_f64`) already live there; adding two
more keeps the locality. Revisit if a `jitter_us` / `delay` follow-up
pushes the count higher.

The dead_code concern that drove Plan 27 to put these in `run.rs`
no longer applies: `midi_trace::TraceArgs` and `SyncSub::Trace` are
always compiled (no feature gate), so the parsers are always
referenced.

## Review

### Implementation deviations

- **`parse_quantum_from_beats` needs `#[allow(dead_code)]`.** Only
  consumed under `link` / `run` features; default-feature builds
  warn without the allow. Cleanest fix without a `#[cfg(any(...))]`
  ceremony.

- **`parse_positive_f64` and `parse_non_negative_f64` deleted.** Plan
  listed only `parse_cli_bpm` for removal, but the `jitter_us` /
  `delay` follow-up sweep took every former caller of both helpers,
  leaving zero remaining users. Both removed per CLAUDE.md "if you
  are certain that something is unused, you can delete it
  completely."

- **Typed fallbacks compile as const.** `Tempo::from_bpm_integer(120)`,
  `Quantum::from_bars(4)`, `Pico::ZERO`, `Micro::ZERO` are all `const`,
  so bpaf's `fallback(...)` accepts them directly. The plan's
  `fallback_with(|| ...)` workaround is unnecessary.

- **`probe_emits_rows_and_keeps_initial_tempo` test fixture updated.**
  This `#[cfg(test)]` test inside the `link` feature module passed
  `125.0: f64` to `probe`. The plan didn't enumerate it; it surfaced
  on the cargo-check pass. Updated to `Tempo::from_bpm_integer(125)`.

- **Sprint-review feedback applied.** Tier-1 review raised four
  items, all addressed in the same commit:
  - **`pushed_bpm` format** changed from `{:.4}` (`pushed_bpm=120.0000`)
    to `{:.2}` (`pushed_bpm=120.00`). Two decimals match `Tempo`'s
    µBPM storage precision (rounds-to-nearest at 6 decimal positions
    of f64-BPM, but printing more than 2 was already lying about the
    user's effective precision after `f64_bpm_to_tempo`'s
    integer round). The `demo` startup eprintln aligns to `{:.2}`.
  - **Parser visibility** changed from `fn` to `pub(crate) fn`, matching
    plan T1's spec.
  - **`SyncSub::Trace.jitter_us: f64` → `Pico`** with new parser
    `parse_jitter_us_to_pico`. Drops the open-coded `* 1.0e-6` shift
    from `sync_trace::trace` body.
  - **`ChannelSub::Trace.delay: f64` → `Micro`** with new parser
    `parse_ms_to_micro`. Drops the `ms_to_micro` closure from
    `channel_trace::trace` body. `channel_trace::TraceArgs.delay`
    field follows.

- **`refactor:` → `feat:`.** Per the local-review item-2 flag, the
  implementation commit's prefix was amended to `feat:` to align
  with CLAUDE.md's enumerated list (`plan / feat / fix / fmt / doc
  / test / task / debt`). Recent repo precedent (PRs #30/#31/#32) used
  `refactor:` for analogous audit sweeps; the strict reading of
  CLAUDE.md wins.

### Final state

After this PR, every argv field across every CLI subcommand that was
previously `f64` (bpm, quantum, jitter_us, delay) is typed end-to-end
— `Tempo`, `Quantum`, `Pico`, `Micro`. The f64 surface collapses to
the bodies of four named bpaf parsers in main.rs:
`parse_bpm_to_tempo`, `parse_quantum_from_beats`,
`parse_jitter_us_to_pico`, `parse_ms_to_micro`. The deleted helpers
(`parse_cli_bpm`, `parse_positive_f64`, `parse_non_negative_f64`)
and the dropped open-coded `* 1.0e±N` shifts (`ms_to_micro` closure
in `channel_trace::trace`, `* 1.0e-6` in `sync_trace::trace`) close
the L-tail and the M-family follow-ups in one swing.

Only the `check-conns.sh` enforcement script remains on the deferred
list from the meta-plan.
