# Plan 02 — `sync/`: peak detector + Type-II PLL

## Goal

Deliver `agogo-core::sync` as a pure-DSP module that consumes an
`&[f32]` sample stream and emits (a) detected pulse positions with
sub-sample precision and (b) a smoothed BPM + phase estimate from a
Type-II PLL. Verified against synthetic pulse trains with injected
Gaussian timing noise. No audio I/O — the caller provides samples; the
CLI smoke harness generates its own pulse train in-memory.

## Context

`doc/agogo.md` §4 targets the audio-sync path as the precision
crown-jewel (±20 µs matching the original E-RM Multiclock). §9
specifies the sprint shape: "sync/pll.rs + sync/detect.rs tested
against synthetic pulse trains with injected Gaussian timing noise.
Proptest: PLL BPM estimate converges within a known error bound."
This plan implements that, minus any WAV-file path — the CLI harness
is fully synthetic so it runs in CI with no binary fixtures.

Parallel-independent of `plan-2026-04-22-01` (time/ — Cirklon grid
algebra). This plan emits sample-indexed phase and BPM; it does **not**
convert to `Tick`. Tick conversion is Sprint 3 integration work.

Reference material in `ext/`:
- `ext/clocked/src/lib.rs` — `PidSettings` struct shape (prop/integ/
  deriv factors, clamp, interp) at lines 28–42. Borrow the tuning-
  field shape; implement the PLL control law from control-theory
  first principles. `clocked` is buffer-occupancy PID, not a PLL.
- `ext/hertz` — trivial rate helpers. Not worth depending on; inline
  any conversion math in `sync/pll.rs`.

### T1 — Peak detector with sub-sample interpolation

`crates/core/src/sync/detect.rs`.

- `pub struct Peak { pub sample_index: f64, pub amplitude: f32 }`
  — `f64` to carry sub-sample fractional offsets.
- `pub struct DetectorConfig { pub threshold: f32, pub hold_samples:
  u32 }` — threshold is amplitude floor; hold is the minimum
  inter-pulse gap (prevents double-triggering on a decaying peak).
- `pub struct PeakDetector { cfg: DetectorConfig, state: DetectorState
  }` where `DetectorState` owns the ring-of-three last samples for
  parabolic interpolation and the hold countdown.
- `fn process(&mut self, samples: &[f32], start_index: u64) ->
  Vec<Peak>` — drains a block; `start_index` is the sample offset of
  `samples[0]` in the overall stream so returned `sample_index` values
  are stream-global.
- Sub-sample interpolation: parabolic fit over `(i-1, i, i+1)` around a
  local maximum; fractional offset is `0.5 * (y[-1] - y[+1]) / (y[-1]
  - 2*y[0] + y[+1])`, clamped to `[-0.5, 0.5]`.

### T2 — Type-II PLL

`crates/core/src/sync/pll.rs`.

- `pub struct PllSettings { pub kp: f64, pub ki: f64, pub clamp_hz:
  f64, pub interp: f64 }` — borrow `clocked::PidSettings` field names
  where they fit, but strip the derivative term (Type-II = PI, not
  PID) and rename `prop_factor → kp`, `integ_factor → ki`.
- `pub struct PllState { pub phase: f64, pub freq_hz: f64,
  pub integrator: f64 }` — frequency in Hz (later derivable to BPM
  via `bpm = freq_hz * 60 / ppq`).
- `pub struct Pll { cfg: PllSettings, state: PllState }`.
- `pub struct PllOutput { pub bpm: f32, pub phase: f32 }`.
- `fn step(&mut self, measured_pulse_sample: Option<f64>, sr: u32,
  ppq: u32) -> PllOutput` — if `Some(n)`, run one phase-detector
  update (phase error = observed arrival − expected arrival) and
  advance the loop filter; if `None`, advance the integrator at the
  current frequency only.
- Control law: classical Type-II second-order PLL, critically damped
  by default (`kp^2 = 4*ki`). Include a sane default `PllSettings`
  constant sized for a 24-PPQ audio-sync input at 48 kHz: bandwidth ~2
  Hz, damping 0.707.

### T3 — PhaseSource enum

`crates/core/src/sync/source.rs`.

- `pub enum PhaseSource { Internal { bpm: f32 }, External(Pll) }`.
- `fn phase_at_sample(&mut self, n: u64) -> f32` — unified API. For
  `Internal`, derive phase from `(n, bpm, sr)` deterministically. For
  `External`, caller feeds peaks through `Pll::step` and queries
  phase here.
- `fn feed_samples(&mut self, _samples: &[f32], _start: u64)` — a
  no-op for `Internal`, routes to `PeakDetector::process` →
  `Pll::step` for `External`.

### T4 — Proptest strategies

Extend `crates/core/src/arb.rs`:

- `fn arb_bpm() -> impl Strategy<Value = f32>` — biased toward musical
  ranges (60–200) with boundary variants.
- `fn arb_sample_rate() -> impl Strategy<Value = u32>` —
  `prop_oneof!` of {44100, 48000, 96000, 192000}.
- `fn arb_jitter_sigma_us() -> impl Strategy<Value = f32>` — range
  `[0.0, 500.0]` with weight toward small values.
- `fn pulse_train(bpm: f32, sr: u32, ppq: u32, jitter_sigma_us: f32,
  n_pulses: u32) -> (Vec<f32>, Vec<f64>)` — returns `(samples,
  ground_truth_peak_positions_f64)`. Pulses are triangular ~1.5 ms
  wide per the design brief; jitter is Gaussian on arrival time,
  seeded via proptest's RNG.

### T5 — CLI `sync trace` subcommand

Extend `crates/cli/src/main.rs` using `clap` (add as dep if not
present): subcommand `sync trace` with flags `--bpm <f32> --sr <u32>
--ppq <u32> --jitter-us <f32> --pulses <u32>`. Generates the pulse
train in-memory via the same helper used in proptests, runs detector
→ PLL, prints `sample_index, bpm_estimate, phase_estimate` one line
per PLL update. Pure CPU, repeatable in CI.

## Verification

### Properties (must pass)

| Property | Module | Invariant |
|----------|--------|-----------|
| `detector_recovers_all_peaks` | `sync::detect` | every synthetic peak is reported exactly once; no false positives outside hold window |
| `detector_subsample_precision` | `sync::detect` | `|reported - truth| ≤ 1.0` sample for SNR > 20 dB; `≤ 0.1` for clean input |
| `detector_hold_blocks_doubles` | `sync::detect` | two peaks within `hold_samples` report only the first |
| `pll_bpm_converges` | `sync::pll` | after ≥ 32 pulses, `|bpm - ground_truth| < 0.05` for jitter σ ≤ 200 µs |
| `pll_phase_converges` | `sync::pll` | after ≥ 32 pulses, phase RMS error < 50 µs for jitter σ ≤ 200 µs |
| `pll_rejects_outliers` | `sync::pll` | a single 10× jitter spike perturbs steady-state BPM by < 0.5 |
| `pll_no_panic_on_silence` | `sync::pll` | `step(None, ..)` for 1000 calls never panics; output stays finite |
| `pll_bandwidth_monotone` | `sync::pll` | increasing `kp` at fixed `ki` reduces convergence time (checked by regression, not a proptest) |
| `source_internal_is_linear` | `sync::source` | `Internal { bpm }` yields phase that grows linearly in `n` |

### Spot checks

- `DetectorConfig { threshold: 0.5, hold_samples: 1000 }` on a hand-
  crafted 5-peak stream at 48 kHz recovers all 5 peaks within ±0.1
  sample.
- Default `PllSettings` at 120 BPM / 48 kHz / 24 PPQ converges in
  under 1 second of audio (5760 PLL ticks).
- `PhaseSource::Internal { bpm: 120.0 }.phase_at_sample(24000) == 0.5`
  at 48 kHz (half a beat in, phase wraps at 1.0).
