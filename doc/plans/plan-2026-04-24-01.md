# Plan 12 — `out/midi`: MidiSink trait + MIDI clock byte emission

## Goal

First of the three remaining v0.1 output-chain sprints. Define the
`MidiSink` trait and render `ChannelMode::MidiClock` channels to byte
streams (`0xF8` clock ticks; `0xFA` / `0xFB` / `0xFC` transport
bytes). Pure-logic + a synthetic `TestSink`; no real backend (midir
is Plan 13's job).

## Context

`doc/versions/version-0.1.md` lists `out/midi` as the next
output-chain slot with unchanged scope:

> `out/midi` — MIDI clock byte emission (0xF8 ticks at PPQN/24,
> 0xFA/0xFC start/stop), `MidiSink` trait, sample-indexed
> timestamping. Pure trait + a synthetic test sink; no real backend
> yet.

`doc/agogo.md` §3 names the module (`src/out/midi.rs`) and §5 pins
the trait shape verbatim:

```rust
trait MidiSink: Send {
    fn send_at(&self, msg: &[u8], at_sample: u64);
}
```

`crates/core/src/channel/transform.rs` already emits
`ScheduledEvent { sample_index: u64, tick: Tick }` — the input to
this plan's rendering. `ChannelMode::MidiClock` exists as a stub
today (`crates/core/src/channel/mode.rs:14`) and this plan is the
first to produce bytes for it.

Neither in-flight branch is a prerequisite: `out/midi` reads
`ScheduledEvent` + `Channel::mode`, not channel state (`shift` /
`offset`), so Plan 11 MR #2's `f32` → `Micro` field flip is invisible
here. Plan 09's transport FSM is *consumed* (Plan 14 translates FSM
transitions into `MidiRtByte` values per buffer) but Plan 12
exposes the `MidiRtByte` type rather than depending on the FSM.

## Tasks

### T1 — `MidiSink` trait + byte constants + `TestSink`

Files:
- `crates/core/src/out.rs` — new module root.
- `crates/core/src/out/midi.rs` — new file, owns the trait and sink
  impls.

Trait (verbatim from `doc/agogo.md` §5, plus RT-safety docstring):

```rust
/// Back-end-agnostic MIDI output sink.
///
/// Each back-end converts `at_sample` to its native timebase inside
/// `send_at` — mach time for CoreMIDI, frame index for JACK,
/// `QueryPerformanceCounter` for WinMM (agogo.md §5). The core only
/// ever sees monotonic sample counts.
///
/// **RT safety.** Implementations may allocate or take locks
/// (`midir` does both). Plan 13's `rt/control.rs` wires an `rtrb`
/// drain thread so the audio callback enqueues `(bytes, at_sample)`
/// pairs without calling `send_at` directly.
pub trait MidiSink: Send {
    fn send_at(&self, msg: &[u8], at_sample: u64);
}
```

Status byte constants — module-public `const`, one per MIDI-1.0
Real-Time status byte Plan 12 emits:

```rust
pub const MIDI_CLOCK:    u8 = 0xF8;
pub const MIDI_START:    u8 = 0xFA;
pub const MIDI_CONTINUE: u8 = 0xFB;
pub const MIDI_STOP:     u8 = 0xFC;
```

`TestSink` — in-memory synthetic sink. The `Mutex` makes it non-RT;
it exists for proptests and the CLI tracer, not production:

```rust
#[derive(Clone, Debug, Eq, PartialEq)]
pub struct TestRecord {
    pub at_sample: u64,
    pub bytes: Vec<u8>,
}

#[derive(Default)]
pub struct TestSink {
    inner: std::sync::Mutex<Vec<TestRecord>>,
}

impl TestSink {
    pub fn new() -> Self;
    /// Cloned snapshot of all records to date, in FIFO order.
    pub fn records(&self) -> Vec<TestRecord>;
    pub fn clear(&self);
    pub fn len(&self) -> usize;
    pub fn is_empty(&self) -> bool;
}

impl MidiSink for TestSink { /* push onto inner */ }
```

### T2 — Clock renderer

Same file. Zero-alloc pure function that maps a `ScheduledEvent`
slice to `send_at` calls.

```rust
/// Render a block of MidiClock `ScheduledEvent`s. Emits one `0xF8`
/// byte per event at its `sample_index`. No allocation — the
/// one-byte slice is stack-local per iteration.
pub fn render_clock_block(events: &[ScheduledEvent], sink: &dyn MidiSink) {
    for ev in events {
        sink.send_at(&[MIDI_CLOCK], ev.sample_index);
    }
}
```

`&dyn MidiSink` (not `&impl MidiSink`) so Plan 13's dispatcher can
hold a boxed sink without monomorphising the whole render path per
backend.

### T3 — Transport bytes + per-buffer render frontend

```rust
/// Per-buffer transport command. Caller decides when to inject one
/// based on its transport FSM state (Plan 09's `LinkSession`,
/// Plan 14's Machine). Plan 12 does not own transport logic.
#[derive(Copy, Clone, Debug, Eq, PartialEq)]
pub enum MidiRtByte {
    Start,
    Continue,
    Stop,
}

impl MidiRtByte {
    pub fn status_byte(self) -> u8 {
        match self {
            Self::Start    => MIDI_START,
            Self::Continue => MIDI_CONTINUE,
            Self::Stop     => MIDI_STOP,
        }
    }
}

/// Per-buffer render: emits the optional transport byte at
/// `buffer_start_sample` ahead of the clock stream, then the clock
/// events. Callers that want to place the transport byte mid-buffer
/// can call `send_at` directly with a custom sample index.
pub fn render_buffer(
    events: &[ScheduledEvent],
    transport: Option<MidiRtByte>,
    buffer_start_sample: u64,
    sink: &dyn MidiSink,
) {
    if let Some(t) = transport {
        sink.send_at(&[t.status_byte()], buffer_start_sample);
    }
    render_clock_block(events, sink);
}
```

### T4 — Per-channel dispatch

Public entry point Plan 14's Machine calls once per channel per
buffer. Exhaustive match on `ChannelMode`: non-`MidiClock` variants
are intentional no-ops, their rendering paths land in later versions
per the existing doc comments on `ChannelMode`.

```rust
pub fn render_channel_block(
    ch: &Channel,
    events: &[ScheduledEvent],
    transport: Option<MidiRtByte>,
    buffer_start_sample: u64,
    sink: &dyn MidiSink,
) {
    match ch.mode {
        ChannelMode::MidiClock => {
            render_buffer(events, transport, buffer_start_sample, sink);
        }
        // DIN bytes (v0.2), CV pulse + analog LFO (v0.4), MIDI CC
        // (post-v0.5 — needs a u7 newtype outside agogo-core).
        // Intentional no-op per the stub docs in `channel/mode.rs`.
        ChannelMode::Din
        | ChannelMode::AnalogPulse
        | ChannelMode::AnalogLfo
        | ChannelMode::MidiCc { .. } => {}
    }
}
```

### T5 — Wire-up + `agogo midi trace` CLI

`crates/core/src/lib.rs`:

```rust
pub mod out;
```

`crates/core/src/out.rs` (module root; `audio` submodule stays absent
until v0.4):

```rust
//! Output rendering. v0.1 ships only `midi`; `audio` (CV / LFO)
//! lands in v0.4 per `doc/versions/version-0.4.md`.
pub mod midi;
```

`crates/cli/src/main.rs`: add `agogo midi trace` subcommand,
stylistically matching the existing `sync trace` / `channel trace` /
`link probe` commands. Runs `tick_stream` + `render_channel_block`
against a `TestSink` for N buffers and dumps
`(at_sample,byte_hex)` CSV.

```
agogo midi trace
    --bpm <f64>             # argv boundary → Tempo (scaled µBPM)
    --sr <u32>              # one of 44_100 / 48_000 / 88_200 / 96_000 / 176_400 / 192_000
    --divider <tbase>       # t4/t8/t16/t32t/… (existing parser)
    --frames <usize>        # per-buffer frame count
    --buffers <u32>         # number of buffers to run
    [--start]               # inject MidiRtByte::Start on buffer 0
    [--stop-on-exit]        # inject MidiRtByte::Stop on last buffer
```

**MIDI-spec rate.** The MIDI 1.0 spec pins clock at 24 PPQN — one
`0xF8` every `PPQN/24` master ticks. At agogo's 192 PPQN master
that's every 8 master ticks, which is **`TBase::T32t`** (32nd-note
triplet = `192 / 24 = 8` ticks per step). The trace examples below
use `--divider t4` for human-readable output (one `0xF8` per beat);
pick `--divider t32t` when you want a true MIDI-spec 24 PPQN
stream. Plan 14's `agogo run` defaults to `t32t` for the same
reason. `doc/designs/output.md:37-41` is the design source.

Output format:

```
at_sample,byte
0,0xFA
0,0xF8
24000,0xF8
48000,0xF8
...
```

No new external crate deps for this task.

| Property | Module | Invariant |
|----------|--------|-----------|
| `clock_every_event_produces_one_record` | `core::out::midi::tests` | For any `ScheduledEvent` slice, `render_clock_block` produces exactly `events.len()` `TestSink` records, each with a single `0xF8` byte. |

| `non_clock_modes_are_noop` | `core::out::midi::tests` | `render_channel_block` on a channel with `mode ∈ {Din, AnalogPulse, AnalogLfo, MidiCc{..}}` produces zero sink records, even with non-empty `events`. |
| `block_render_matches_scheduler` | `core::out::midi::tests` | End-to-end composition: for an arbitrary MidiClock `(Channel, buffer_start, frames)`, the `TestRecord.at_sample` list emitted by `render_channel_block(..., transport: None, ...)` equals `tick_stream(...)`'s `ScheduledEvent.sample_index` list bit-for-bit. |

### Spot checks

- `render_clock_block` over four events at `[0, 24_000, 48_000, 72_000]` against a fresh `TestSink` → four records in that order, each `{at_sample: s, bytes: vec![0xF8]}`.
- `MidiRtByte::Start.status_byte() == 0xFA`; `Continue == 0xFB`; `Stop == 0xFC`.
- `render_buffer(&[], Some(Start), 1024, &sink)` produces exactly one record `{at_sample: 1024, bytes: vec![0xFA]}`.
- `TestSink` shared across two `std::thread::scope` threads, each sending 1 000 records → `len() == 2000` (confirms the `Send + Mutex` design and flushes out any `Sync` requirement mismatch early).
- `agogo midi trace --bpm 120 --sr 48000 --divider t4 --frames 4096 --buffers 16 --start` prints 16 clock rows at `(0, 24_000, 48_000, …, 360_000)` preceded by one `0xFA` row at sample `0`.

## Deferred

- **Real backends** (`midir`, `coremidi`, `alsa_midi`, `jack`,
  `winmm`) — Plan 13 (`host/midir` + `host/cpal` + `rt/` +
  audio callback). midir is the cross-platform v0.1 default;
  platform-native sinks are post-v0.5 per `version-0.1.md`.
- **Non-clock `ChannelMode` rendering** — DIN sync24 (v0.2), CV
  pulse + analog LFO (v0.4 via `out/audio.rs`), MIDI CC (post-v0.5 —
  wants a real `u7` newtype which agogo-core deliberately does not
  carry).
- **Song Position Pointer** (`0xF2`) — transport navigation
  mid-song. Revisit with the Plan 09 forerun FSM in v0.5.
- **SysEx** — out of scope per `doc/agogo.md` §11.
- **Per-format latency compensation** — v0.5 Sprint 03. Plan 12's
  `at_sample` is the master timebase; backend-specific compensation
  is Plan 13's job.
- **RT-safe enqueue path** — `MidiSink::send_at` may block.
  Plan 13's `rt/control.rs` drains an `rtrb` SPSC on a dedicated
  thread so the audio callback stays allocation-free.
- **Transport FSM integration** — Plan 12 exposes `MidiRtByte`;
  Plan 14's Machine maps Plan 09 FSM state transitions to
  `MidiRtByte` per buffer.
