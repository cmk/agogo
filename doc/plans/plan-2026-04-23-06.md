# Plan 09 — Link bidirectional (tempo push + transport + quantum)

## Goal

Extend the read-only Link integration (PRs #6 and #8) to full
bidirectional: agogo pushes tempo changes back to the Link session,
subscribes to network-shared start/stop transport (with one-shot
user-initiated publish via CLI), snaps per-channel starts to Link's
quantum grid, and re-anchors host-time per audio buffer so the phase
bridge stays tight once the audio callback lands.

## Context

Plan 07 (PR #6) shipped the `agogo-host-link` crate scaffold with
lifecycle-only `LinkClock` (enable / tempo / num_peers) plus the
`PhaseSourceImpl` trait and `PhaseSource::Custom(...)` variant in
`agogo-core::sync`. Plan 08 (PR #8) landed the
`LinkClock::phase_at_sample` host-time bridge using a static
`HostTimeAnchor { host_origin_micros: i64, sample_rate: NonZeroU32 }`,
the bridge math `host_micros = anchor.origin + n × 10⁶ / sr.get()`
in `i128`, and the CLI probe `agogo link probe` with
`t_ms,peers,tempo_bpm,phase` CSV output. This sprint wires up the
write-side surface that Plan 07 §Deferred + Plan 08 §Deferred both
enumerate.

Plan 09 is the final Link sprint for the v0.2 track. Plan 10+ will
address the one-bar NEG/POS forerun FSM (`doc/agogo.md §10` open
question) that this plan deliberately ships without.

## Prerequisites

**Plan 09 depends on the post-fxp enforcement sprint landing first**
(branch TBD — see `~/.claude/plans/please-plan-and-then-cozy-wadler.md`
for that sprint's design). The enforcement sprint retires the
bespoke `f32_*_to_*` / `f64_*_to_*` helpers in favour of named
`Conn` constants, flips `Channel::{shift_ms, offset_ms}: f32` to
`Micro`, and ports `f32fix` / `f64fix` / `ratfix` upstream. Plan 09
is written against that post-landing state.

Specifically, Plan 09 is load-bearing on:

- `connections::fixed::F12F06` — `Conn<Pico, Micro>` (decimal ladder,
  exact embed at the 10⁻⁶ rung). Used to cross Micro ↔ Pico inside
  the snap-offset math.
- `PicoSampleConn` (`agogo-core::time::conn`, new in enforcement's
  T0) — runtime-parameterised `Conn<Pico, i64 samples>` sibling to
  the existing `SampleTickConn`. Used to cross Pico ↔ Sample at
  runtime-chosen rates.
- `F64TMP: Conn<f64, Tempo>` (new in enforcement's T1) — f64 BPM →
  `Tempo`. Used at the Link-FFI boundary inside `LinkClock::tempo`
  / `push_tempo`.
- `F64QNT: Conn<f64, Quantum>` (new in Plan 09's T0, justified
  below) — f64 beats → `Quantum`. The ABI cast from Link's
  `double quantum` into agogo's `Quantum` newtype.
- `Channel::{shift, offset}: Micro` (post-enforcement) —
  Plan 09 bakes snap offsets into `offset: Micro`, not
  `offset_ms: f32`.

**`Quantum` type decision (settled here).** Link internally
represents quantum as `int64` microbeats (`link::Beats`, see
`ext/rusty_link/link/include/ableton/link/Beats.hpp:31-47`); its
`double quantum` public ABI is converted via
`std::llround(q * 1e6)` into microbeats on line 1 of every API
body. So agogo's `Quantum` maps bit-exactly to Link's internal
representation if we wrap a `Micro` (10⁻⁶ rung of the decimal
ladder, `i64` backing):

```rust
// crates/core/src/fxp.rs
use connections::fixed::Micro;

#[repr(transparent)]
#[derive(Copy, Clone, Debug, Eq, PartialEq, PartialOrd, Ord, Default)]
pub struct Quantum(pub Micro);   // microbeats

impl Quantum {
    pub const fn from_bars(n: u32) -> Self {
        Self(Micro((n as i64) * 1_000_000))
    }
}

// F64QNT: f64 beats → Quantum. Rounds identically to Link's own
// Beats(double) constructor — zero disagreement at the FFI
// boundary. Proptest: adjoint laws + round-trip match with a
// `std::llround(q * 1e6)` reference on a wide sweep of f64 inputs.
pub const F64QNT: Conn<f64, Quantum>;
```

Integer-bar users write `Quantum::from_bars(4)`; fractional users
write `Quantum(Micro(4_500_000))`; the Link FFI cast uses `F64QNT`.
No information is lost at the boundary.

**Decisions locked in by the v0.2 design doc** (see commit history
on PRs #6 / #8's plan docs for the full reasoning):

- Link and the audio-PLL stay **mutually exclusive** `PhaseSource`
  variants — user picks one at session start, no hybrid / voting.
- **Link-master transport.** agogo mirrors Link's `is_playing` flag
  into its transport state. The symmetric continuous-publish
  direction (Machine-master → Link) is blocked on the forerun FSM
  that has no spec yet; Plan 09 ships only a one-shot publish on
  `--start` / `--stop-on-exit` CLI flags so the user can initiate
  transport once per session.
- **`rust-fsm 0.7`** for the transport FSM. The minimal `{Stopped,
  Playing}` FSM Plan 09 ships is structured so the forerun sprint
  can extend it (adding `PreRoll` and a forerun-aware stop state)
  rather than rewriting a hand-rolled `match`.
- **Tempo push = always active on Link source.** When the user
  mutates BPM through agogo's control plane and the active
  `PhaseSource` is Link, emit `push_tempo(bpm: Tempo)` on the
  `LinkSession`, which internally captures session state, calls
  `set_tempo(tempo_to_f64(bpm), clock_micros())`, and commits. Link
  smooths peer-side; no agogo-side ramp. The `Tempo → f64` cast is
  the only `// Link FFI` site for tempo push.
- **Quantum snap at the Channel layer.** `Channel::snap_to_quantum:
  Option<Quantum>` on the existing struct in `agogo-core`
  (`Quantum` = `Micro`-backed newtype pinned above). When the
  orchestrating layer arms a channel and Link is active, it calls
  `session_state.request_beat_at_time(next_beat,
  clock_micros() + small_future_budget, quantum.to_f64())`, then
  derives a `Micro` delta via
  `F12F06.ceil(psc.inner(delta_samples))` (where `psc =
  PicoSampleConn::new(sr)`), and adds it to `channel.offset:
  Micro` (post-enforcement field type). **The `tick_stream`
  scheduler stays Link-unaware**; Plan 03's
  `scheduler_block_equivalence` property must remain bit-for-bit
  unchanged when `snap_to_quantum = None`.
- **Per-buffer host-time re-anchoring = atomic-packed.** Plan 08's
  `HostTimeAnchor` is promoted to a torn-read-safe variant backed by
  two `AtomicU64` fields plus a generation counter (seqlock pattern).
  The audio callback calls a new `set_host_time_anchor(host_micros,
  sample_index)` setter at each buffer's top. The static anchor
  stays available for test + CLI-probe paths where no audio callback
  is running.
- **Scheduler signature stays.** `tick_stream(channel, stc,
  buffer_start, frames)` unchanged. The Link-aware snap offset is
  computed at arm time by the orchestrating layer and baked into the
  channel's offset; the scheduler sees a plain `Channel`.
- **Quantum = per-session CLI flag, default 4** (one bar in 4/4).
  The `--quantum <f64>` argv dies on handler entry via
  `F64QNT.ceil(q_f64)`, stored as `Quantum` in the run-session
  struct. Per-channel override via `snap_to_quantum:
  Option<Quantum>`; CLI exposure of the per-channel override is
  deferred to the preset sprint.
- **Testing = two in-process `AblLink` instances** discovering each
  other on localhost multicast. Gated behind
  `fixture_or_skip!("link_multicast")` so CI environments without
  multicast loopback skip cleanly.

**Open design questions answered for Plan 06 (`machine.rs`)** when
it lands:
- Transport source of truth: Machine transport state **mirrors** Link
  when `PhaseSource` is Link; Machine is authoritative when the PLL
  is. Mirror is one-way (Link → Machine) in Plan 09.
- Channel arm-time hook: the orchestrator calls
  `compute_snap_offset(channel, link_session) -> Micro` and adds
  the result to `channel.offset: Micro`.
- Quantum storage: the orchestrator carries a `quantum: Quantum`
  field (`Micro`-backed newtype, default `Quantum::from_bars(4)`,
  preset-round-trippable via `serde` on the `Micro` payload).

**Still deferred to a later sprint**:
- One-bar NEG/POS forerun semantics (§10 open question).
- Machine-master transport publish — blocked on the forerun spec.
- Combined atomic `set_is_playing_and_request_beat_at_time` — the
  two-step (set → request) form ships here; switch to combined if
  races surface.
- Per-channel quantum-override CLI surface — with the preset
  format.

### T1 — Tempo push

Files:
- `crates/host-link/src/link.rs` (extend `LinkClock`).

Add a `push_tempo` method:

```rust
impl LinkClock {
    /// Push a new BPM to the Link session at the current host-time.
    /// Link smooths peer-side; no local ramp.
    ///
    /// # RT-safety
    ///
    /// Not RT-safe. `commit_audio_session_state` allocates internally
    /// in rusty_link. Run on the control thread, never the audio
    /// thread.
    pub fn push_tempo(&mut self, bpm: Tempo) {
        self.link.capture_audio_session_state(&mut self.session);
        // The Tempo → f64 cast is the only `// Link FFI` site for
        // tempo push. `tempo_to_f64` is the enforcement-sprint
        // helper (PI-exempt, single use-site).
        let bpm_f64 = tempo_to_f64(bpm); // Link FFI
        self.session.set_tempo(bpm_f64, self.link.clock_micros());
        self.link.commit_audio_session_state(&self.session);
    }
}
```

Tests: unit test that pushes `Tempo::from_bpm_integer(137)` on a
disabled LinkClock and reads it back via `tempo()` — the
`LinkClock::tempo` getter already returns `Tempo` after enforcement,
so the round-trip stays in-type.

### T2 — Transport FSM (minimal, `rust-fsm 0.7`)

Files:
- `crates/host-link/src/transport.rs`.

Declare the FSM with `rust_fsm::state_machine!`:

```rust
rust_fsm::state_machine! {
    #[derive(Debug)]
    transport_fsm(Stopped)

    Stopped => {
        LinkReportsPlaying => Playing,
        UserStart          => Playing [PublishPlaying],
    },
    Playing => {
        LinkReportsStopped => Stopped,
        UserStop           => Stopped [PublishStopped],
    },
}
```

(rust-fsm's macro DSL syntax; transitions can emit outputs
(`PublishPlaying`, `PublishStopped`) that the caller acts on.)

Wire-up:
- `LinkSession::on_user_start()` drives a `UserStart` event; if the
  FSM emits `PublishPlaying`, call
  `session.set_is_playing(true, clock_micros()) +
   commit_audio_session_state`.
- A periodic `poll_link_transport` (called from the CLI loop or the
  audio callback's control path) reads `session_state.is_playing()`
  and drives `LinkReportsPlaying` / `LinkReportsStopped` events to
  keep the local FSM in sync.

State exposed to the rest of agogo via `LinkSession::is_playing() ->
bool` (backed by the FSM's current state). When paused, the CLI run
loop discards scheduler output instead of stopping the scheduler —
keeps the scheduler's internal state consistent across start/stop.

**Forerun FSM explicitly deferred.** The hardware Multiclock's
one-bar NEG/POS forerun isn't implemented; Playing transitions take
effect immediately. Flagged in Deferred and cross-referenced with
`doc/agogo.md §10`.

### T3 — Atomic-packed per-buffer host-time anchor

Files:
- `crates/host-link/src/anchor.rs`.

Move the existing `HostTimeAnchor` here (from `link.rs`), then add:

```rust
/// Torn-read-safe anchor. Audio thread reads via `load()`; control
/// thread writes via `store()`. Uses a seqlock-style generation
/// counter to detect torn reads — reader retries if the counter
/// changed between start and end of the read.
pub struct AtomicHostTimeAnchor {
    host_origin_micros: AtomicI64,
    sample_rate: AtomicU32,       // stores NonZeroU32.get()
    generation:  AtomicU32,
}

impl AtomicHostTimeAnchor {
    pub fn new(initial: HostTimeAnchor) -> Self;
    pub fn store(&self, anchor: HostTimeAnchor);   // control-thread
    pub fn load(&self) -> HostTimeAnchor;          // audio-thread, RT-safe
}
```

`LinkClock` gains an `AtomicHostTimeAnchor` field alongside (or
replacing) the static `HostTimeAnchor`. `phase_at_sample` loads from
the atomic path. A new `set_host_time_anchor(host_micros,
sample_index)` setter converts the two integers to a
`HostTimeAnchor` and calls `store`.

The seqlock pattern — odd generation = write in progress, retry;
even generation = stable, use it. Acquire/Release ordering on the
generation writes; Relaxed on the payload stores (bracketed by the
generation). Standard pattern; no unsafe.

Properties:
- `host_time_anchor_torn_read_safe`: a proptest harness with a
  writer thread + reader thread racing for 1000 iterations never
  returns a torn `(host_origin_micros, sample_rate)` pair.

### T4 — `Channel::snap_to_quantum` + orchestrator hook

Files:
- `crates/core/src/fxp.rs` — add the `Quantum(Micro)` newtype +
  `F64QNT: Conn<f64, Quantum>` constant (declared in Prerequisites).
  Implementation mirrors Link's own `Beats(double)` conversion:
  `llround(q * 1e6)` → `Micro(_)` → `Quantum(_)`. Proptests: adjoint
  laws + bit-exact match against a reference `llround` sweep.
- `crates/core/src/channel/transform.rs` — add
  `pub snap_to_quantum: Option<Quantum>` field to `Channel`. Default
  is `None`. `Channel::default()` unchanged.
- `crates/host-link/src/session.rs` — `LinkSession::arm_channel(ch,
  stc)` computes the snap offset for channels with
  `snap_to_quantum = Some(q)` when Link is active:
  1. Read Link session state.
  2. Call `session_state.request_beat_at_time(next_beat,
     clock_micros() + small_future_budget, quantum_to_f64(q))`
     (request, not force — respects peer negotiation; the
     `Quantum → f64` cast is `// Link FFI`).
  3. `commit_audio_session_state`.
  4. Compute the sample delta between "Tick(0) at buffer_start"
     and "Tick(0) at the requested beat-time" via the current
     atomic anchor (T3) — result is an `i64` sample count.
  5. Convert the sample delta to `Micro` via
     `F12F06.ceil(psc.inner(delta_samples))` where `psc =
     PicoSampleConn::new(anchor.sample_rate)`, then add it to
     `ch.offset: Micro` (post-enforcement field type). No open-coded
     `samples * 1e6 / sr` — every conversion is a ladder Conn.

When the active `PhaseSource` is the PLL, `snap_to_quantum` is
silently ignored (quantum has no meaning outside Link). A CLI
warning if `snap_to_quantum = Some(_)` and `--source=pll` is
nice-to-have — deferred as T6 follow-up.

**The scheduler is unchanged.** Plan 03's `scheduler_block_equivalence`
property must pass bit-for-bit when `snap_to_quantum = None`.

### T5 — `LinkSession` orchestration

Files:
- `crates/host-link/src/session.rs`.

Glue type that brings T1 + T2 + T3 + T4 together:

```rust
pub struct LinkSession {
    clock: LinkClock,
    transport: TransportFsm,
    quantum: Quantum,                 // Micro-backed, not f64
    anchor: AtomicHostTimeAnchor,
    config: LinkWriteConfig,
}

pub struct LinkWriteConfig {
    pub enable_start_stop_sync: bool,
    pub enable_start_stop: bool,
    pub default_quantum: Quantum,     // was f64
    pub push_tempo_on_change: bool,
}

impl LinkSession {
    pub fn new(initial_bpm: Tempo, anchor: HostTimeAnchor,
               config: LinkWriteConfig) -> Self;

    /// Control-thread: push a new BPM to the Link network.
    pub fn set_tempo(&mut self, bpm: Tempo);
    /// Control-thread: drive `UserStart` through the FSM; may emit
    /// a `set_is_playing(true, now)` publish.
    pub fn user_start(&mut self);
    pub fn user_stop(&mut self);
    /// Control-thread: poll Link's `is_playing` flag and drive the
    /// FSM with `LinkReportsPlaying` / `LinkReportsStopped` events.
    pub fn poll_transport(&mut self);
    /// Audio-thread: update the anchor with the current buffer's
    /// host-time + stream-global sample index.
    pub fn set_host_time_anchor(&self, host_micros: i64, sample_index: u64);
    /// Any-thread: read the current transport state.
    pub fn is_playing(&self) -> bool;
    /// Control-thread: compute a snap offset for a channel and add
    /// it to `ch.offset: Micro`. No-op when `ch.snap_to_quantum`
    /// is `None` or the active `PhaseSource` is the PLL.
    pub fn arm_channel(&mut self, ch: &mut Channel, stc: &SampleTickConn);
}
```

`LinkSession` is the struct Plan 06's `Machine` absorbs. Kept
intentionally thin — no audio-callback integration, no preset I/O,
no multi-channel coordination. Those all land with Plan 06.

### T6 — CLI exposure

Extend `crates/cli/src/main.rs`.

New top-level `agogo run` subcommand that drives a `LinkSession` +
the scheduler over a fixed duration. Phase 1 has no audio callback
(Plan 05 lands that), so this is a synthetic CPU-bound run that
feeds synthetic buffers into the scheduler:

```
agogo run
    --link                    # use Link as the PhaseSource
    --bpm <f64>               # initial BPM (argv; dies via F64TMP on entry)
    --sr <u32>                # sample rate (NonZeroU32 after parse)
    --quantum <f64>           # default 4.0 (argv; dies via F64QNT on entry)
    [--start]                 # one-shot set_is_playing(true) at session start
    [--stop-on-exit]          # one-shot set_is_playing(false) before exit
    [--push-tempo | --no-push-tempo]   # default on
    --frames <usize>          # buffer length
    --buffers <u32>           # number of buffers to run
```

All three `f64`-typed argv fields (`--bpm`, `--quantum`, plus any
future additions) die on the first line of the handler via the
matching Conn: `F64TMP.ceil(bpm_f64)` → `Tempo`, `F64QNT.ceil(q_f64)`
→ `Quantum`. Nothing `f64` survives past the handler boundary.
Annotate each of those calls `// argv boundary` per the
post-enforcement CLAUDE.md rule.

Plus a diagnostic subcommand:

```
agogo link diag               # print current Link session state + peers
```

Feature-gated behind `--features link`. Synthetic mode — the run
loop advances `buffer_start_sample` by `frames` each iteration and
calls `tick_stream` per channel (initially one hard-coded channel;
multi-channel wiring is Plan 06).

Per-channel `snap_to_quantum` is not exposed via the CLI in Plan 09
— the `Channel` struct field exists, preset I/O + `--snap-channel`
style flags land with Plan 06 / the preset format sprint.
