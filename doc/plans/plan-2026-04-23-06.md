# Plan 09 — Link bidirectional foundation (tempo push + transport FSM seam + quantum snap)

## Goal

Land the Link **write-path foundation** that the rest of the v0.5 Link
work will build on: agogo pushes tempo changes back to the Link
session, a minimal `{Stopped, Playing}` transport FSM subscribes to
Link's `is_playing` flag (and optionally publishes via user-initiated
CLI events), and per-channel quantum snap bakes a `Micro` offset into
`channel.offset` at arm-time.

Plan 09 is deliberately scoped to what is closable *now*, without
depending on Plan 05 (audio callback) or a full transport FSM. The
per-buffer host-time re-anchoring, wrapped-error PID sync, and the
`cpal.playback` timestamp path move to **v0.5 Sprint 02**
(`PhaseSource::Link` PID sync); the full NEG/POS forerun FSM moves to
**v0.5 Sprint 01** (Transport FSM), which extends the `rust-fsm`
skeleton declared here rather than rewriting it.

## Context

Plan 07 (PR #6) shipped the `agogo-host-link` crate scaffold with
lifecycle-only `LinkClock` (enable / tempo / num_peers) plus the
`PhaseSourceImpl` trait and `PhaseSource::Custom(...)` variant in
`agogo-core::sync`. Plan 08 (PR #8) landed the
`LinkClock::phase_at_sample` host-time bridge using a static
`HostTimeAnchor { host_origin_micros: i64, sample_rate: NonZeroU32 }`,
bridge math `host_micros = anchor.origin + n × 10⁶ / sr.get()` in
`i128`, and the CLI probe `agogo link probe` with
`t_ms,peers,tempo_bpm,phase` CSV output.

Plan 09 is the **foundation sprint** for v0.5's Link work. It ships
the Link-side surface that doesn't need the audio callback (tempo
push, transport FSM seam, quantum snap) and leaves the
audio-callback-dependent pieces (per-buffer anchor, wrapped-error PID)
for v0.5 Sprint 02. Co-designing the transport FSM skeleton here with
Link subscription in view prevents the v0.5 Sprint 01 FSM from being
designed in isolation and then needing a bolt-on.

## Prerequisites

This plan was originally drafted against a separate post-fxp
enforcement sprint (branch TBD — see
`~/.claude/plans/please-plan-and-then-cozy-wadler.md` for that
sprint's design). In the current plan/PR, the key enforcement
changes it needed are pulled in here directly (see §Review item 1):
retiring the bespoke `f32_*_to_*` / `f64_*_to_*` helpers in favour
of named `Conn` constants, flipping `Channel::{shift_ms, offset_ms}:
f32` to `Micro`, and surfacing the `Tempo` conversion used at the
Link boundary. The list below therefore records the
post-enforcement state Plan 09 now includes, rather than an
external dependency that must land first.

- `connections::fixed::F12F06` — `Conn<Pico, Micro>` (decimal ladder,
  exact embed at the 10⁻⁶ rung). Used to cross Micro ↔ Pico inside
  the snap-offset math.
- `PicoSampleConn` (`agogo-core::time::conn`, new in enforcement's
  T0) — runtime-parameterised `Conn<Pico, i64 samples>` sibling to
  the existing `SampleTickConn`. Used to cross Pico ↔ Sample at
  runtime-chosen rates.
- `F64TMP: Conn<f64, Tempo>` (new in enforcement's T1) — f64 BPM →
  `Tempo`. Used at the Link-FFI boundary inside `LinkClock::tempo`
  / `push_tempo`.
- `F64QNT: Conn<f64, Quantum>` (new in Plan 09's T0, justified
  below) — f64 beats → `Quantum`. The ABI cast from Link's
  `double quantum` into agogo's `Quantum` newtype.
- `Channel::{shift, offset}: Micro` (post-enforcement) —
  Plan 09 bakes snap offsets into `offset: Micro`, not
  `offset_ms: f32`.

**`Quantum` type decision (settled here).** Link internally
represents quantum as `int64` microbeats (`link::Beats`, see
`ext/rusty_link/link/include/ableton/link/Beats.hpp:31-47`); its
`double quantum` public ABI is converted via
`std::llround(q * 1e6)` into microbeats on line 1 of every API
body. So agogo's `Quantum` maps bit-exactly to Link's internal
representation if we wrap a `Micro` (10⁻⁶ rung of the decimal
ladder, `i64` backing):

```rust
// crates/core/src/fxp.rs
use connections::fixed::Micro;

#[repr(transparent)]
#[derive(Copy, Clone, Debug, Eq, PartialEq, PartialOrd, Ord, Default)]
pub struct Quantum(pub Micro);   // microbeats

impl Quantum {
    pub const fn from_bars(n: u32) -> Self {
        Self(Micro((n as i64) * 1_000_000))
    }
}

// F64QNT: f64 beats → Quantum. Rounds identically to Link's own
// Beats(double) constructor — zero disagreement at the FFI
// boundary. Proptest: adjoint laws + round-trip match with a
// `std::llround(q * 1e6)` reference on a wide sweep of f64 inputs.
pub const F64QNT: Conn<f64, Quantum>;
```

Integer-bar users write `Quantum::from_bars(4)`; fractional users
write `Quantum(Micro(4_500_000))`; the Link FFI cast uses `F64QNT`.
No information is lost at the boundary.

## Design decisions

Locked in by the v0.2 design doc (PRs #6 / #8) and the Link triage at
`doc/designs/link.md`:

- **Link and the audio-PLL stay mutually exclusive `PhaseSource`
  variants** — user picks one at session start, no hybrid / voting.
- **`rust-fsm 0.7`** for the transport FSM. The minimal `{Stopped,
  Playing}` FSM Plan 09 ships is structured so v0.5 Sprint 01's
  forerun work can extend the declaration (adding `PreRoll` and a
  forerun-aware stop state) rather than rewriting a hand-rolled
  `match`. Declarative DSL + compiler-checked transition exhaustiveness.
- **FSM inputs co-designed with Link.** Events are `{LinkReportsPlaying,
  LinkReportsStopped, UserStart, UserStop}` from day one. `User*`
  events publish one-shot to Link; `LinkReports*` never publish. This
  decision lives here (not in v0.5 Sprint 01) so the FSM can't be
  designed without the Link subscription seam in view.
- **Tempo push = always active when Link source is selected.** When
  the user mutates BPM through agogo's control plane and the active
  `PhaseSource` is Link, emit `push_tempo(bpm: Tempo)` on the
  `LinkClock`, which internally captures session state, calls
  `set_tempo(tempo_to_f64(bpm), clock_micros())`, and commits. Link
  smooths peer-side; no agogo-side ramp. The `Tempo → f64` cast is
  the only `// Link FFI` site for tempo push.
- **Quantum snap at the Channel layer.** `Channel::snap_to_quantum:
  Option<Quantum>` on the existing struct in `agogo-core`
  (`Quantum` = `Micro`-backed newtype pinned above). When the
  orchestrating layer arms a channel and Link is active, it calls
  `session_state.request_beat_at_time(next_beat,
  clock_micros() + small_future_budget, quantum.to_f64())`, then
  derives a `Micro` delta via
  `F12F06.ceil(psc.inner(delta_samples))` (where `psc =
  PicoSampleConn::new(sr)`), and adds it to `channel.offset: Micro`
  (post-enforcement field type). **The `tick_stream` scheduler stays
  Link-unaware**; Plan 03's `scheduler_block_equivalence` property
  must remain bit-for-bit unchanged when `snap_to_quantum = None`.
- **Quantum = per-session CLI flag, default `Quantum::from_bars(4)`**
  (one bar in 4/4). The `--quantum <f64>` argv dies on handler entry
  via `F64QNT.ceil(q_f64)`, stored as `Quantum` in the run-session
  struct. Per-channel override via `snap_to_quantum:
  Option<Quantum>`; CLI exposure of the per-channel override is
  deferred to the preset sprint.
- **Testing = two in-process `AblLink` instances** discovering each
  other on localhost multicast. Gated behind
  `fixture_or_skip!("link_multicast")` so CI environments without
  multicast loopback skip cleanly.

**Explicitly deferred to v0.5 Sprint 01** (full transport FSM):

- NEG/POS one-bar forerun semantics (§10 open question).
- `Locate` command and bar-boundary alignment.
- `PreRoll` + forerun-aware stop states (extend this plan's FSM
  declaration).
- Continuous Playhead-master transport publish (blocked on forerun).

**Explicitly deferred to v0.5 Sprint 02** (`PhaseSource::Link` PID sync):

- Per-buffer host-time re-anchoring (atomic seqlock pattern).
- Wrapped-error PID over Link timeline, per `doc/designs/link.md`
  Adopt §§1 + 5 — demote `LinkClock` from direct `PhaseSourceImpl`
  to PID-smoothed reference.
- `cpal_info.timestamp().playback` as the Link query instant (Adopt
  §2).
- Per-buffer `capture_app_session_state()` (Adopt §3).
- `Stopped → Starting` reset-phase-and-zero-integrator (Adopt §6).

**Out of scope entirely (later sprints):**

- Combined atomic `set_is_playing_and_request_beat_at_time` — the
  two-step form ships here; switch if races surface.
- Per-channel quantum-override CLI surface — with the preset sprint.
- Preset round-trip of Link state — with the preset sprint.
- Live CLI control plane (BPM / transport pokes while running) —
  Plan 09 exposes one-shot subcommands only.
- Tempo glide on the originating side — Link smooths peer-side.

### T1 — Tempo push

Files:
- `crates/host-link/src/link.rs` (extend `LinkClock`).

Add a `push_tempo` method:

```rust
impl LinkClock {
    /// Push a new BPM to the Link session at the current host-time.
    /// Link smooths peer-side; no local ramp.
    ///
    /// # RT-safety
    ///
    /// Not RT-safe. `commit_audio_session_state` allocates internally
    /// in rusty_link. Run on the control thread, never the audio
    /// thread.
    pub fn push_tempo(&mut self, bpm: Tempo) {
        self.link.capture_audio_session_state(&mut self.session);
        // Link FFI — Tempo → f64 is the only site for tempo push.
        // `tempo_to_f64` is the enforcement-sprint helper (PI-exempt,
        // single use-site).
        let bpm_f64 = tempo_to_f64(bpm);
        self.session.set_tempo(bpm_f64, self.link.clock_micros());
        self.link.commit_audio_session_state(&self.session);
    }
}
```

Tests: unit test that pushes `Tempo::from_bpm_integer(137)` on a
disabled LinkClock and reads it back via `tempo()` — the
`LinkClock::tempo` getter returns `Tempo` after enforcement, so the
round-trip stays in-type.

### T2 — Transport FSM (minimal, `rust-fsm 0.7`, Link-seam-ready)

Files:
- `crates/host-link/src/transport.rs`.

Declare the FSM with `rust_fsm::state_machine!`:

```rust
rust_fsm::state_machine! {
    #[derive(Debug)]
    transport_fsm(Stopped)

    Stopped => {
        LinkReportsPlaying => Playing,
        UserStart          => Playing [PublishPlaying],
    },
    Playing => {
        LinkReportsStopped => Stopped,
        UserStop           => Stopped [PublishStopped],
    },
}
```

(rust-fsm's macro DSL syntax; transitions can emit outputs
(`PublishPlaying`, `PublishStopped`) that the caller acts on.)

Wire-up (via `LinkSession` in T4):
- `LinkSession::on_user_start()` drives a `UserStart` event; if the
  FSM emits `PublishPlaying`, call
  `session.set_is_playing(true, clock_micros()) +
   commit_audio_session_state`.
- A periodic `poll_link_transport` (called from the CLI loop or,
  later, the audio callback's control path) reads
  `session_state.is_playing()` and drives `LinkReportsPlaying` /
  `LinkReportsStopped` events to keep the local FSM in sync.

State exposed to the rest of agogo via `LinkSession::is_playing() ->
bool` (backed by the FSM's current state).

**Forerun FSM explicitly deferred to v0.5 Sprint 01.** The hardware
Multiclock's one-bar NEG/POS forerun isn't implemented; Playing
transitions take effect immediately. Flagged in Deferred and
cross-referenced with `doc/agogo.md §10`. The rust-fsm declaration
here is the extension point — v0.5 Sprint 01 adds `PreRoll` and
forerun-aware transitions to this same declaration.

### T3 — `Channel::snap_to_quantum` + orchestrator hook

Files:
- `crates/core/src/channel/transform.rs` — add
  `pub snap_to_quantum: Option<Quantum>` field to `Channel`. Default
  is `None`. `Channel::default()` unchanged (field defaults to `None`).
- `crates/host-link/src/session.rs` — `LinkSession::arm_channel(ch,
  stc)` computes the snap offset for channels with
  `snap_to_quantum = Some(q)` when Link is active:
  1. Read Link session state.
  2. Call `session_state.request_beat_at_time(next_beat,
     clock_micros() + small_future_budget, quantum_to_f64(q))`
     (request, not force — respects peer negotiation; the
     `Quantum → f64` cast is `// Link FFI`).
  3. `commit_audio_session_state`.
  4. Compute the sample delta between "Tick(0) at buffer_start"
     and "Tick(0) at the requested beat-time" via the anchor —
     result is an `i64` sample count. Plan 09 uses the static
     `HostTimeAnchor` (stored on `LinkClock`, set at session start
     and on `set_anchor` calls); v0.5 Sprint 02 swaps it for the
     per-buffer atomic anchor.
  5. Convert the sample delta to `Micro` via
     `F12F06.ceil(psc.inner(delta_samples))` where `psc =
     PicoSampleConn::new(anchor.sample_rate)`, then add it to
     `ch.offset: Micro` (post-enforcement field type). No open-coded
     `samples * 1e6 / sr` — every conversion is a ladder Conn.

When the active `PhaseSource` is the PLL, `snap_to_quantum` is
silently ignored (quantum has no meaning outside Link). A CLI
warning if `snap_to_quantum = Some(_)` and `--source=pll` is
nice-to-have — deferred as T5 follow-up.

**The scheduler is unchanged.** Plan 03's `scheduler_block_equivalence`
property must pass bit-for-bit when `snap_to_quantum = None`.

### T4 — `LinkSession` orchestration (thin)

Files:
- `crates/host-link/src/session.rs`.

Glue type that brings T1 + T2 + T3 together. Deliberately thin — no
audio-callback integration (Plan 05), no per-buffer anchor (v0.5
Sprint 02), no PID (v0.5 Sprint 02), no Playhead coordination
(Plan 06).

```rust
pub struct LinkSession {
    clock: LinkClock,
    transport: TransportFsm,
    quantum: Quantum,                 // Micro-backed, not f64
    config: LinkWriteConfig,
}

pub struct LinkWriteConfig {
    pub enable_start_stop_sync: bool, // subscribe to Link is_playing
    pub enable_start_stop: bool,      // allow User* events to publish
    pub default_quantum: Quantum,
    pub push_tempo_on_change: bool,
}

impl LinkSession {
    pub fn new(initial_bpm: Tempo, anchor: HostTimeAnchor,
               config: LinkWriteConfig) -> Self;

    /// Control-thread: push a new BPM to the Link network.
    pub fn set_tempo(&mut self, bpm: Tempo);
    /// Control-thread: drive `UserStart` through the FSM; may emit
    /// a `set_is_playing(true, now)` publish.
    pub fn user_start(&mut self);
    pub fn user_stop(&mut self);
    /// Control-thread: poll Link's `is_playing` flag and drive the
    /// FSM with `LinkReportsPlaying` / `LinkReportsStopped` events.
    pub fn poll_transport(&mut self);
    /// Any-thread: read the current transport state.
    pub fn is_playing(&self) -> bool;
    /// Control-thread: compute a snap offset for a channel and add
    /// it to `ch.offset: Micro`. No-op when `ch.snap_to_quantum`
    /// is `None` or the active `PhaseSource` is the PLL.
    pub fn arm_channel(&mut self, ch: &mut Channel, stc: &SampleTickConn);
}
```

`LinkSession` is the struct Plan 06's `Playhead` absorbs. v0.5
Sprint 02 will add `set_host_time_anchor(host_micros, sample_index)`
and swap `clock: LinkClock` semantics from direct phase source to
PID-smoothed reference.

### T5 — CLI exposure

Extend `crates/cli/src/main.rs`. Three new subcommands under the
existing `link` namespace; all feature-gated behind `--features link`.
**No `agogo run --link` yet** — that lands with Plan 05 (audio
callback) in v0.5 Sprint 02.

```
agogo link push-tempo <bpm>        # one-shot tempo write
    --bpm <f64>                    # argv; dies via F64TMP on entry

agogo link transport               # headless FSM runner
    --bpm <f64>                    # initial BPM (argv; F64TMP)
    --sr <u32>                     # NonZeroU32 after parse
    --quantum <f64>                # argv; F64QNT; default 4.0 bars
    --duration-ms <u32>            # how long to run
    [--start]                      # drive UserStart at session start
    [--stop-on-exit]               # drive UserStop before exit
    [--enable-start-stop-sync]     # default on — subscribe to Link
    [--enable-start-stop]          # default on — allow User* publish

agogo link diag                    # print current session state + peers
```

Both `f64`-typed argv fields die on the first line of the handler via
the matching Conn: `F64TMP.ceil(bpm_f64)` → `Tempo`,
`F64QNT.ceil(q_f64)` → `Quantum`. Nothing `f64` survives past the
handler boundary. Annotate each of those calls `// argv boundary` per
the post-enforcement CLAUDE.md rule.

`agogo link transport` runs a simple loop:
1. Construct `LinkSession` with the given config.
2. If `--start`, call `user_start()`.
3. Every ~10 ms, call `poll_transport()` and print the current
   `(peers, tempo_bpm, is_playing)` tuple when any of the three
   change.
4. After `duration_ms`, if `--stop-on-exit`, call `user_stop()`.
5. Exit.

Per-channel `snap_to_quantum` is not exposed via the CLI in Plan 09
— the `Channel` struct field exists, preset I/O + `--snap-channel`
style flags land with Plan 06 / the preset format sprint.

## Verification

### Properties (must pass)

| Property | Module | Invariant |
|----------|--------|-----------|
| `tempo_push_monotone` | `host-link::link` | sequence of `push_tempo(b1), push_tempo(b2), …` emits `set_tempo` calls with non-decreasing `at_time` values |
| `transport_fsm_deterministic` | `host-link::transport` | FSM state + emitted publishes are a pure function of the event sequence |
| `transport_fsm_no_spurious_publishes` | `host-link::transport` | `LinkReports*` events never trigger a `set_is_playing` publish; only `User*` events do |
| `quantum_snap_idempotent` | `host-link::session` | computing `arm_channel`'s snap offset twice in a row at the same Link state yields the same offset |
| `quantum_snap_nonneg` | `host-link::session` | snap offset `Micro` ≥ `Micro::ZERO` (snap goes forward to the next boundary, never backward) |
| `f64qnt_adjoint` | `agogo_core::fxp` | `F64QNT.ceil(q) ≤ x ⟺ q ≤ F64QNT.inner(x)` — the Conn's upper-adjoint law, validated on `f64` inputs across Link's ABI range |
| `f64qnt_matches_link_beats` | `agogo_core::fxp` | `F64QNT.ceil(q).0.0` (the inner `i64` of `Quantum(Micro(_))`) equals `llround(q * 1e6)` — bit-exact agreement with Link's own `Beats(double)` constructor |
| `scheduler_unchanged_by_link` | `channel::scheduler` | Plan 03's `scheduler_block_equivalence` still passes bit-for-bit when `snap_to_quantum = None` |

### Spot checks

- `LinkClock::new(Tempo::from_bpm_integer(120), …)`,
  `push_tempo(Tempo::from_bpm_integer(140))` — subsequent
  `link.capture_audio_session_state(&mut s); s.tempo()` returns
  `140.0` within one commit round-trip.
- `Channel { snap_to_quantum: Some(Quantum::from_bars(4)), … }` armed
  at a Link beat of `1.7` (1.7 beats into a 4-beat bar) schedules its
  first tick at the sample corresponding to Link beat `4.0` — i.e.
  the next bar boundary, `2.3 beats × samples/beat` later.
- `TransportFsm`: `Stopped + UserStart + LinkReportsStopped` ends in

  and then exactly one `set_is_playing(false, _)` — wait, correction:
  `LinkReportsStopped` doesn't publish, so the publish count is
  exactly one `(true, _)`. This spot check doubles as
  `fsm_no_echo_loop`'s sanity sibling.

## Review

**Scope deviations from the draft plan:**

1. **Plan 11 T2 + T5 pulled forward.** The enforcement sprint
   (plan-11, PR #10) landed only the scaffolding (rev bump, renames,
   `PicoSampleConn`, `tempo_to_hz` / `bits_q48_16_to_seconds`, PLL
   migration). The `Channel::{shift_ms, offset_ms}: f32 → Micro`
   flip (Plan 11 T2) and `LinkClock` Tempo surface (Plan 11 T5)
   were still on f32/f64 when Plan 09 started. Rather than write
   Plan 09 against pre-enforcement types and undo the work when
   Plan 11's remainder lands, the two flips were pulled into Plan
   09's first two commits. Plan 11 T2/T5 can now be closed as
   "absorbed into Plan 09" when its continuation lands.

2. **`arm_channel` does not take `&SampleTickConn`.** Plan 09's
   draft signature was `arm_channel(&mut self, ch: &mut Channel,
   stc: &SampleTickConn)` with the rationale that the sample-delta
   computation needed `psc.inner(_)` + `F12F06.ceil(_)`. In
   implementation, Link's host-time domain and agogo's `Micro`
   lattice are both microseconds — the snap delta is already in
   the target type. `PicoSampleConn` only enters the picture
   downstream in `transform::micro_to_samples` when applying the
   sample rate. Simpler signature, same semantics.

3. **`snap_offset_micro` is a pure query, not a
   `request_beat_at_time` publish.** The draft plan called for
   `request_beat_at_time(next_beat, now + small_future_budget, q)`
   followed by `commit_audio_session_state`. Implementation uses
   `beat_at_time(now, q)` + `ceil(current/q) * q` + `time_at_beat`
   — no side effects, no commit. This is what a per-channel snap
   *should* do (compute where the boundary would be, not move the
   Link timeline). The draft's approach would have mutated shared
   Link transport state for every channel arm; the pure-query
   form is correct and RT-cheaper.

4. **`LinkSession::enable` auto-enables start-stop-sync.**
   Discovered during integration-test development: Link's
   `is_playing` flag only propagates across peers that BOTH have
   start-stop-sync enabled, and it's off by default. The draft
   plan didn't call this out. Now handled transparently in
   `LinkSession::enable(on)` when `config.enable_start_stop_sync`
   is true (the default), and documented on
   `LinkClock::enable_start_stop_sync`.

**Draft-verification properties not (yet) covered, documented
here rather than `#[ignore]`'d:**

- `quantum_snap_idempotent` (exact) — the LinkSession-level
  `arm_channel_is_near_idempotent` substitutes with a 1 ms
  tolerance. Link's session state drifts µs between two
  `capture_audio_session_state` calls (the network sync runs
  continuously), so bit-exactness isn't achievable with a real
  `AblLink`. A fully-mocked Link (deferred to a future sprint
  with its own `MockPhaseSource`) could be bit-exact.
- `tempo_push_monotone` — the property is trivially true for
  agogo's push path (each `push_tempo` captures a fresh
  `clock_micros()` which is monotonically increasing). No
  dedicated proptest was written because the property holds by
  construction of `LinkClock::push_tempo`; an integration test
  with two pushes would fail on Link's internal debouncing, not
  on the monotonicity claim.

**F64QNT vs `f64_beats_to_quantum`.** The Prerequisites section
pinned `F64QNT: Conn<f64, Quantum>` as an agogo-local Conn. In
implementation, it's a standalone function `f64_beats_to_quantum`
with proptest coverage of the adjoint-monotonicity surrogate
(`f64qnt_monotone`) and bit-exact Link-agreement
(`f64qnt_matches_link_beats`). Full `Conn<f64, Quantum>` requires
upstream `float_conn!` to accept `i64`-backed newtypes — tracked
in the enforcement sprint's §Deferred. Swapping the helper for a
Conn constant when that lands is a mechanical rename.
