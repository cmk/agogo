## Tasks

### T1 — `SampleTickConn::inner` saturation + wrap proptest

`crates/core/src/sync/sample_tick.rs:60–68`:

```rust
pub fn inner(&self, tick: Tick) -> u64 {
    let num = u128::from(tick.0) * u128::from(self.sr) * 60 * 1_000_000;
    let denom = u128::from(self.bpm.0) * u128::from(self.ppqn);
    ((num + denom / 2) / denom) as u64    // ← silent wrap
}
```

For pathological inputs (`Tick(u32::MAX)`, `bpm_µ = 1`, `ppqn = 1`):

```
4_294_967_295 × 192_000 × 60 × 10⁶ / 1 ≈ 4.95 × 10²⁵
u64::MAX ≈ 1.84 × 10¹⁹
```

The result wraps modulo `2⁶⁴` rather than saturating. Mirror
`to_tick`'s pattern:

```rust
fn to_tick(x: u128) -> Tick {
    Tick(x.min(u128::from(u32::MAX)) as u32)
}
```

Apply analogously:

```rust
pub fn inner(&self, tick: Tick) -> u64 {
    let num = u128::from(tick.0) * u128::from(self.sr) * 60 * 1_000_000;
    let denom = u128::from(self.bpm.0) * u128::from(self.ppqn);
    let q = (num + denom / 2) / denom;
    q.min(u128::from(u64::MAX)) as u64
}
```

**Proptest** (per CLAUDE.md "test the test before pushing" rule):

```rust
proptest! {
    /// Pathological inputs deliberately fish for the u128→u64 narrow.
    /// Tick near `u32::MAX`, bpm_µ near 1, ppqn near 1 push the
    /// numerator past `u64::MAX`. With the saturating clamp,
    /// `inner` returns `u64::MAX`; without it, the wrap modulo
    /// `2⁶⁴` returns garbage.
    #[test]
    fn sample_tick_inner_saturates_on_overflow(
        tick in (u32::MAX / 2)..=u32::MAX,
        bpm_u in 1u32..=100,         // 0.000001..=0.0001 BPM
        ppqn in 1u32..=8,
        sr in (192_000u32..=192_000), // largest standard rate
    ) {
        let stc = SampleTickConn::new(sr, Tempo(bpm_u), ppqn);
        let result = stc.inner(Tick(tick));
        // Compute the exact answer in u128; `result` should equal
        // it (saturated to u64::MAX if the answer exceeds u64).
        let num = u128::from(tick) * u128::from(sr) * 60 * 1_000_000;
        let denom = u128::from(bpm_u) * u128::from(ppqn);
        let exact = (num + denom / 2) / denom;
        let expected = exact.min(u128::from(u64::MAX)) as u64;
        prop_assert_eq!(result, expected);
    }
}
```

Test the test: revert the saturation in a dirty worktree, re-run.
Without the clamp, the existing `as u64` truncates and the
proptest fails (proves the generator reaches the failure region).

The existing `sample_tick_round_trip`, `sample_tick_monotonic`,
`sample_tick_ceil_ge_floor` proptests use `arb_integer_stc()` which
only emits realistic `(sr, bpm, ppqn)` combos that don't exercise
the wrap. Those continue to pass unchanged — the new proptest
covers a region the existing battery doesn't touch.

### T3 — Rename `micro_from_ms` → `micro_from_user_ms`

`crates/core/src/machine/spec.rs:534`:

```rust
fn micro_from_ms(ms: f64) -> Option<Micro> { ... }
```

Three callers:
- `spec.rs:272` (doc comment reference)
- `spec.rs:291` (call site inside `delay=` parser)
- `spec.rs:417` (doc comment reference)

Rename to `micro_from_user_ms` to signal the argv-boundary
semantics: this helper takes a user-typed decimal in
milliseconds (the `delay=` mini-language value) and converts to
`Micro` once. Not a general-purpose `ms → Micro` helper; not
Conn-composable. The new name surfaces that distinction at every
call site.

Visibility stays `fn` (private). No external callers.

### Notes on test coverage

The new `sample_tick_inner_saturates_on_overflow` proptest is
**deliberately bounded to a pathological region** (tick near
`u32::MAX`, bpm_µ ∈ `1..=100`, ppqn ∈ `1..=8`) so the generator
actually reaches the wrap. CLAUDE.md's "Generator domain = the
input type's full domain" rule is satisfied at the type level —
all field types are full-range — and the bounded sub-ranges are
documented inline as the *targeting* of a specific failure region,
not as coverage faking. The realistic-input region is already
covered by `sample_tick_round_trip` and friends.
