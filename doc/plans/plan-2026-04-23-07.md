# Plan 10 — Post-fxp enforcement: f32/f64 + ad-hoc conversion audit fixes

**Sprint plan — ships across two MRs.**
- **MR #1 (this branch):** scaffolding + PLL migration. Rev bump, T0
  (`PicoSampleConn`), T1 (`tempo_to_hz` / `bits_q48_16_to_seconds` +
  dead-helper cleanup), T6 (PLL consumes the new helpers). No public
  API changes; no stored-state flips.
- **MR #2 (next plan branch):** boundary sweep + enforcement. T2
  (Channel → Micro), T3/T4 (CLI argv f64 + ProbeRow), T5 (host-link
  `Tempo` surface), T7 (`scripts/check-floats.sh` + CI), T8
  (CLAUDE.md rules + review-calibration Patterns 9/10/11).

Splitting this way gives MR #1 a zero-risk review profile (pure
scaffolding + internal refactor), so the plateau of "new types +
new helpers" can merge quickly; MR #2 then lands every boundary
migration and locks it in with the grep gate and the codified
rules.

## Goal

Close two workspace-drift classes:

1. **No stored `f32` / `f64`** outside the five documented exceptions
   (PI controller, PCM audio ABI, parabolic-fit ABI-local, CLI argv
   boundary, Link FFI).
2. **No ad-hoc numerical conversions** where a named `Conn` (or a
   runtime Conn-lookalike with the same adjoint-law proptests)
   already exists or can be introduced.

Both rules get codified in `CLAUDE.md` and `doc/reviews/review-calibration.md`
(MR #2) so future sprints reject regressions at review time.

After the fxp flip (PR #5), host-link (PR #6), and the Link phase

but has drifted back in a handful of places. Reviewer didn't flag

## Tasks

### T0 — `PicoSampleConn` Conn-lookalike for Pico↔Sample

`crates/core/src/time/conn.rs`.

Do NOT bolt `pico_floor` / `pico_ceil` / `pico_inner` onto the
existing `SampleTickConn` as a loose bundle. That would be a grab-bag
of casts, not a Galois connection. Instead, add a sibling struct
mirroring `connections::sample::F12SXX`'s shape, runtime-parameterised
by sample rate (the same `fn`-pointer-capture constraint that forced
`SampleTickConn` to be a Conn-lookalike):

```rust
/// Pico ↔ Sample bridge parameterised by sample rate. Mirrors
/// `connections::Conn<Pico, i64>` and obeys the adjoint laws
/// `ceil(x) ≤ s ⟺ x ≤ inner(s)` and `inner(s) ≤ x ⟺ s ≤ floor(x)`.
///
/// Not a real `Conn` because its conversion depends on runtime `sr`
/// (closure-capturing `Conn` variant is tracked upstream).
#[derive(Copy, Clone, Debug)]
pub struct PicoSampleConn {
    sr: u32,
}

impl PicoSampleConn {
    pub fn new(sr: u32) -> Self;
    pub fn ceil(&self, p: Pico) -> i64;    // rounding up
    pub fn inner(&self, s: i64) -> Pico;   // exact on the sr grid
    pub fn floor(&self, p: Pico) -> i64;   // rounding down
}
```

Samples are `i64` (signed) so negative Pico input produces negative
samples; unsigned callers cast via `.max(0) as u64` at their
boundary.

Implementation: u128 integer math. Formula: `sample = pico * sr /
10^12`, with per-direction rounding (ceil adds `(10^12 - 1)` to the
numerator; floor uses `div_euclid`; inner uses `pico = sample * 10^12
/ sr`, `div_euclid`).

Proptests (co-located, same style as `SampleTickConn`):

1. `adjoint_upper`: `psc.ceil(p) ≤ s ⟺ p ≤ psc.inner(s)`.
2. `adjoint_lower`: `psc.inner(s) ≤ p ⟺ s ≤ psc.floor(p)`.
3. `monotone_ceil`, `monotone_floor`.
4. `floor_le_ceil`: `floor(p) ≤ ceil(p)` for all `p`.
5. `inner_round_trip_aligned`: for Pico values on the sample-period
   grid, `inner(ceil(p)) == p` and `inner(floor(p)) == p`.
6. `tick_pico_sample_triangle`: `tick → pico → sample` agrees with
   `tick → sample` within the tolerated rounding.

### T1 — Retire bespoke `f32_*_to_*` / `f64_*_to_*` helpers in `fxp.rs`

`crates/core/src/fxp.rs`. Delete the existing argv-conversion helpers
and replace with named `Conn<FloatExt<f64>, Extended<Target>>`
constants following the same adjoint-law shape as upstream `F64Fxx`:

```rust
use connections::{conn::Conn, extended::Extended, float_ext::FloatExt};

pub const F64TMP: Conn<FloatExt<f64>, Extended<Tempo>>;   // f64 BPM → Tempo
pub const F64PHS: Conn<FloatExt<f64>, Extended<Phase>>;   // f64 cycles → Phase (Q0.32)
pub const F64Q15: Conn<FloatExt<f64>, Extended<Q15>>;     // f64 in [0,1] → Q0.15 u16
```

`Q15` is a new `#[repr(transparent)] pub struct Q15(pub u16)`
co-located with `Tempo`/`Phase`. Each conn proptested for the full
adjoint-law battery (reuse strategy shape from upstream
`fixed::tests::float_conn_props`).

Plus two two-argument helpers (not Conn-shaped, PI-exempt because
they feed the control-law inputs):

```rust
pub fn tempo_to_hz(bpm: Tempo, ppq: u32) -> f64;            // PI-exempt
pub fn bits_q48_16_to_seconds(bits: i64, sr: u32) -> f64;   // PI-exempt
```

Argv helper signatures become single-line Conn applications. Keep
the old function names as no-op thin shims only if a one-sprint
grace period is wanted — otherwise delete outright and migrate
call sites.

CLI takes `f64` everywhere (BPM, ms, threshold). The old f32 argv
paths die in T3.

### T2 — Channel state flips to `connections::fixed::Micro`

```rust
let offset_samples = psc.ceil(F12F06.inner(channel.offset));
```

Identical pattern in `crates/core/src/channel/scheduler.rs`. Every
conversion is a named ladder application plus a runtime Conn-lookalike
method.

`F64F12.ceil`.

### Design deviations

- **`F64TMP` / `F64PHS` / `F64Q15` Conn constants dropped from T1.**
  Plan originally specified these as full-shape
  `Conn<FloatExt<f64>, Extended<T>>`. The target types are u32 /
  u16-backed, which doesn't fit upstream's i64-backed `float_conn!`
  macro without duplicating it. The argv-boundary helpers
  (`f64_bpm_to_tempo`, `f64_phase_to_phase`) already exist and are
  semantically equivalent for the "ceil" direction that the CLI
  parser uses. Deferred; see §Deferred beyond MR #2.
- **`PicoSampleConn` uses Q48.16 samples, not `i64`.** Plain
  integer samples can't represent sub-sample Pico offsets at 44.1
  kHz (`10¹²` isn't divisible by 44 100); the Galois laws would
  break there. Using `connections::sample::Q48_16` matches upstream
  `F12S44` / `F12S48` / etc. exactly and makes both adjoint laws
  hold across every IEEE-reasonable rate. Callers extract integer
  sample counts via `.ceil().to_num::<i64>()` at the boundary.
- **MR split.** Not a deviation per se, but the plan's original
  "ships in one branch" was loosened to MR #1 + MR #2 once the
  change-set crossed ~500 LoC and started touching public API in
  T2. MR #1 stays pure scaffolding for low review load.

### Recommendations

- MR #2 should start with T2 immediately (Channel state → Micro),
  since T3/T4/T5 all consume the new `Channel` shape.
- The `// PI-exempt` / `// argv boundary` / `// Link FFI` /
  `// PCM ABI` / `// ABI-local` comment convention that T7's grep
  gate will enforce should be applied defensively at every float
  site as T2–T5 land, so T7 can be added without a separate
  annotation pass.
