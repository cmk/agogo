# Plan 07 — Link read-only (structural slice)

## Goal

Land the workspace + API scaffolding for Ableton Link integration: a
new feature-gated `crates/host-link/` crate wrapping `rusty_link`, a
`PhaseSourceImpl` trait + `PhaseSource::Custom(...)` extension variant
in `agogo-core::sync`, and a `agogo link probe` CLI subcommand that
prints peers and tempo. **Phase-at-sample math is deliberately
deferred** to a follow-up sprint after the in-flight fixed-point
refactor (`plan/2026-04-23-03`) merges — `phase_at_sample` ships as an
explicit unimplemented stub here so the refactor can land the final
sample-index ↔ host-time bridge in the right numeric types.

## Context

This sprint lands Sprint A of the Link integration as outlined in the
approved design doc at `/Users/cmk/.claude/plans/lets-do-a-bit-hashed-dream.md`.
Full Sprint A would also implement the phase bridge (host-time
anchor, `phase_at_sample(n)`, monotonicity property tests). That path
touches `f32`/`f64` arithmetic on phase values — the same surface the
concurrent fxp refactor (`plan/2026-04-23-03`, commits `6251586 plan:`
and `ed03f9e feat(core): fxp shim`) is replacing with rate-typed sample
+ decimal time tiers. Shipping both against each other risks conflict;
**this plan ships only the non-numerical parts**, leaves
`LinkClock::phase_at_sample` as a `todo!()` stub, and queues the
numerical slice for a "Plan 07-b" sprint once fxp merges.

Decisions already locked in by the combined design doc and the follow-up
AskUserQuestion (quoted in the Claude Code plan file):

- Binding: `ext/rusty_link` (thin FFI over abl_link C wrapper, sync,
  RT-safe). The pure-Rust alternative `ext/ableton-link-rs` is tokio-
  first and rejected.
- Link and the audio-PLL are mutually exclusive `PhaseSource` variants
  — no hybrid / voting.
- Placement: a sibling `crates/host-link/` crate, matching the
  `host/cpal, host/coremidi, host/winmm` pattern in `doc/agogo.md §5`.
  `agogo-core` stays free of the CMake + C++ build cost.
- Dependency: `rusty_link` pinned at rev `5b3f44e81b0aa30dae4b0650b2f5882048c0b842`
  (currently the HEAD of upstream `https://github.com/anzbert/rusty_link`).
  Consumed via a workspace path dep to `ext/rusty_link` — `ext/` is
  gitignored, each developer clones `rusty_link` with submodules into
  their worktree's `ext/`. CI does not build the `link` feature until
  the CMake/C++ CI story is settled (a separate chore).
- `PhaseSource` extension point: add a `Custom(Box<dyn PhaseSourceImpl + Send>)`
  enum variant plus a `PhaseSourceImpl` trait in `crates/core/src/sync/source.rs`.
  The one-vtable-hop-per-buffer cost is unmeasurable; the alternatives
  (feature on core, full trait-ification) are rejected per the design
  doc.

### T1 — `PhaseSourceImpl` trait + `Custom` variant

Files:
- `crates/core/src/sync/source.rs` — add the trait and the new variant:

  ```rust
  /// RT-safety contract: `phase_at_sample` must be non-blocking and
  /// allocation-free. `feed_samples` may be called per audio buffer
  /// from the audio thread.
  pub trait PhaseSourceImpl: Send {
      fn phase_at_sample(&mut self, n: u64) -> f32;
      fn feed_samples(&mut self, samples: &[f32], start: u64);
  }

  pub enum PhaseSource {
      Internal { bpm: f32, sr: u32 },
      External { detector: PeakDetector, pll: Pll },
      Custom(Box<dyn PhaseSourceImpl + Send>),
  }
  ```

  Delegate in `PhaseSource::phase_at_sample` and `PhaseSource::feed_samples`
  to the inner impl for the `Custom` arm. Note: this change is
  compatible with the fxp refactor — the refactor will flip the
  return type of both the trait method and the enum method in
  lockstep.

- `crates/core/src/sync.rs` — re-export `PhaseSourceImpl` alongside `PhaseSource`.

Unit test in the same file: a mock `PhaseSourceImpl` that records
calls; wrapping it in `PhaseSource::Custom(...)` and invoking through
`PhaseSource::phase_at_sample(0)` must reach the mock.

### T2 — `LinkClock` lifecycle (no phase math)

Files:
- `crates/host-link/src/link.rs` — the actual module.

API:
```rust
pub struct LinkClock {
    link: rusty_link::AblLink,
    session: rusty_link::SessionState,
}

impl LinkClock {
    /// Construct a disabled LinkClock. Networking is off until
    /// `enable(true)` is called. **Not RT-safe** — opens a socket
    /// and spawns Link's internal threads internally.
    pub fn new(initial_bpm: f64) -> Self;

    /// Toggle Link peer discovery / session joining. **Not RT-safe.**
    pub fn enable(&self, on: bool);

    /// Whether peer discovery is currently on. RT-safe.
    pub fn is_enabled(&self) -> bool;

    /// Current session tempo in BPM. RT-safe.
    pub fn tempo(&mut self) -> f64;

    /// Number of connected peers. RT-safe.
    pub fn num_peers(&self) -> u64;
}

impl agogo_core::sync::PhaseSourceImpl for LinkClock {
    /// **Deferred to Plan 07-b (post-fxp).** Panics to surface
    /// incorrect use in this slice. The host-time ↔ sample bridge
    /// lands once fxp's Phase / Sample types are available.
    fn phase_at_sample(&mut self, _n: u64) -> f32 {
        unimplemented!(
            "LinkClock::phase_at_sample is deferred to Plan 07-b; \
             requires the fxp Phase / Sample types"
        )
    }

    fn feed_samples(&mut self, _samples: &[f32], _start: u64) {
        // Link derives tempo from network, not from audio input.
    }
}
```

Notes on construction: `rusty_link::AblLink::new(bpm: f64) -> AblLink`
is synchronous and opens a UDP socket (per rusty_link's docs); it
must not run on the RT thread. That restriction applies to
`LinkClock::new` and `LinkClock::enable` transitively. Document this
in the rustdoc per method — all four getters (`is_enabled`, `tempo`,
`num_peers`, and eventually `phase_at_sample`) are RT-safe and use
`capture_audio_session_state` + direct field reads.

### T3 — CLI `agogo link probe`

Files:
- `crates/cli/src/main.rs` — extend with a new feature-gated subcommand.

```
agogo link probe
    --initial-bpm <f64>   # tempo to initialise Link with (default 120.0)
    --duration-ms <u32>   # total probe duration (default 3000)
    --period-ms <u32>     # sampling period (default 100)
```

Output: CSV with columns `t_ms,peers,tempo_bpm`. No phase column
this iteration. The loop calls `std::thread::sleep(Duration::from_millis(period_ms))`
between rows; Link's background threads handle peer discovery
transparently.

Dispatch: new `#[cfg(feature = "link")] enum LinkSub { Probe { ... } }`
and a `#[bpaf(command("link"))]` variant on the existing `Command`
enum, also `cfg`-gated.

## Review

### `#[ignore]`d properties

None introduced by this sprint. `LinkClock::phase_at_sample` is
wired as `unimplemented!()` with a matching `#[should_panic]` test
rather than `#[ignore]`d — the panic surfaces misuse in any dependent
code path, and Plan 07-b replaces the stub body directly.

### Design deviations from the plan

1. **Workspace `exclude = ["ext"]` added.** Not explicitly called out
   in T0's file list but necessary in practice: without it,
   `cargo test --workspace` picks up `ext/rusty_link` as an implicit
   workspace member and runs its doc tests (two of which fail
   upstream). Excluding `ext/` keeps third-party path deps as
   libraries only.

2. **`parse_positive_f64` helper was already in the tree.** Plan 07
   assumed it would need to be added for the `--initial-bpm` flag;
   it had already landed as part of Plan 03's `channel trace`
   subcommand (commit `c93b351..755df4e`). Reused verbatim.

3. **T4 merged into T1 and T2 commits.** The plan listed T4 as a
   separate "tests" task. Per the repo's "do not commit a library
   module without its tests in the same commit" rule (CLAUDE.md),
   the trait-plumbing test went in with T1's enum variant, and the
   lifecycle tests went in with T2's implementation. The CLI smoke
   test rides with T3.

### Recommendations for Plan 07-b (post-fxp phase bridge)

- Once the fxp `Phase` and rate-typed `Sample` land, replace
  `LinkClock::phase_at_sample`'s body with the host-time bridge
  outlined in `/Users/cmk/.claude/plans/lets-do-a-bit-hashed-dream.md`
  (Sprint A, key design decisions): `HostTimeAnchor` struct, i128
  intermediate arithmetic for sample → host-µs, then
  `session.phase_at_time(host_micros, 1.0)` with the `f32`-to-1.0
  wrap guard from Plan 03.
- Remove the `#[should_panic]` test and replace with the numerical
  properties from the combined plan (`phase_monotonic_across_random_anchors`,
  spot checks for wrap-around and anchor-respect).
- Add the phase column to the CLI probe (`t_ms,peers,tempo_bpm,phase`)
  and accept `--sr` for the sample-rate portion of the anchor.

### Recommendations for Plan 08 (bidirectional)

- The `Custom(Box<dyn PhaseSourceImpl + Send>)` shape absorbs the
  bidirectional surface with zero changes: tempo push / transport
  publish become methods on `LinkClock` (not on the trait), called

- `rust-fsm 0.7` lands in Plan 08 as a new workspace dep; scope the
  FSM to `Stopped`/`Playing` with the declaration structured to
