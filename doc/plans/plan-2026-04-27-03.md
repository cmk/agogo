# Plan 26 — Q2: Conn-discipline sweep (audit findings M + N)

## Goal

Close the **M-family** (open-coded `× 1.0e±N` unit arithmetic
disguised as Conn wrappers) and **N-family** (lossy `as` casts /
narrowing without a named saturation contract) audit findings.
Every numerical conversion that was hand-rolled becomes a
composition of lawful, proptest-backed `Conn` constants from
`agogo_core::time::{decimal, sample}` (or a thin, well-named
helper that wraps a single visible composition).

This is step Q2 of the four-PR Conn-discipline + float-surface
sweep. Q1a vendored the type families; Q1b swept to canonical
names; Q2 closes the discipline gap.

## Context

The audit (`/Users/cmk/.claude/plans/harmonic-snacking-conway.md`)
documents 13 sites that violate CLAUDE.md's "Cross-conversions
compose existing `Conn`s — they are not hardcoded" rule. After
Q1a + Q1b, the lawful primitives are in scope under canonical
names:

- `F064FD03: Conn<ExtendedFloat<f64>, Extended<FD03>>` (f64 ms → milliseconds)
- `F064FD06: Conn<ExtendedFloat<f64>, Extended<FD06>>` (f64 → microseconds)
- `F064FD12: Conn<ExtendedFloat<f64>, Extended<FD12>>` (f64 → picoseconds)
- `FD06FD03: Conn<FD06, FD03>` (lossless ms ↔ µs)
- `FD12FD06: Conn<FD12, FD06>` (lossless µs ↔ ps; `inner` does ×10⁶)
- `connections::conn::std::u32::I064U032: Conn<i64, u32>`
  (saturating narrowing: `ceil(-1) = 0`, `ceil(i64::MAX) = u32::MAX`,
  `inner: u32 → i64` is lossless widening)
- `connections::conn::compose!` macro for compile-time chaining

## Tasks

### T1 — Add helpers in `crates/core/src/fxp.rs`

Three new public items at the bottom of `fxp.rs` (alongside
`f64_bpm_to_tempo` etc.):

```rust
impl Tempo {
    /// `|self - other|` as u32, without sign-flipping through i64.
    pub const fn abs_diff(self, other: Tempo) -> u32 {
        self.0.abs_diff(other.0)
    }
}

/// `Tempo` (u32 microBPM) → f64 BPM via the lawful
/// `F064FD06.inner` Conn-inverse. The `10⁶` unit shift lives
/// inside `F064FD06`'s definition — not open-coded here.
///
/// `Tempo` is u32; `I064U032.inner` widens losslessly to i64;
/// `F064FD06.inner(Extended::Finite(FD06(i64)))` returns
/// `ExtendedFloat<f64>`. The unwrap is total because the input
/// chain is pure `Finite` → `Extend`.
pub fn tempo_to_f64_bpm(t: Tempo) -> f64 {
    let widened = I064U032.inner(t.0);
    match F064FD06.inner(Extended::Finite(FD06(widened))) {
        ExtendedFloat::Extend(b) => b,
        // Unreachable: I064U032.inner of a u32 never overflows i64,
        // and F064FD06.inner of Extended::Finite never lifts to
        // Bot/Top. Keep saturating-safe defaults so the function
        // stays total.
        ExtendedFloat::Bot => f64::NEG_INFINITY,
        ExtendedFloat::Top => f64::INFINITY,
    }
}
```

Plus one method on the `SampleTime` trait:

```rust
pub trait SampleTime: SampleRate + Copy + Default + Ord + core::fmt::Debug {
    // ... existing methods ...

    /// Q48.16 sample position as f64 (integer + sub-sample
    /// fraction). `bits / 2^16` is the standard binary-fixed →
    /// float conversion; the `1u64 << 16` divisor is intrinsic
    /// to the Q48.16 representation, not an SI unit shift.
    fn samples_f64(self) -> f64 {
        self.to_bits_q48_16() as f64 / (1u64 << 16) as f64
    }
}
```

### T2 — Rewrite forward conversions (M1, M2, M3)

`crates/core/src/fxp.rs`:

```rust
// f64_beats_to_quantum (was: scaled = (q * 1_000_000.0).round())
pub fn f64_beats_to_quantum(q: f64) -> Quantum {
    if !q.is_finite() {
        return Quantum::ZERO;
    }
    match F064FD06.ceil(ExtendedFloat::Extend(q)) {
        Extended::Finite(fd06) => Quantum(fd06),
        Extended::PosInf => Quantum(FD06(i64::MAX)),
        Extended::NegInf => Quantum(FD06(i64::MIN)),
    }
}

// f64_bpm_to_tempo (was: scaled = (b * 1_000_000.0).round())
pub fn f64_bpm_to_tempo(b: f64) -> Tempo {
    if !b.is_finite() || b <= 0.0 {
        return Tempo::ZERO;
    }
    let bpm_micro = match F064FD06.ceil(ExtendedFloat::Extend(b)) {
        Extended::Finite(fd06) => fd06.0,
        Extended::PosInf => return Tempo(u32::MAX),
        Extended::NegInf => return Tempo::ZERO,
    };
    Tempo(I064U032.ceil(bpm_micro))
}

// tempo_to_hz (was: bpm.0 as f64 / 1.0e6 inline)
pub fn tempo_to_hz(bpm: Tempo, ppq: u32) -> f64 {
    // PI-exempt: ppq * Hz arithmetic stays f64; the Tempo→f64
    // conversion is lawful (tempo_to_f64_bpm uses F064FD06.inner).
    tempo_to_f64_bpm(bpm) * ppq as f64 / 60.0
}
```

## Review

### Implementation deviations from the plan

The plan's T2 was over-ambitious about what `Conn` composition
can express. Three categories of audit findings turned out to be
**not Conn-composable** and were re-documented as bounded
exceptions rather than rewritten:

1. **`F064FDxx` interprets f64 as canonical seconds, not as the
   rung's unit.** This is the connections crate's documented
   convention. Concretely:
   - `F064FD03.ceil(0.5) = FD03(500)` — 0.5 s → 500 ms.
   - `F064FD06.ceil(0.5) = FD06(500_000)` — 0.5 s → 500_000 µs.

   So the audit's "rewrite `micro_from_ms` to compose `F064FD03`"
   is wrong: `F064FD03.ceil(ms_value)` would interpret a
   millisecond input as **seconds**, getting the answer 1000×
   too large. The user-input `ms` (or `µs`) must first be
   converted to canonical seconds via `× 10⁻³` (or `× 10⁻⁶`)
   — and that shift has no Conn equivalent, because the F-ladder
   is rooted in seconds. Both **M1** (spec.rs) and **M2**
   (cli/main.rs `ms_to_micro` and the µs jitter site) keep
   their leading user-unit shifts with new "argv-boundary
   user-unit-to-canonical-seconds shift" annotations per
   CLAUDE.md exception 4.

2. **Round-half-away-from-zero (Link FFI requirement) is not
   a Galois adjoint.** `F064FD06.ceil` rounds **up**;
   `F064FD06.floor` rounds **down**. Neither matches Link's
   C++ `std::llround` (round-half-away-from-zero), which
   `f64_beats_to_quantum` and `f64_bpm_to_tempo` must agree
   with bit-for-bit at the FFI seam. The proptest
   `f64qnt_matches_link_beats` caught this immediately when
   I tried `F064FD06.ceil` — q=944307.2541834672 produced
   944307254184 vs the spec's 944307254183. Both bodies keep
   `(x * 1_000_000.0).round()` with new "FFI-parity exception"
   annotations. The auto-captured proptest seed for that
   q-value is now committed as a regression gate against
   future "let's switch to ceil" attempts. The **i64→u32
   narrowing** for `Tempo` IS lawful and goes through
   `I064U032.ceil` (closes the saturating-cast portion of
   M3 + N5).

3. **N2 (scheduler.rs `.0 as i64`) was a misdiagnosis.** The
   audit assumed `stc.floor(swung_lo).0` was a `SampleTime`
   Q48.16 unwrap. It's actually a `Tick` (u32) → i64 lossless
   widening — `Tick` has no `to_bits_q48_16` method (it's a
   wrapping u32 counter, not a Q48.16 sample position). The
   `.0 as i64` is benign u32 widening. No fix needed; not a
   Conn-discipline violation.
