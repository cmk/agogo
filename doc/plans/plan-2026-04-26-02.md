# Plan 21 — Sum-typed `Channel` + per-target role enums (audit P3)

## Context

Audit plan finding **B** + **C**: `ChannelMode`
(`crates/core/src/channel/mode.rs`) is a flat enum that mixes
routing-target encoding with role:

```rust
pub enum ChannelMode {
    MidiClock,                         // MIDI-target role
    Din,                               // DIN-target role
    AnalogPulse,                       // CV/analog role
    AnalogLfo,                         // CV/analog role
    MidiCc { cc: U7, range: (U7, U7) },// MIDI-target role
    Click(ClickConfig),                // ← only agnostic-role variant
}
```

Only `Click(ClickConfig::Midi(MidiClickConfig))` follows the
"agnostic role + nested target-specific config" pattern that PR #21
established. Every other variant encodes the routing target in the
variant name. The current renderer dispatch on `ChannelMode`
silently no-ops on unsupported variants
(`crates/core/src/out/midi.rs:475-491`'s `non_clock_modes_are_noop`
test literally codifies the silent-no-op as the contract).

This is **P3 of the structural-type audit** — the major reshape.
With P1 (U7/U4 newtypes — PR #23) and P2 (drop `snap_to_quantum` —
PR #25) merged, the `Channel` field set is stable; P3 reshapes the
routing axis itself. After P3, a non-MIDI `Channel` variant won't
*type-check* as input to `render_midi_channel`. Silent no-ops
become compile errors.

## Goal

1. Replace `Channel` (struct) with a sum-typed `Channel` enum
   tagged by routing target (`Midi` | `Din` | `Cv`).
2. Extract the shared field set into `ChannelCommon`
   (`divider`, `shuffle`, `delay`, `offset`, `bar_multiplier`).
3. Replace `ChannelMode` with per-target role enums:
   `MidiRole { Clock, Click, Cc }`, `DinRole { Sync24 }`,
   `CvRole { Pulse, Lfo }`.
4. Split `render_channel_block(&Channel, ...)` into per-target
   renderers (`render_midi_channel(&ChannelCommon, &MidiRole, ...)`)
   plus a `Playhead`-level dispatch on the outer `Channel` variant.
5. Migrate all `ChannelMode::*` literals (67 references across 10
   files) to the new shape.
6. Delete `ChannelMode`.

The `Audio` variant from the audit's recommended target shape is
**deferred**: an empty `AudioRole` enum would make `Channel::Audio`
uninhabited, which is structurally honest (no audio renderer
exists yet) but would require a placeholder variant for any test
fixture that wants to construct it. v0.4's audio-click renderer is
the natural slot to add `Channel::Audio { common, role:
AudioRole::Click(AudioClickConfig) }`; until then, the routing
axis has three variants, not four.

## Dependency Graph

```
T1 (define ChannelCommon, role enums, Channel sum type) ──┐
                                                          ├─→ T2 (transform()/scheduler take ChannelCommon)
                                                          │
                                                          ├─→ T3 (render dispatch split: Playhead matches outer
                                                          │      variant; render_midi_channel narrows to MidiRole)
                                                          │
                                                          ├─→ T4 (spec.rs into_channel → Channel::Midi)
                                                          │
                                                          └─→ T5 (sweep all ChannelMode::*  literals across 10 files)
                                                                  │
                                                                  └─→ T6 (delete old ChannelMode + struct)
```

T1 is the foundation. T2 + T3 + T4 are mechanical and independent
of each other (all depend only on T1). T5 is the bulk of the diff
(test literals). T6 is the cleanup that confirms the migration
is exhaustive: deletion only succeeds if no caller still
references `ChannelMode::*`.

## Tasks

### T1 — `crates/core/src/channel/role.rs` (NEW module)

```rust
//! Per-routing-target role enums + the shared `ChannelCommon`
//! field set. Channels are sum-typed by routing target
//! (`Channel::Midi | Din | Cv`); each variant carries a
//! `ChannelCommon` and a target-specific `*Role` payload.

use core::num::NonZeroU16;

// `MidiClickConfig` lives in this module (see below) — the old
// `crate::channel::mode::*` path is deleted in T6.
use crate::midi::U7;
use crate::time::grid::Grid;
use crate::time::swing::SwingConfig;
use connections::conn::fixed::Micro;

/// Field set shared across all `Channel` variants — the
/// scheduler/transform pipeline operates on this struct alone.
#[derive(Copy, Clone, Debug)]
pub struct ChannelCommon {
    pub divider: Grid,
    pub shuffle: SwingConfig,
    pub delay: Micro,
    pub offset: Micro,
    pub bar_multiplier: Option<NonZeroU16>,
}

/// MIDI-target role: what kind of MIDI channel-voice / system-real-time
/// payload this channel emits.
#[derive(Copy, Clone, Debug, Eq, PartialEq, Hash)]
pub enum MidiRole {
    /// `0xF8` System Real-Time Clock per scheduled tick.
    Clock,
    /// Note On + same-sample Note Off per scheduled tick.
    Click(MidiClickConfig),
    /// Continuous-controller value over `range`. Stub — rendering
    /// path lands in v0.2.
    Cc(MidiCcConfig),
}

#[derive(Copy, Clone, Debug, Eq, PartialEq, Hash)]
pub struct MidiCcConfig {
    pub cc: U7,
    pub range: (U7, U7),
}

/// DIN-sync target role.
#[derive(Copy, Clone, Debug, Eq, PartialEq, Hash)]
pub enum DinRole {
    /// 24 PPQN sync pulse stream. Stub — spec surface only.
    Sync24,
}

/// Analog/CV target role. Stub family — rendering lands in v0.2+
/// (`out/audio.rs` for both variants; `Pulse` is single-sample
/// gate, `Lfo` is sample-rate continuous waveform).
#[derive(Copy, Clone, Debug, Eq, PartialEq, Hash)]
pub enum CvRole {
    Pulse,
    Lfo,
}
```

### T1b — `crates/core/src/channel/mod.rs`: replace `Channel` with the sum type

```rust
pub mod mode;        // legacy ChannelMode — DELETED in T6
pub mod role;        // NEW: ChannelCommon + per-target role enums
pub mod scheduler;
pub mod transform;

pub use role::{ChannelCommon, CvRole, DinRole, MidiCcConfig, MidiRole};
pub use transform::{Channel, MAX_DELAY, ScheduledEvent};
// ChannelMode + the old struct are NOT re-exported after T6.
```

In `crates/core/src/channel/transform.rs`:

```rust
/// Per-channel configuration, sum-typed by routing target. Each
/// variant carries a `ChannelCommon` and a target-specific role
/// payload. Renderers narrow on the outer variant: a non-MIDI
/// `Channel` doesn't type-check as input to `render_midi_channel`.
#[derive(Copy, Clone, Debug)]
pub enum Channel {
    Midi { common: ChannelCommon, role: MidiRole },
    Din  { common: ChannelCommon, role: DinRole },
    Cv   { common: ChannelCommon, role: CvRole },
}

impl Channel {
    /// Borrow the shared common field set regardless of variant.
    pub fn common(&self) -> &ChannelCommon { ... }
    pub fn common_mut(&mut self) -> &mut ChannelCommon { ... }
}
```

### T2 — `transform()` + `scheduler` take `&ChannelCommon`

`transform::transform` currently takes `&Channel`. Change to
`&ChannelCommon` — it only reads `divider`, `shuffle`, `delay`,
`offset`. Same for `scheduler::tick_stream` and
`scheduler::tick_stream_into`.

Callers update with `ch.common()`:

```rust
// Today
transform(master, &ch, &stc)
// After
transform(master, ch.common(), &stc)
```

### T3 — render dispatch split

`crates/core/src/out/midi.rs`:

```rust
/// Render one MIDI channel's block to the sink. Match-exhaustive on
/// `MidiRole`; the `Playhead`-level dispatch hands us only `Channel::Midi`
/// variants, so a `Cv`/`Din` channel literally cannot reach this
/// function.
pub fn render_midi_channel(
    common: &ChannelCommon,
    role: &MidiRole,
    events: &[ScheduledEvent],
    transport: Option<MidiRtByte>,
    buffer_start_sample: u64,
    click_counter: Option<&mut u32>,
    sink: &dyn MidiSink,
) {
    let _ = common; // unused today; v0.5 uses for per-channel mute/etc.
    match role {
        MidiRole::Clock => render_buffer(events, transport, buffer_start_sample, sink),
        MidiRole::Click(cfg) => {
            let counter = click_counter.expect("Click role requires counter slot");
            render_midi_click_block(events, cfg, counter, sink);
        }
        MidiRole::Cc(_) => {} // v0.2+
    }
}
```

`render_channel_block(&Channel, ...)` is **deleted**. The dispatch
moves up into `Playhead::on_buffer`:

```rust
match channel {
    Channel::Midi { common, role } => {
        render_midi_channel(common, role, events, transport, buf_start,
                            Some(&mut self.click_counters[idx]), sink);
    }
    Channel::Din { .. } | Channel::Cv { .. } => {
        // No renderer yet for these targets — sink is MIDI-only in v0.1.
    }
}
```

The `non_clock_modes_are_noop` proptest in `out/midi.rs:475-491`
becomes meaningless (it tested that non-MIDI modes silently no-op
through the MIDI renderer — which is now a *compile error* because
non-MIDI Channels can't be passed to `render_midi_channel` in the
first place). It gets **deleted**.

### T4 — `spec.rs` `into_channel` produces `Channel::Midi`

The current parser only emits `ChannelMode::MidiClock` or
`ChannelMode::Click(ClickConfig::Midi(_))` — both MIDI-targeted.
So `into_channel` always returns `Channel::Midi { ... }`:

```rust
let role = match self.mode {
    ChannelMode::MidiClock => MidiRole::Clock,
    ChannelMode::Click(ClickConfig::Midi(cfg)) => MidiRole::Click(cfg),
    // The other ChannelMode variants are never produced by the parser
    // (they're spec-surface stubs only).
    other => unreachable!("parser cannot produce {other:?}"),
};
Ok(Channel::Midi {
    common: ChannelCommon { divider: self.grid, shuffle: self.swing, delay, offset: Micro::ZERO, bar_multiplier: self.bars },
    role,
})
```

But wait — by T6, `ChannelMode` is deleted. So the spec parser's
internal `mode` field can't stay typed as `ChannelMode`. The
spec's `mode` field becomes typed as `MidiRole` directly (the
parser only ever produces MIDI roles, by construction).

### T5 — sweep all `ChannelMode::*` literals (67 references)

Mechanical migration across 10 files. The mapping:

| Old | New |
|-----|-----|
| `ChannelMode::MidiClock` | `MidiRole::Clock` (inside `Channel::Midi { role: ... }`) |
| `ChannelMode::Click(ClickConfig::Midi(cfg))` | `MidiRole::Click(cfg)` |
| `ChannelMode::MidiCc { cc, range }` | `MidiRole::Cc(MidiCcConfig { cc, range })` |
| `ChannelMode::Din` | `DinRole::Sync24` (inside `Channel::Din { role: ... }`) |
| `ChannelMode::AnalogPulse` | `CvRole::Pulse` (inside `Channel::Cv { role: ... }`) |
| `ChannelMode::AnalogLfo` | `CvRole::Lfo` (inside `Channel::Cv { role: ... }`) |

Channel literal shape changes too:

```rust
// Today
Channel {
    mode: ChannelMode::MidiClock,
    divider: Grid::T4,
    shuffle: SwingConfig { resolution: TBase::T16, amount: 0 },
    delay: Micro::ZERO,
    offset: Micro::ZERO,
    bar_multiplier: None,
}

// After
Channel::Midi {
    common: ChannelCommon {
        divider: Grid::T4,
        shuffle: SwingConfig { resolution: TBase::T16, amount: 0 },
        delay: Micro::ZERO,
        offset: Micro::ZERO,
        bar_multiplier: None,
    },
    role: MidiRole::Clock,
}
```

A small helper `channel_test_common()` in test modules where the
literal is repeated 5+ times reduces noise.

### T6 — delete `ChannelMode`

After T5 succeeds, `ChannelMode` has zero references outside its
own file. Delete `crates/core/src/channel/mode.rs` entirely; remove
`pub mod mode;` from `crates/core/src/channel/mod.rs`. The
`MidiClickConfig` / `MidiClickAccent` types move to
`crates/core/src/channel/role.rs` since `MidiRole::Click` carries
`MidiClickConfig`.

The deletion is the verification: if any call site still references
`ChannelMode::*` after T5, T6 won't compile.

### Design deviations from the plan

- **`Channel::common()` returns `&ChannelCommon`, not by value.**
  The plan's sketch implied a getter; the implementation matches
  that intent (3-arm match → reference into the variant). Same
  for `common_mut`.
- **`MidiCcConfig` stays in `role.rs` next to `MidiRole`** rather
  than getting its own file. The struct is 5 lines; a separate
  module is overkill.
- **`render_midi_channel`'s `_common` parameter is unused today**
  but kept in the signature for future per-channel mute / mix /
  transport-state logic (v0.5). Documented inline with a
  leading-underscore name.
- **`tick_stream` / `tick_stream_into` parameter renamed
  `channel: &Channel` → `common: &ChannelCommon`** instead of
  preserving the old name. The new name reflects the type
  precisely; the pre-P3 name was already a slight misnomer
  (the function never read `mode`).
- **Suppress-unused-import shim** `_channel_type_is_used` in
  `out/midi.rs` keeps the `Channel` import rooted in the
  `render_midi_channel` test module even though no test directly
  matches on it (they all go through `MidiRole` now). Avoids a
  warning-only clippy nit.
- **Hook didn't fire during commits** — this worktree was
  branched from `origin/main` before PR #24's hook fix landed.
  Ran the full `scripts/check-pii.sh && scripts/check-floats.sh
  && cargo test --workspace --quiet && cargo clippy --all-targets
  -- -D warnings` chain manually before each commit.

### Recommendations

- **Land #24 first** (still open as of this PR's creation), then
  this PR. Once #24 merges, future plan branches automatically
  pick up the corrected pre-commit hook.
- **Audit P4 is the natural follow-up.** With `Channel` sum-typed,
  `ChannelSpec` reshaping (sum-typed by `dev=` axis to mirror
  `Channel`'s variants) is the next structural cleanup.
- The `Channel::common()` accessor is a minor ergonomic cost at
  call sites that previously did `ch.delay` etc. — about 6 uses
  in control/transport.rs, transform.rs's tests, and bidirectional.rs.
  Consider adding `Deref<Target = ChannelCommon>` to `Channel` if
  the call-site count grows; the accessor is fine for now.
