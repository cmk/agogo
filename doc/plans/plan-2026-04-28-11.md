## Tasks

### T1 — `LpfPid` struct + `LpfPidSettings` + `LpfPidOutput`

**Problem.** The existing `Pll<R>` in `crates/core/src/sync/pll.rs`
exposes a pulse-event idiom: `fn step(&mut self, measured_pulse_sample:
Option<R>) -> PllOutput`. The eventual Link follower wants a
tempo-update idiom: every audio buffer call, hand it the current
target Tempo (from Link) and current observed Tempo (from agogo's
internal timeline) and get back a smoothed Tempo + a phase correction.

**Solution.** New module `crates/core/src/sync/lpf_pid.rs`:

```rust
pub struct LpfPid {
    pll: Pll<S048>,            // wrap the existing controller; rate is
                                // a sentinel — LpfPid doesn't index into
                                // a sample stream, it acts on Tempo deltas.
    lpf_state: Tempo,           // single-pole IIR over controller output
    settings: LpfPidSettings,
}

#[derive(Clone, Copy, Debug)]
pub struct LpfPidSettings {
    pub kp: PllSettings,        // re-use PI gain shape
    pub lpf_gain: Q15,          // 0.0 = pure passthrough, 1.0 = max smoothing
    pub clamp_hz: Hz,           // per-step Tempo Δ ceiling
}

#[derive(Clone, Copy, Debug)]
pub struct LpfPidOutput {
    pub tempo: Tempo,
    pub phase_correction: Phase,
}
```

The `Pll` field stays untouched — `LpfPid` *composes* the existing
controller, doesn't fork it.

### T2 — `fn step(target, observed, dt) -> LpfPidOutput`

**Problem.** The PI math itself is unchanged from `Pll::step`. The
wrapper's job is type-translation: Tempo→Tempo idiom (instead of
"pulse arrival timestamp" idiom).

**Solution.**

```rust
impl LpfPid {
    pub fn step(
        &mut self,
        target: Tempo,
        observed: Tempo,
        dt: Micro,
    ) -> LpfPidOutput {
        let err: Tempo = target.abs_diff(observed);  // signed — see below
        let raw: Tempo = self.pi_step(err, dt);      // // PI-exempt body
        let smoothed: Tempo = self.lpf_step(raw);    // single-pole IIR
        let clamped: Tempo = self.clamp_step(smoothed);
        self.lpf_state = clamped;
        LpfPidOutput {
            tempo: clamped,
            phase_correction: self.compute_phase_correction(target, clamped, dt),
        }
    }
}
```

The PI math (`pi_step`) is allowlisted PI-exempt per CLAUDE.md
exception 1 — intermediate locals get the `// PI-exempt` comment.
The LPF math is also exempt (it's the same control loop's smoothing
stage, by extension of the PI exception class — confirm in review).

`Tempo::abs_diff` already exists at `crates/core/src/time/tempo.rs:33`
(per the `doc/todo.md` audit-N3-resolved finding). For a *signed*
error, either add a `Tempo::signed_diff` helper or compute the sign
locally and carry it through the wrapper. Decide at T2 sprint time —
prefer extending `Tempo` if the operation is reusable.

### T3 — Proptests

**Problem.** Per CLAUDE.md, "properties that must hold for a sprint

**Solution.** `#[cfg(test)] mod tests` block at the bottom of

Strategies needed:

  pathological saw).
- Reuse existing `arb_bpm` for individual Tempo values.

## Verification

### Properties (must pass)

| Property | Module | Invariant |
|----------|--------|-----------|
| `lpf_pid_converges_to_step_target` | `sync::lpf_pid` | For any reachable target Tempo, output converges within the documented settling spec (steady-state error ≤ 0.05 BPM after N=200 steps at typical gains). |
| `lpf_pid_clamp_respected` | `sync::lpf_pid` | Output Tempo never exceeds `clamp_hz` from the previous step's output (smoothness guarantee). Catches a runaway P-gain. |
| `lpf_pid_zero_gain_is_passthrough` | `sync::lpf_pid` | `lpf_gain = 0` ⇒ output equals raw PI output (no smoothing). Useful as a regression sentinel. |
| `lpf_pid_no_alloc` | `sync::lpf_pid` | Zero allocations in `step` (DeallocTest pattern). |
| `lpf_pid_phase_correction_within_halfquantum` | `sync::lpf_pid` | The phase-correction output's magnitude ≤ half the wrapping period (mirrors v0.5's `wrapped_error_within_halfquantum` invariant from `doc/versions/version-0.5.md`). |
| `lpf_pid_step_response_no_overshoot_under_critical_damping` | `sync::lpf_pid` | At the critically-damped gain setting, step response monotonic — no overshoot (catches sign errors in the PI integrator). |
