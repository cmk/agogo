# Plan 04 — Host rustdoc on GitHub Pages + check-layers.sh port

## Goal
Publish workspace rustdoc to GitHub Pages on every push to `main`,
link the site from `README.md`, and port the upgraded
`scripts/check-layers.sh` from the sibling `stdio-core` repo so the
layering gate catches `pub use` re-exports and grouped imports.

## Dependency Graph

```
T1 (docs.yml workflow) ──┐
                         ├─> ship as PR (two commits)
T2 (README link)        ─┤
                         │
T3 (port check-layers)  ─┘
```

T3 is independent of T1/T2 and lands as its own commit so reviewers
can see the diff in isolation; both commits ride on the same PR per
the user's request.

## Tasks

### T1 — Add `.github/workflows/docs.yml`

Build `cargo doc --workspace --no-deps` and deploy the resulting
`target/doc/` to GitHub Pages. The job triggers on push to `main`
(deploy) and on PRs (build-only smoke check, no deploy).

- Toolchain: `dtolnay/rust-toolchain@1.85.0` to match `rust-toolchain.toml`.
- Cache: `Swatinem/rust-cache@v2`.
- ALSA dev headers (`libasound2-dev`) installed even though the four
  workspace members (`agogo`, `agogo-core`, `agogo-cli`, `agogo-host`)
  don't currently need them — leaves room for cpal/midi to migrate
  in without re-editing this workflow.
- Generate a top-level `index.html` that redirects to the facade
  crate (`agogo/index.html`) so the Pages root URL lands somewhere
  useful.
- Use the official `actions/configure-pages@v5`,
  `actions/upload-pages-artifact@v3`, `actions/deploy-pages@v4`
  pattern. Pages source must be set to "GitHub Actions" in the
  repo's Pages settings (one-time manual step; documented in plan
  Review).

`cargo doc` flags:

```sh
RUSTDOCFLAGS="-D warnings" cargo doc --workspace --no-deps --lib
```

`-D warnings` keeps broken intra-doc links from landing silently —
matches the `-D warnings` clippy gate. `--lib` skips bin targets:
the `agogo-cli` crate defines `[[bin]] name = "agogo"` which
otherwise collides with the facade lib crate's doc output path
(cargo issue #6313). `agogo-cli` is binary-only (no `lib.rs`), so
`--lib` excluding it costs nothing.

### T3 — Port `scripts/check-layers.sh` from stdio-core

The sibling `stdio-core` repo has an upgraded version that closes
the two blind spots the agogo script's docstring explicitly flagged
(see review-00048 context):

1. `pub use crate::<layer>::...` re-exports (line starts with `pub`,
   so the old grep skipped it).
2. `use crate::{conn::..., control::...};` grouped imports (the old
   regex required `[a-z]` immediately after `crate::`).

The port also adds `//! layer:` sentinel validation — if the layer
name in the file's header doesn't match the filename, the script
fails fast. This catches stale headers left over from a rename.

Agogo-specific bits to preserve when porting:
- `ALL_LAYERS=(channel conn control sink test time)` — keep agogo's
  six layers, not stdio-core's fifteen.
- `(crate|agogo_core)` regex — keep dual matching for cross-crate
  imports inside `crates/core/src/`. The stdio-core version dropped
  to `crate::` only.
- The HEREDOC error message — keep agogo's "partial-order layering
  rule" prose; stdio-core's points at a different design doc.
- Keep the smoke-test recipe in the docstring (inject violation
  into `crates/core/src/conn/fixed.rs` and run).

Audit before porting confirms no production file under
`crates/core/src/` uses either of the formerly-blind patterns, so
the port is a pure capability bump — no existing imports become
violations.

Also update AGENTS.md's `scripts/check-layers.sh` paragraph to
mention the new coverage so the docs and the gate stay in sync (per
the gardener rule).
