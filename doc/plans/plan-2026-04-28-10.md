# Plan 2026-04-28-10 — Audio-click channel (`Channel::Audio` + cpal output)

## Goal

A working `--ch dev=audio,div=…,env=…` channel that emits an audible
click on every scheduled tick via the cpal output stream. Closes two
top-level deferred items from `doc/todo.md` at once: "`Channel::Audio`
variant + `AudioRole::Click(AudioClickConfig)`" and "output buffer
writes (CV pulse, analog LFO)" — `io.output` is a zero-length stub
today (Plan 13 only opened the input stream).

Default sound: white noise gated by an ADSR envelope. Sample-loading
(`wav=path/to/file.wav`) is a stretch task (T6), gated to ship if
core scope is comfortable.

## Dependency Graph

```
T1 (Channel::Audio + AudioRole + AudioClickConfig types)
   │
   └──> T2 (spec parser: dev=audio + env=A/D/S/R + src=noise)
            │
            └──> T3 (sink/audio.rs renderer: ADSR + noise)
                     │
                     ├──> T4 (machine.rs orchestrator dispatch)
                     │
                     └──> T5 (host-cpal output stream + --audio-out flag)
                              │
                              └──> T6 [stretch] (sample loading via hound)
```

T1 lands the type vocabulary; T2 makes the spec parseable (replacing
the existing `AudioDeferred` rejection); T3 is the substantive renderer
work; T4 wires it through the orchestrator; T5 opens the actual cpal
output stream so render output is audible. T6 is opportunistic — drop
if T3 / T5 turn out to be larger than estimated.

## Tasks

### T1 — `Channel::Audio` variant + `AudioRole` + `AudioClickConfig`

**Problem.** `crates/core/src/channel/time.rs:41-54` declares
`enum Channel { Midi, Din, Cv }`. No `Audio` arm exists. Per the
file-internal comment at lines 37-39, "An empty `AudioRole` would
make the variant uninhabited; v0.4's audio-click renderer is the
natural slot to introduce both." — that's now.

**Solution.**

In `crates/core/src/channel/role.rs` (alongside `MidiRole` /
`CvRole` / `DinRole`):

```rust
#[derive(Clone, Copy, PartialEq, Eq, Hash, Debug)]
pub enum AudioRole {
    Click(AudioClickConfig),
}

#[derive(Clone, Copy, PartialEq, Eq, Hash, Debug)]
pub struct AudioClickConfig {
    pub source: AudioSource,
    pub env: AdsrEnv,
}

#[derive(Clone, Copy, PartialEq, Eq, Hash, Debug)]
pub enum AudioSource {
    Noise { seed: u32 },
    // T6 stretch: Sample(SampleHandle) — gated behind T6 task.
}

#[derive(Clone, Copy, PartialEq, Eq, Hash, Debug)]
pub struct AdsrEnv {
    pub attack: Micro,    // ramp-up time
    pub decay: Micro,     // attack-peak → sustain ramp
    pub sustain: Q15,     // sustain amplitude (0.0..=1.0)
    pub release: Micro,   // sustain → 0 ramp
}
```

All-fixed-point per CLAUDE.md "no stored f32/f64" rule. `Q15` is the
existing `connections` type for unit-interval scalars. `Micro` is the
existing µs-Q48.16 fixed-point.

In `crates/core/src/channel/time.rs:41-54`, add the variant:

```rust
pub enum Channel {
    Midi { common: ChannelCommon, role: MidiRole },
    Din { common: ChannelCommon, role: DinRole },
    Cv { common: ChannelCommon, role: CvRole },
    Audio { common: ChannelCommon, role: AudioRole },
}
```

Strategies for proptest live in `crates/core/src/channel/role/arb.rs`
(per CLAUDE.md colocation rule).

### T2 — Spec parser: accept `dev=audio` + `env=A/D/S/R` + `src=noise`

**Problem.** `crates/core/src/channel/spec/parser.rs:70` rejects
`dev=audio` with `ChannelSpecError::AudioDeferred`. The error variant
itself is at `crates/core/src/channel/spec/error.rs:15-16`.

**Solution.** Replace the rejection with parsing. New keys:

- `env=A/D/S/R` — slash-separated 4-tuple. A/D/R are `Micro` parsed
  via `F064FD06` (the existing argv-boundary Conn for ms→Micro).
  S is `Q15` parsed via the existing `f64_to_q15` argv helper. Format
  example: `env=2/30/0.5/40` (2 ms attack, 30 ms decay, 0.5 sustain,
  40 ms release). Default: `env=2/30/0.5/40` if key omitted.
- `src=noise` — only `noise` accepted in T1–T5. T6 adds `wav`.

The existing `note=` / `vel=` / `mch=` keys do **not** apply to audio
channels — silently rejected with `ChannelSpecError::KeyNotApplicable`
(or whatever the existing pattern is for "key not valid for this
device"; check at sprint time).

Drop the `AudioDeferred` variant from `error.rs`.

### T3 — `sink/audio.rs`: ADSR-noise renderer

**Problem.** No audio renderer exists. `:4`
has `pub mod midi;` only — the same comment block notes "v0.1 ships
only [`midi`]. `audio` (CV pulse + analog LFO) lands in v0.4 per
`doc/versions/version-0.4.md`."

**Solution.** Create `crates/core/src/sink/audio.rs`:

```rust
pub fn render_audio_click_block(
    events: &[ScheduledEvent],
    cfg: &AudioClickConfig,
    env_state: &mut EnvState,
    sr: u32,
    output: &mut [f32],            // PCM ABI
    buffer_start_sample: u64,
) { ... }
```

`EnvState` carries the per-channel envelope phase across buffer
boundaries (a tick triggered late in buffer N continues into buffer
N+1's release tail). Pre-sized in `Machine` alongside `events_pool`
and `click_counters` — no RT alloc.

Noise generation: deterministic LCG seeded per-channel from
`cfg.source` (`Noise { seed }`). LCG → i16 → f32 in `[-1.0, 1.0]`.
Multiplication by envelope amplitude (Q15 → f32 conversion at the
PCM ABI boundary, marked `// PCM ABI`).

**Write every sample, no preclear** — per `doc/todo.md`'s v0.4 rule,
cpal buffers have undefined contents on entry. Fill the entire output
slice (zero in idle frames, envelope-shaped noise in active frames).

`crates/core/src/sink/audio.rs` is added to `scripts/check-floats.sh`'s
`ALLOWED` list with the one-line justification: `// PCM ABI: cpal
output sample slice; LCG → f32 noise + Q15 envelope mul stay local
to the render fn`.

### T4 — Orchestrator dispatch

**Problem.** `crates/core/src/control.rs:359-378` dispatches per
channel via a `match ch { Channel::Midi {..} => ..., Channel::Din
| Channel::Cv => /* silent no-op */ }`. After T1, the new
`Channel::Audio { .. }` arm needs to call `render_audio_click_block`.

**Solution.** Add the arm:

```rust
Channel::Audio { common: _, role: AudioRole::Click(cfg) } => {
    render_audio_click_block(
        &self.events_pool,
        cfg,
        &mut self.audio_env_states[idx],
        io.sample_rate,
        io.output,
        io.buffer_start_sample,
    );
}
```

Pre-size `Machine.audio_env_states: Vec<EnvState>` at construction
based on the audio-channel count in the spec list. The `Din`/`Cv`
silent no-op arm stays unchanged.

When multiple audio channels are present, sum their outputs into
`io.output`. The first audio channel's render is "write the slice";
subsequent channels' renders sum-add (or use a scratch buffer per
channel and combine at the end). Decide implementation at T4 sprint
time; **whatever the choice, document the saturation policy** —
sum-then-clip to `[-1.0, 1.0]`, with a saturation flag raised on
first occurrence (reuse the existing `dropped_count` AtomicU64
pattern from `crates/host-cpal/src/cpal/control.rs:78`).

### T5 — `host-cpal` output stream + `--audio-out` CLI flag

**Problem.** Today `crates/host-cpal/src/cpal/callback.rs:120` test
uses `let mut output: [f32; 0] = []; // PCM ABI` — the production
callback wires through a zero-length output slice because Plan 13
only opened the cpal input stream. Without an output stream, T3's
renderer has nowhere to write.

**Solution.** In `crates/host-cpal/src/cpal/`:

- Open a cpal output stream alongside the input stream. New struct
  `CpalDuplexHost` (or extend the existing `CpalHost`) holds both.
- Output stream's data callback writes the rendered samples (filled
  in by `Machine::on_buffer` via `io.output`).
- New `--audio-out <dev>` flag in `crates/cli/src/main.rs` selects
  the output device. Default to `<input device>` if not specified
  (cpal allows this; same device handle is fine for single-stream
  duplex on most macOS/Linux backends).

Keep the input-only callback path for `agogo demo` (Plan 13 scope) —
the audio-out path is only required when at least one `--ch
dev=audio` spec is present. Detect this at startup and skip output
stream open if no audio channels exist (preserves the v0.1 sleep
budget for input-only configs).

### T6 — [stretch] Sample loading via `hound`

**Problem.** Default noise source is fine but a real click sample
(short percussive WAV) is more pleasant.

**Solution.** Add `hound` as an `agogo-core` dev/optional dep
(or `agogo-host-cpal` if cleaner). Decode WAV at startup on the
control thread (never RT). `SampleHandle = Arc<[f32]>` carried in
`AudioSource::Sample(SampleHandle)`. Resampling is **out of scope** —
sample must match the cpal stream rate (validate at parse time, error
otherwise).

`src=sample,wav=path/to/file.wav` parses; the actual WAV decode
happens after the parser builds the spec but before `Machine`
construction (so RT never sees the path).

**Cut from sprint if T3 + T5 turn out larger than estimated.** Noise
+ ADSR is the user's stated baseline ("nothing complex").

## Verification

### Properties (must pass)

| Property | Module | Invariant |
|----------|--------|-----------|
| `audio_click_lands_on_tick_sample` | `out::audio` | At v0.2 sweet-spot rates (integer samples-per-tick), the envelope's attack starts at the exact tick-boundary sample (no off-by-one vs the MIDI click renderer at `out::midi::render_midi_click_block`). |
| `audio_click_envelope_sums_to_finite_energy` | `out::audio` | For any ADSR + tick stream over N buffers, total emitted energy ≤ `n_ticks · max_envelope_integral`. Catches runaway envelope state on tick collision. |
| `audio_render_no_alloc` | `out::audio` | `render_audio_click_block` allocates zero bytes (DeallocTest harness pattern from `agogo_stdio::rt_bridge` properties in v0.3). |
| `audio_click_writes_every_sample` | `out::audio` | After render, every output sample index `0..output.len()` is written exactly once — not skipped on idle frames. Catches the cpal-undefined-contents bug. |
| `audio_spec_round_trips` | `machine::spec::parser` | `parse(display(spec)) == spec` for arbitrary `AudioClickConfig`. Mirrors the existing MIDI-spec round-trip. |
| `audio_mix_sum_clips_in_range` | `out::audio` | When N audio channels overlap on the same sample, summed amplitude ∈ `[-1.0, 1.0]` and the saturation flag is raised if any sample would have exceeded the range pre-clip. |
| `noise_lcg_deterministic_in_seed` | `out::audio` | Two `Noise { seed: s }` channels with identical envelopes and tick streams produce identical sample sequences (bit-exact). |

## Deferred

- **Stereo / multi-channel output.** v0.4 ships mono. Per-channel
  panning, multi-output routing → post-v0.5.
- **Sample-rate conversion of WAV files.** T6 requires the WAV's
  rate match cpal's; resampling is its own sprint.
- **CV pulse output** (the other half of v0.4's `sink/audio` per
  `doc/versions/version-0.4.md`) — different envelope shape (single
  sample impulse), different DC behaviour. Could share T3's renderer
  scaffolding but the proptests are different. Plan separately.
- **LFO render** — analog/CV LFO at sample rate. Post-v0.5.
- **Live audio parameter updates** (live ADSR knob via the atomic
  parameter bridge) — depends on the v0.3 control-plane work.
