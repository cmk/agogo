# Plan — CLI parser: clap → bpaf

## Goal

Swap the `agogo-cli` parser from `clap` (derive) to `bpaf` (derive),
preserving the `agogo sync trace` and `agogo time schedule` flag
surfaces and behaviour exactly, for a lighter dependency graph.

## Context

When this plan was first written, `time/` (Plan 01, PR #2) was still
open and had carried an earlier clap→bpaf swap bundled with its
Recologic-algebra work. That side of PR #2 was backed out during
rebase, then the `time schedule` subcommand landed on main under
clap. Separating the parser swap from both landed and in-flight
feature work has two wins:

1. Plan 03 (channel/, already opened on branch `plan/2026-04-23-01`)
   assumes a bpaf-based CLI in its Task T5. Landing the swap unblocks
   that assumption without re-bundling it into a feature PR.
2. Any future CLI extension sees one canonical parser style rather
   than a clap/bpaf mix.

Because PR #2 has already merged and introduced `agogo time schedule`,
the swap now covers **two** subcommand trees: `sync trace` (from
PR #1) and `time schedule` (from PR #2). The branch was originally
opened against pre-PR-#2 main and rebased onto post-merge main; the
rebase re-applied the swap against the wider surface.

T0 workspace deps ──→ T1 CLI parser rewrite ──→ T2 verify tests + E2E

## Tasks

### T0 — Workspace dependency swap

- `Cargo.toml`: replace `clap = { version = "4", features = ["derive"] }`
  with `bpaf = { version = "0.9", features = ["derive"] }`.
- `crates/cli/Cargo.toml`: replace `clap = { workspace = true }` with
  `bpaf = { workspace = true }`.
- `Cargo.lock` regenerates on next build.

### T1 — Rewrite `crates/cli/src/main.rs`

Replace the `clap::{Parser, Subcommand, Args}` derive tree with
`bpaf::Bpaf`. Both flag surfaces must be preserved bit-for-bit:

```
agogo sync trace \
    --bpm <f32, positive finite> \
    --sr <u32, ≥ 1> \
    --ppq <u32, ≥ 1> \
    [--jitter-us <f32, non-negative>  default 0.0] \
    --pulses <u32, ≥ 1> \
    [--seed <u64>  default 1]

agogo time schedule \
    --bpm <f32> \
    --tbase <TBase via FromStr: t1, t2, …, t128t> \
    [--swing <f32>  default 0.5] \
    --bars <u16>
```

Implementation notes:

- Keep the `parse_positive_f32` and `parse_non_negative_f32` helpers;
  wire them in via `bpaf`'s `parse(fn)` combinator.
- For the `u32 ≥ 1` validation (previously
  `clap::value_parser!(u32).range(1..)`), add a local `parse_positive_u32`
  helper — `bpaf` doesn't have a built-in range validator on primitives.
- For `--tbase`, use `argument::<String>("TBASE")` + `parse(parse_tbase)`
  where `parse_tbase` calls `TBase::from_str` (TBase's `FromStr::Err`
  is already `String`, so the conversion is a one-liner).
- Defaults via `fallback(...)`.
- `Cli::parse()` becomes `cli().run()` (the derive-generated function is
  `cli` when the struct is `Cli`).
- The `None` branch (print `agogo-cli (…)`) stays; `bpaf` treats a
  missing subcommand the same as `clap` here because `command` is
  `Option<Command>`.
- `ScheduleArgs` keeps its `time_sched` module home; `use time_sched::schedule_args;`
  at the top of `main.rs` lets the enum variant reference the derive-
  generated external parser by identifier.

No change to the `sync_trace` or `time_sched` *logic* — only the
parser annotations on `ScheduleArgs` flip from `clap::Args` to
`bpaf::Bpaf`.

## Verification

### Properties (must pass)

No new properties — this is a pure refactor. The existing property
tests in `agogo-core` continue to pass untouched.

### Spot checks

| Test | Module | Assertion |
|------|--------|-----------|
| `sync_trace_converges` | `cli::tests` | 256 pulses @ 120 BPM / 48 kHz / 24 PPQ / 50 µs jitter converge to within ±0.05 BPM of 120.0. Pre-existing; unchanged by the swap. |
| `schedule_ticks_*` (5 tests) | `cli::tests` | T16 two-bar count, swing offset, T128t 192-per-bar, T1 one-per-bar, swing-to-config boundaries. Pre-existing; unchanged by the swap. |

### Build gates

- `cargo build --workspace` — clean.
- `cargo test --workspace` — all pre-existing tests pass, no
  `#[ignore]` additions.
- `cargo clippy --all-targets -- -D warnings` — clean.
- E2E smokes (manual):
  - `cargo run -p agogo-cli -- sync trace --bpm 120 --sr 48000 --ppq 24 --jitter-us 50 --pulses 256 --seed 1`
    emits a CSV header plus 256 rows and the final row's `bpm_estimate`
    is within ±0.05 of 120.
  - `cargo run -p agogo-cli -- time schedule --bpm 120 --tbase t16 --swing 0.54 --bars 2`
    emits 32 tick positions, off-beats shifted by -4.
- Negative-path smoke: `--bpm 0`, `--bpm -1`, `--sr 0` each exit with a
  non-zero status and a clear message (matching the pre-swap clap
  behaviour, modulo wording).

## Review

### Deviations from the plan

1. **`--bpm -1` error path changed.** Under clap, `-1` parsed as an
   f32 and then my `parse_positive_f32` validator produced
   "must be a positive finite number, got -1". Under bpaf,
   arguments that start with `-` are read as flags, so `-1` is
   rejected at the parser layer with
   "`--bpm` requires an argument `BPM`, got a flag `-1`, try
   `--bpm=-1` to use it as an argument". Both paths exit status 1
   with a clear message; literal negative values must now be
   written `--bpm=-1`. Acceptable — negative BPM is invalid either
   way, and `--flag=value` is the documented bpaf idiom.

2. **`parse_positive_u32` helper added.** Clap's
   `value_parser!(u32).range(1..)` had no one-line bpaf equivalent,
   so I added a three-line validator mirroring the f32 helpers.

3. **Program name in `--help` is now `agogo-cli`, not `agogo`.**
   Clap's `#[command(name = "agogo")]` override has no direct bpaf
   derive equivalent. The binary on disk is `agogo-cli` so bpaf
   uses that. Cosmetic; doesn't affect any test or usage pattern.

4. **Scope widened by rebase.** The branch was cut before PR #2
   merged, so the original plan talked only about `sync trace`.
   Rebasing onto post-PR-#2 main pulled in the `time schedule`
   subcommand and its `time_sched::ScheduleArgs`, so the swap now
   covers both. The plan body has been updated to reflect this;
   the overall shape of the change (swap, not rewrite of logic) is
   unchanged.

### `#[ignore]`d properties

None added by this PR. Core still has one `#[ignore]` carried over
from PR #2 (`swing_zero_mean_over_beat`), documented there.

### Recommendations

- When Plan 03 (channel/) extends the CLI with `agogo channel trace`,
  follow the same bpaf derive pattern used here for `SyncSub::Trace`.
  A struct-variant with per-field `#[bpaf(long, argument(...), parse(...))]`
  is the lowest-friction shape — no helper struct needed.
- Consider adding `#[bpaf(version)]` to the top-level `Cli` in a
  follow-up so `agogo --version` works out of the box; kept out of
  this PR for tight scope.
