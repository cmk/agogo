# Plan 22 — Drop `ChannelSpec.dev` field (audit P4, structural cleanup)

## Context

Audit plan finding **A** (the headline bug) called out the
independent `dev` × `mode` axes on `ChannelSpec`:

```rust
ChannelSpec {
    dev: ChannelDev::Audio,
    mode: ChannelMode::MidiClock,        // structural nonsense
    ...
}
```

P3 (PR #26) collapsed `mode: ChannelMode` into `mode: MidiRole`, so
`dev=audio,mode=AnalogPulse` is no longer expressible. But the
narrower nonsense `dev=audio,mode=MidiClock` is still
representable at the spec level — `ChannelSpec.dev` is parser-stage
state with no other consumer:

- `cli/run.rs:126` reads `spec.dev` to filter for the "first MIDI
  port name" — but every spec is implicitly MIDI today, so the
  filter is a tautology.
- `into_channel` reads `spec.dev` once to short-circuit
  `dev=audio` to `AudioDeferred`. The check more naturally lives
  in the parser (where the bad value comes from) than in
  `into_channel` (which converts an already-validated spec to a
  runtime channel).
- `ChannelDev` is publicly re-exported from `agogo_core::machine`
  but only the parser / CLI uses it.

**P4 of the structural-type audit** drops the field and the
`ChannelDev` enum. The parser still validates the `dev=` key
(required, only `dev=midi` accepted; `dev=audio` returns
`AudioDeferred` at *parse* time instead of at *into_channel*
time). The user-facing CLI surface stays identical: `--ch
dev=midi,grid=t4` still parses, and Display still emits
`dev=midi,…` for round-tripping.

The full sum-typed `ChannelSpec` reshape (`enum { Midi, Din, Cv }`
mirroring `Channel`'s variants from P3) is **deferred** until a
second routing target gets a parser. Today every spec is
MIDI-targeted; a single-variant enum would be pure overhead. The
day `dev=din` or `dev=cv` lands, the right move is to add the
variants alongside the new parser keys.

## Goal

1. Remove `ChannelSpec.dev: ChannelDev` field.
2. Remove the `ChannelDev` enum (and its `pub use` re-export from
   `agogo_core::machine`).
3. Move the `dev=audio` → `AudioDeferred` check from
   `into_channel` to the parser body, so by the time a
   `ChannelSpec` exists, it represents a valid MIDI-targeted spec
   by construction.
4. Simplify `cli/run.rs:122-136` — the "first MIDI port name"
   filter collapses to "first spec's `out` field."
5. Tests + Display + arb_spec strategy update.

## Dependency Graph

```
T1 (drop field + enum + Display + parser audio-error move) ──┐
                                                              ├─→ T3 (CLI port-name filter simplification)
T2 (arb_spec + tests update)  ────────────────────────────────┘     │
                                                                     └─→ T4 (verify no callers leak)
```

T1 is the bulk of the change. T2 is mechanical (test fixtures
that currently set `dev: ChannelDev::Midi` drop the field). T3
collapses the CLI filter. T4 is the final grep.

## Tasks

### T1 — `crates/core/src/machine/spec.rs`: drop `dev` field

Remove from `ChannelSpec`:

```rust
pub struct ChannelSpec {
    pub id: Option<String>,
    pub dev: ChannelDev,    // ← REMOVE
    pub out: Option<String>,
    // ...
}
```

Remove the `ChannelDev` enum + its `Display` impl. Remove the
`pub use spec::ChannelDev` re-export at
`crates/core/src/machine.rs:35`.

In the parser body, the `"dev"` arm changes from "store into local"
to "validate only":

```rust
// Before
"dev" => {
    dev = Some(match v.as_str() {
        "midi" => ChannelDev::Midi,
        "audio" => return Err(ChannelSpecError::AudioDeferred),
        other => {
            return Err(ChannelSpecError::BadValue("dev", other.to_string()));
        }
    });
}

// After
"dev" => {
    match v.as_str() {
        "midi" => {} // ok, no field to set
        "audio" => return Err(ChannelSpecError::AudioDeferred),
        other => {
            return Err(ChannelSpecError::BadValue("dev", other.to_string()));
        }
    }
    dev_seen = true;
}
```

The parser still requires the `dev=` key (existing
`MissingKey("dev")` error preserved); a new local `dev_seen: bool`
gates that check.

`into_channel` simplifies:

```rust
// Before
pub fn into_channel(self) -> Result<Channel, ChannelSpecError> {
    if matches!(self.dev, ChannelDev::Audio) {
        return Err(ChannelSpecError::AudioDeferred);
    }
    // ... build Channel::Midi
}

// After
pub fn into_channel(self) -> Result<Channel, ChannelSpecError> {
    // dev=audio rejected at parse; offset_ticks rejected separately.
    // ... build Channel::Midi
}
```

Display: unchanged externally — `write!(f, "dev=midi,…")` becomes
`write!(f, "dev=midi,…")` (the "midi" is a literal now since
that's the only valid value). Round-trip preserved.

### T2 — arb_spec + spot-test fixture updates

`crates/core/src/machine/spec.rs:903-904`:

```rust
// Before
fn arb_dev() -> impl Strategy<Value = ChannelDev> {
    Just(ChannelDev::Midi)
}
```

Just delete the helper — the field is gone, no need to generate
it. The `arb_spec` strategy drops the `arb_dev()` arm.

The `parse_minimal` test at `:671` (`assert_eq!(spec.dev,
ChannelDev::Midi)`) becomes meaningless — drop the assertion.
Other tests that construct `ChannelSpec { dev: …, … }` literals
(if any) drop the field.

### T3 — `crates/cli/src/run.rs`: simplify port-name filter

```rust
// Before (lines 122-136)
let midi_port_request = named
    .iter()
    .find_map(|(_, spec)| {
        if matches!(spec.dev, agogo_core::machine::ChannelDev::Midi) {
            Some(spec.out.clone().unwrap_or_else(|| "default".to_string()))
        } else {
            None
        }
    })
    .ok_or_else(|| {
        "no `dev=midi` channels among --ch specs (v0.1 only routes MIDI; \
         dev=audio is reserved for v0.4)"
            .to_string()
    })?;

// After — every spec is implicitly MIDI; port name is the first
// spec's `out` (or "default").
let midi_port_request = named
    .first()
    .map(|(_, spec)| spec.out.clone().unwrap_or_else(|| "default".to_string()))
    .ok_or_else(|| "at least one --ch spec is required".to_string())?;
```

Note: the existing `args.ch.is_empty()` check at line 95 already
returns the required-spec error before this point, so the
`.ok_or_else` branch becomes structurally unreachable. Keep it as
defense-in-depth or replace with `.expect("args.ch non-empty
checked above")`.

### T4 — final sweep

`grep -rn "ChannelDev" crates/` returns nothing (excluding doc-
comment historical references). The build + tests pass. The
public `agogo_core::machine` API loses `ChannelDev` from its
re-export list.

## Out of scope

- **Full sum-typed `ChannelSpec` reshape** (`enum { Midi { ... } }`
  → `enum { Midi, Din, Cv }`). Single-variant enum is overhead
  until a second routing target gets a parser; the natural moment
  to introduce variants is when `dev=din` or `dev=cv` lands. P4
  achieves the structural goal (no dev × role nonsense) without
  the enum overhead.
- **Making `dev=` optional at parse** (default `midi`, omit in
  Display). User-facing CLI change; out of scope for an
  audit-cleanup PR. If desired, easy follow-up.
- **Audit P0a/P0b/P5** remain blocked on upstream `Conn::then`.
- **`MidiSink` typed-message migration** (audit finding E).
  Deferred.
