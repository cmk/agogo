### T4 — Move `Phase` / `Tempo` / `Quantum` to their proper crates

The three newtypes split three different ways based on what they
actually represent:

- **`Phase(u32)` Q0.32 → `core::sync::phase`**. NCO accumulator
  state. The wrapping_add/sub operations *are* controller math.
  Used by `sync::pll` (state) and `host-link` (Link's `f64` phase
  converted via `f64_phase_to_phase`).
- **`Tempo(u32)` BPM × 10⁶ → `core::time::tempo`**. BPM is a rate
  over musical time — pairs naturally with Tick / Time / Sxxx. The
  `time/` module's "no tempo coupling" invariant is about
  *operations* (the `SampleTickConn` violation T3 fixed), not about
  the existence of the tempo type. Used workspace-wide as currency.

  entirely). Every production caller is host-link-bound: the
  orchestrator builds a `Quantum` solely to call

  solely to feed `LinkSettings.default_quantum`. `core::machine::spec`
  produces it for the same reason. Pull it as far to the periphery
  as the dep graph allows.

**Body cleanups using upstream lifters:**

a. `tempo_to_f64_bpm` (currently a hand-rolled `match
   ExtendedFloat::Extend(b) => b, Bot|Top => unreachable!()`):

```rust
// crates/core/src/conn/boundary.rs
fn finite_or_unreachable(ef: ExtendedFloat<f64>) -> f64 {
    match ef {
        ExtendedFloat::Extend(x) => x,
        ExtendedFloat::Bot | ExtendedFloat::Top => unreachable!(
            "F064FD?? Conn::inner of Extended::Finite cannot lift to Bot/Top"
        ),
    }
}

pub fn tempo_to_f64_bpm(t: Tempo) -> f64 {
    let widened = I064U032.inner(t.0);
    finite_or_unreachable(F064FD06.inner(Extended::Finite(FD06(widened))))
}

pub fn pico_to_f64_seconds(p: Pico) -> f64 {
    finite_or_unreachable(F064FD12.inner(Extended::Finite(p)))
}
```

The `unreachable!` arm is colocated with the invariant proof, not
duplicated across two production helpers.

b. `pico_to_samples` (currently per-rate match with `FD12Sxxx.ceil(p).0.round().to_num()`):

`Q48_16 → i64-with-round-to-nearest` isn't a clean Galois adjoint
(round-to-nearest has no monotone partner), so introducing a
`Conn<S048, i64>` doesn't fit. The upstream-blessed shape for
"apply a unary endo on the source side, snap back through the
Conn pair" is the `ceiling1` lifter:

```rust
use connections::conn::ceiling1;

pub fn pico_to_samples(p: Pico, sr: u32) -> Option<i64> {
    fn snap_to_int(s: impl SampleTime) -> impl SampleTime {
        // illustrative; real shape uses Q48.16 round + extract
    }
    Some(match sr {
        44_100 => ceiling1(&FD12S044, |s| s.round_to_int(), p).to_int(),
        48_000 => ceiling1(&FD12S048, |s| s.round_to_int(), p).to_int(),
        // ...
        _ => return None,
    })
}
```

The closure runs in `Sxxx` (Q48.16) space and returns an `Sxxx`
snapped to integer. The outer `ceiling1` takes care of `Pico → Sxxx`
and back; the final `.to_int()` extracts the `i64`. Each `Sxxx` type
needs a `round_to_int(self) -> Self` method that snaps Q48.16 to
the nearest whole sample (`(bits + (1<<15)) >> 16 << 16`); this
lives in `time/sample.rs` alongside `SampleTime`.

If the `ceiling1` shape doesn't read better in practice (the
closure is short but introduces a method on `Sxxx`), fallback is
the `compose!` form:

```rust
44_100 => compose!(FD12S044, S044_TO_I64).ceil(p),
```

— if a lawful `S044 → i64` Conn (round toward `+∞`, exact embed,
round toward `-∞`) is constructible. Pick whichever shape lands
cleanest at implementation time; both express the composition.

The proptest `pico_to_samples_one_second_maps_to_sr` and friends
(currently in `fxp.rs:749–768`) move to `boundary.rs::tests` and
must pass unchanged.

### T10 — `host-link` f64-FFI containment + missing PCM-ABI annotation

Audit finding (`host-link/src/link.rs:239–246`): the helper
`next_quantum_boundary_us(session, q_f64) -> Micro` extracts the
quantum-boundary computation into a dedicated function but performs
the f64 arithmetic (`current_beat / q_f64`, `.ceil() * q_f64`)

(`session.beat_at_time`, `session.time_at_beat`). CLAUDE.md
exception 5 ("Link FFI") requires the float math to land "within
1–2 lines of the FFI call."

Two viable shapes:

(a) **Inline the helper into `snap_offset_micro`**, putting the
   FFI call and the `(beat / q).ceil() * q` arithmetic on the same
   line or adjacent lines, with `// Link FFI` comments on each.

(b) **Restructure the helper** so each FFI call is followed
   immediately (1–2 lines) by its f64 reduction to fxp, with the
   integer-domain math separated. Probably means doing the
   `.ceil() * q_f64` before the second FFI call and converting to
   `Micro` immediately after each FFI hop.

intent visible without harming readability. The audit P5 extraction
that motivated the original helper was about keeping the *public*
boundary clean; inlining preserves that property because
`snap_offset_micro` is itself the public seam.

annotation on the `&[f32]` slice parameter of

Properties: existing `host-link/tests/bidirectional.rs` and the
`snap_offset_*` proptests in `link.rs` continue to pass — this is a
pure restructure, no behaviour change.

  `time::float` lets them keep using `agogo_core::conn::float::Extended`
  without a Cargo.toml change.
