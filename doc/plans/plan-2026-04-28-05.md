# Plan 2026-04-28-05 — Extract 7 inline modules from cli/main.rs

## Goal

`crates/cli/src/main.rs` is 1722 lines. 887 of those are seven
inline `pub mod` blocks doing self-contained handler work; each
exports a single entry point and is independently feature-gated.
Plus a 172-line EOF `#[cfg(test)] mod tests` block that holds
tests for three of those modules.

This is the T11 deliverable from PR #35's audit
(`plan-2026-04-28-03.md` §What's actually disorganized). After
this PR:
- `main.rs` shrinks to ~650 lines (CLI enum hierarchy + parser
  fns + dispatch match + `main()`).
- Each handler module lives in its own sibling file with
  file-level `#[cfg(feature = "...")]`.
- The EOF `mod tests` block is gone — its three test cohorts
  (sync_trace, time_sched, channel_trace) move into the
  respective sibling modules' own `#[cfg(test)] mod tests`.

No functional changes. Pure file-layout work — the imports each
extracted module needs come along, the pub fn / pub struct
surface is preserved, and the dispatcher in `main()` keeps its
existing `super::foo::handler(...)` call shape now that `foo`
lives in `crate::foo`.

## Tasks

For each of T1-T7, the recipe is identical:

1. Create `crates/cli/src/<name>.rs` with:
   - File-level `#![cfg(feature = "<gate>")]` (or a module-level
     attribute via the `mod` declaration in `main.rs`).
   - Imports the module needs (lift them from the current inline
     `use ...` lines inside the module body).
   - The module's body — `pub fn`, `pub struct`, etc. — copied
     verbatim from `main.rs`.
   - For modules with tests in the EOF block, add a
     `#[cfg(test)] mod tests` at the bottom and move the
     relevant tests in.

2. In `main.rs`:
   - Replace `pub mod <name> { ... 100s of lines ... }` with
     `pub mod <name>;` (or `mod <name>;` if no external
     references; check via grep).
   - The dispatcher in `main()` keeps its `<name>::handler(...)`
     calls — those still resolve through the new `pub mod`
     declaration.

3. Run `cargo build --workspace --all-features`,
   `cargo test --workspace --all-features`,
   `cargo clippy --workspace --all-targets --all-features -- -D warnings`.
   Commit.

## Review

### What this PR ships

T1–T7 (the seven module extractions) and an absorbed T8 (deleting
the EOF `mod tests` block, which collapsed into T3 once the block
emptied). Plus a +1 commit at the end updating the check-floats
allowlist to track f64 surface area that moved with the modules.

### Design deviations from the plan

- **T3 + T8 collapsed.** The plan listed T8 ("delete EOF mod tests")
  as a separate task. After T1, T2, and the time_sched move pulled
  every test out of the EOF block, deleting the empty shell rode
  along with T3's commit rather than landing as a standalone "doc"
  commit. Smaller history, same effect.
- **Allowlist update needed.** The plan's verification table listed
  "scripts/check-floats.sh — unchanged (no f64 surface moves)" as
  expected. That was wrong: extracting `sync_trace`, `time_sched`,
  and `link_probe` moved their f64 surface (PCM input + argv
  boundary + a Q0.32 → cycles assertion) out of `cli/main.rs`'s
  allowlisted scope and into new files that needed to be added to
  `ALLOWED`. Fixed in the final commit. CLAUDE.md amended to track
  the now-20-entry allowlist.

### Notes on test coverage

Cli test counts unchanged across the extraction (39 + 39 across the
two `cli` binaries, both before and after). The tests now select
under different `path::to::tests` prefixes — `cli::sync_trace::tests::*`
instead of `cli::tests::*`, etc. — but every test still runs.
