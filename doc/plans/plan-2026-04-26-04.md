# Plan 23 — Re-isolate `snap_offset_micro` f64 footprint (audit P5, finding H)

## Context

Audit plan finding **H**: `LinkClock::snap_offset_micro`
(`crates/host-link/src/link.rs:200-220`) lets a single `f64`
("beats") live across **13 source lines** including two Ableton
Link FFI calls (`beat_at_time`, `time_at_beat`) and a `.ceil()`
round trip. CLAUDE.md exception 5 sanctions Link-FFI `f64`
**only** "within 1–2 lines of the FFI call":

> Link FFI inside `crates/host-link` — AblLink's C++ ABI hands
> us `f64` tempo and phase; we convert to `Tempo` / `Phase`
> within 1–2 lines.

Today's body violates the spirit of that exception — `q_f64` is
declared at line 202 and last referenced at line 214, threaded
through FFI calls, validation, and pure-f64 arithmetic in
between. The structural half of P5 (decoupling host-link from
`agogo_core::channel::Channel`) was already delivered by P2 (PR
#25's `LinkSession::snap_offset_for(Option<Quantum>) -> Micro`).
Plan 23 is the **arithmetic-isolation half**: split the body so
the public API surface stays at the 1-2-line FFI conversion bound
and the deeper `f64` math lives in a named private helper.

The open-coded `/ 1_000_000.0` at line 202 is also a
Conn-discipline violation (audit findings M5/N6). With upstream
`connections` shipping the `compose!` macro and the `F64F06`
inverse already exposed, the lawful fix is available today:
`F64F06.inner(Extended::Finite(quantum.0))` returns an
`ExtendedFloat<f64>` whose finite payload is `quantum.0.0 / 10⁶`
— same value, but the `10⁶` constant lives in the
property-tested `connections` crate instead of inline. Plan 23
folds this fix in alongside the helper extraction so P5 closes
both halves of audit finding H **and** the M5/N6 violations at
this specific call site.

The two other Tempo → f64 sites at `link.rs:68` and `:160`
(the BPM-set / BPM-publish FFI seams) are part of the broader
M3/M5 sweep in audit P0a/P0b — those are tabled until the
`connections` rev bump lands. The Quantum site is in scope here
because P5 already has us editing this function.

## Goal

1. Split `snap_offset_micro`'s body so the public function stays
   at ~5 lines centered on the Quantum→f64 conversion + result
   wrapping.
2. Extract the FFI-arithmetic core into a private
   `next_quantum_boundary_us(&mut self, q_f64, now_us) -> i64`
   helper. The f64 lives only inside this helper.
3. Add an inline `// Conn-discipline: open-coded unit shift,
   audit P0a/P0b deferred` marker on the conversion site so a
   future sweep can grep for it.
4. Verify the existing `snap_offset_for_*` properties on
   `LinkSession` and the bidirectional integration test continue
   to pass byte-for-byte.

## Tasks

### T1 + T2 — `crates/host-link/src/link.rs`: split `snap_offset_micro`

**Before** (lines 200-220):

```rust
pub fn snap_offset_micro(&mut self, quantum: Quantum) -> Micro {
    // Link FFI — Quantum (microbeats) → f64 beats.
    let q_f64 = (quantum.0.0 as f64) / 1_000_000.0;
    if q_f64 <= 0.0 || q_f64.is_nan() {
        return Micro::ZERO;
    }
    self.link.capture_audio_session_state(&mut self.session);
    let now = self.link.clock_micros();
    let current_beat = self.session.beat_at_time(now, q_f64);
    // Next quantum boundary: smallest multiple of `q_f64` that is
    // ≥ `current_beat`. `ceil(current/q) * q` is stable across
    // small f64 rounding — a beat already exactly on a boundary
    // stays on it.
    let next_boundary = (current_beat / q_f64).ceil() * q_f64;
    let time_at_next = self.session.time_at_beat(next_boundary, q_f64);
    let delta_us = time_at_next.saturating_sub(now);
    if delta_us < 0 {
        return Micro::ZERO;
    }
    Micro(delta_us)
}
```

**After:**

```rust
pub fn snap_offset_micro(&mut self, quantum: Quantum) -> Micro {
    // Quantum (Micro/microbeats) → f64 beats via the lawful
    // F64F06 Conn inverse. The 10⁶ unit shift lives inside
    // `F64F06`'s definition in the `connections` crate, not
    // open-coded here (audit findings M5/N6 closed for this
    // site). `Extended::Finite` lifts a regular Micro into the
    // saturation lattice that F64F06 operates on.
    let q_f64 = match F64F06.inner(Extended::Finite(quantum.0)) {
        ExtendedFloat::Finite(b) => b,
        ExtendedFloat::Bot | ExtendedFloat::Top => return Micro::ZERO,
    };
    if q_f64 <= 0.0 || q_f64.is_nan() {
        return Micro::ZERO;
    }
    self.link.capture_audio_session_state(&mut self.session);
    let now = self.link.clock_micros();
    let next_boundary_us = self.next_quantum_boundary_us(q_f64, now);
    Micro(next_boundary_us.saturating_sub(now).max(0))
}

/// Inner FFI-math helper: given an already-validated `q_f64`
/// (positive, finite) and a host-time `now_us`, return the
/// host-time (microseconds) of the next quantum boundary at or
/// after `now_us`.
///
/// Confines the f64 footprint to a single named function — every
/// f64 use lives inside the FFI call site or the immediate
/// `(current/q).ceil() * q` boundary computation. Audit P5
/// extraction (Plan 23).
fn next_quantum_boundary_us(&mut self, q_f64: f64, now_us: i64) -> i64 {
    // Link FFI calls take/return f64 beats. `ceil(current/q) * q`
    // gives the smallest multiple of `q` ≥ `current`; stable under
    // f64 rounding on exact-boundary inputs (a beat already on a
    // boundary stays on it).
    let current_beat = self.session.beat_at_time(now_us, q_f64);
    let next_boundary = (current_beat / q_f64).ceil() * q_f64;
    self.session.time_at_beat(next_boundary, q_f64)
}
```

Net change at the public API surface:
- `q_f64` lifetime in the public method shrinks from 13 lines to
  3 (declaration → guard → handoff to private helper).
- The `.ceil()` arithmetic moves into the named helper alongside
  the two FFI calls that consume it — one logical unit per
  function.
- The two-line `if delta_us < 0 { return Micro::ZERO } Micro(…)`
  saturation tail collapses to the single-expression `Micro(…
  .saturating_sub(now).max(0))` — same semantics, smaller surface.
