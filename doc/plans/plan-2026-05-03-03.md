# Plan 2026-05-03-03 — Remove SampleTickConn and boundary panics

## Goal

Replace `SampleTickConn` with a direct musical-clock conversion:

```text
Tick + Tempo + fixed PPQN
  -> rate-typed Q48.16 sample time (`S044` / `S048` / ...)
  -> whole sample count via `SxxxI064.ceil`
```

`FD06` / `FD12` stay at decimal SI boundaries: CLI delay, offset,
jitter, and FFI seams. Musical tick scheduling should not route
through `Pico`, because the exact tick duration is rational in
`Tempo` and `PPQN`; forcing it into decimal fixed precision creates
double-rounding pressure.

This sprint also moves user-reachable invalid input out of bridge and
scheduler panics. CLI parsers, host-command parsers, config loaders,
and FFI adapters return `Result` / `Option` with precise errors. Once
a value enters core scheduling, rendering, or bridge code, it should
either be type-validated or already boundary-checked.

The branch uses the flat fallback name `plan-2026-05-03-03` because
the documented slash branch `plan/2026-05-03-03` could not be created
in this worktree.

## Tasks

### T0 — Boundary validation and panic audit

- Add AGENTS language for the boundary-validation rule.
- Add `scripts/check-boundary-panics.sh`.
- Wire it into the cheap hook/check chain.
- Ban unannotated `assert!`, `assert_eq!`, `assert_ne!`, `expect`,
  `unwrap`, `panic!`, `unreachable!`, `todo!`, and `unimplemented!`
  in bridge/scheduler production modules.
- Ignore tests and allow a narrow marker comment for true internal
  invariants:

  ```rust
  // boundary-panic-ok: internal invariant, not user input
  ```

- Fix currently user-reachable invalid tempo paths, especially host
  integer BPM parsing accepting `0`.

### T1 — Rate-specific Tick → Q48.16 sample time

Add six rate-specific helpers:

```rust
tick_to_s044(tick: Tick, bpm: Tempo) -> S044
tick_to_s048(tick: Tick, bpm: Tempo) -> S048
tick_to_s088(tick: Tick, bpm: Tempo) -> S088
tick_to_s096(tick: Tick, bpm: Tempo) -> S096
tick_to_s176(tick: Tick, bpm: Tempo) -> S176
tick_to_s192(tick: Tick, bpm: Tempo) -> S192
```

For each rate:

```text
q48_16_bits =
  ceil_div(tick * sr * 2^16 * 60_000_000,
           bpm_µ * PPQN)
```

Use `PPQN` from `crate::time::tick::PPQN`; do not accept a runtime
PPQN argument. Saturate to the maximum representable Q48.16 sample
time rather than wrapping.

### T2 — Runtime sample-rate dispatch over static arms

Add a boundary helper:

```rust
tick_to_whole_samples(tick: Tick, bpm: Tempo, sr: u32) -> Option<u64>
```

It should visibly dispatch to rate-specific helpers and existing
static whole-sample conns:

```rust
48_000 => Some(I064U064.ceil(S048I064.ceil(tick_to_s048(tick, bpm))))
```

Unsupported rates return `None`. They do not panic.

### T3 — Remove SampleTickConn

Delete `SampleTickConn`, its constructor, accessors, tests, lower-PPQN
test cases, and stale docs that describe it as a conn-shaped
workaround. `ppqn = 24` belongs to MIDI clock cadence as a divider
over the 960-PPQN master tick stream, not as a configurable master
tick scale.

### T4 — Update scheduling APIs

Replace APIs that accept `&SampleTickConn` with explicit validated
inputs:

```rust
sr: u32,
bpm: Tempo
```

or a small plain context if that substantially reduces call noise. The
context must not pretend to be a `Conn`.

`Playhead::apply_tempo` updates only tempo. It must not reconstruct a
conn-shaped bridge object.

### T5 — Preserve SI boundary conversions

Keep `Micro -> Pico -> samples` behavior for channel delay and offset.
Those are user-entered SI durations and are correctly handled at the
decimal fixed-point boundary.
