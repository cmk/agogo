# Plan 03 — `channel/` + `SampleTickConn`

## Goal

Deliver the per-channel scheduler that consumes a master Tick stream
(from `sync::PhaseSource`) and emits sample-indexed scheduling events
for one downstream channel, after applying the divider / shuffle /
shift / offset transform pipeline. Land the §7 `SampleTickConn` shim
so Tick ↔ Sample translation is expressible despite `Conn`'s fn-
pointer constraint. Pure logic — no audio I/O, no MIDI bytes (those
are Plan 04). Verified against analytic master phases via proptest.

## Context

This is the third sprint of agogo v0.1 (see
[`../versions/version-0.1.md`](../versions/version-0.1.md)). It is
the bridge between the algebraic groundwork (`time/`, `sync/`) and
the I/O sprints (`out/`, `host/`, `bin/`).

Two foundation modules are assumed on `main`:
- `time/` (Plan 01, PR #2) — `Tick`, `Time`, `TBase`, `SwingConfig`
  with `effective_tick`, the five Galois connections in
  `time::conn`. **Note:** PR #2 was conflicting at the time this
  plan was written; if `time/` is not yet on `main` when
  implementation starts, wait for its merge or rebase this branch
  onto a base that includes it.
- `sync/` (Plan 02, PR #1, merged) — `PhaseSource`, `Pll`,
  `PeakDetector`.

References from `doc/agogo.md`:
- §3 module layout (`channel/{mod,mode,transform,scheduler}.rs`)
- §6 mapping (Divider = TBase choice, Shuffle = SwingConfig, Shift
  & Offset stay outside the grid lattice at the Sample layer)
- §7 the `SampleTickConn` workaround for `Conn`'s fn-pointer
  constraint
- §11 v1 out-of-scope (LFO is in v0.2, not v0.1 — see
  `doc/versions/version-0.1.md`)

### T1 — `SampleTickConn` shim

`crates/core/src/time/conn.rs` (lives alongside the five existing
Galois connections from Plan 01).

The fn-pointer constraint in `connections::Conn<A, B>` means the
natural `fn conn_sample_tick(sr, bpm) -> Conn<Sample, Tick>` is not
expressible — `Conn` cannot capture runtime state (§7). The
pragmatic workaround:

```rust
pub struct SampleTickConn { sr: u32, bpm: f64, ppqn: u32 }

impl SampleTickConn {
    pub fn new(sr: u32, bpm: f64, ppqn: u32) -> Self { ... }
    /// Sample → Tick, rounding down (latest Tick at-or-before sample).
    pub fn floor(&self, sample: u64) -> Tick { ... }
    /// Sample → Tick, rounding up (next Tick at-or-after sample).
    pub fn ceil(&self, sample: u64) -> Tick { ... }
    /// Tick → Sample (exact when arithmetic stays in integer space).
    pub fn inner(&self, tick: Tick) -> u64 { ... }
}
```

Mirrors `Conn`'s shape and laws. Uses `u128` intermediate arithmetic
to avoid overflow on multi-day sample streams.

### T3 — `Channel` + transform pipeline

`crates/core/src/channel/transform.rs`.

```rust
pub struct Channel {
    pub mode: ChannelMode,
    /// Dividing the master 192-PPQN stream down to a musical unit.
    /// Divider = TBase choice per agogo.md §6 mapping.
    pub divider: TBase,
    pub shuffle: SwingConfig,
    pub shift_ms: f32,    // clamped to ±300 ms
    pub offset_ms: f32,   // calibration offset
}

pub struct ScheduledEvent {
    pub sample_index: u64,
    pub tick: Tick,
}
```

Pipeline:

1. **Divide**: master Tick stream → channel-Tick stream by selecting
   only Ticks whose value is divisible by `divider.ticks_per_unit()`.
2. **Shuffle**: apply `SwingConfig::effective_tick` from Plan 01 to
   shift even-numbered ticks.
3. **Tick → Sample** via `SampleTickConn::inner`.
4. **Shift**: add `(shift_ms × sr / 1000)` samples (positive shifts
   delay; negative would advance — flagged in spec as requiring a
   ring buffer of future ticks, deferred to Plan 04 since v0.1 only
   needs forward-shift for MIDI clock-out latency calibration). For
   v0.1 the shift is **clamped to 0..=+300 ms**.
5. **Offset**: add `(offset_ms × sr / 1000)` samples.

The pipeline stays a pure function `(master_tick_stream, channel) ->
Vec<ScheduledEvent>`.

### T4 — Per-block scheduler

`crates/core/src/channel/scheduler.rs`.

```rust
pub fn tick_stream(
    phase: &mut PhaseSource,
    channel: &Channel,
    sr: u32,
    bpm: f64,
    buffer_start_sample: u64,
    frames: usize,
) -> Vec<ScheduledEvent>;
```

Computes which channel events fall inside the audio buffer
`[buffer_start_sample, buffer_start_sample + frames)` and returns
them sorted by `sample_index`. Pure: no I/O, no allocations beyond
the returned `Vec`.

The function:
1. Asks `phase` for the master Tick range covering the buffer (uses
   `SampleTickConn::ceil(start)` and `floor(end)`).
2. Runs the divider+shuffle in Tick space.
3. Maps each surviving Tick to a sample via `SampleTickConn::inner`,
   then applies shift+offset.
4. Filters out events whose final sample falls outside the buffer
   window (after shift+offset can push them into the next buffer's
   window — those re-emerge in the next call; idempotency is
   guaranteed because the master Tick range is recomputed each call).

agogo channel trace

| `sample_tick_round_trip` | `time::conn` | `floor(inner(t)) == t` for any `Tick t` in range |
| `sample_tick_monotonic` | `time::conn` | `s1 ≤ s2 ⇒ floor(s1) ≤ floor(s2)` |

### Spot checks

- `SampleTickConn { sr: 48_000, bpm: 120.0, ppqn: 192 }` produces
  `inner(Tick(192)) = 24_000` (one beat at 120 BPM is 0.5 s = 24 000

- `Channel { divider: TBase::T4, shuffle: SwingConfig::default(),
  shift_ms: 0.0, offset_ms: 0.0 }` at 120 BPM 48 kHz emits events

  stream that spans those Ticks.

## Review

### `#[ignore]`d properties

None introduced by this sprint. The pre-existing
`swing_zero_mean_over_beat` in `time/swing.rs` (Plan 02) stays
ignored; Plan 03's corresponding property is reformulated rather
than lifted verbatim (see below).

### Design deviations from this plan

1. **Verification table — `shuffle_zero_mean_per_beat` replaced.** The
   plan specifies "summed per-tick swing offsets over one beat = 0"
   for `channel::transform`. This cannot hold under Plan 01's
   Haskell-faithful one-sided swing semantics (off-beats subtract;
   on-beats pass through; summed offsets over a beat =
   `-2 × amount × multiplier`, non-zero in general — see
   `time/swing.rs` module doc). Replaced with
   `shuffle_identity_on_even_steps`: swing is the identity on
   even-parity T16 steps. This preserves the spirit — off-beat
   shifts are the only effect of the shuffle stage — without making
   a claim that is false under the existing semantics. Re-enabling
   the original property would require bidirectional swing
   (alternating ± on consecutive off-beats), which is an API change
   out of scope here.

2. **Verification table — `divider_rate_preservation` generalised to
   `div_ceil`.** The plan gives the closed form "divider = T8 emits
   exactly `2 × beats` ticks per beat." That formula is correct for
   dividers finer than a quarter note but breaks for T1 / T2 (tick
   counts 768 / 384 > 192 ticks per beat): a single T1 divider step
   covers four beats, so `192 / 768 = 0` under integer division
   undercounts the Tick(0) emission. The implementation asserts
   `events.len() == span.div_ceil(divider.tick_count())`, matching
   the plan's intent across the full `TBase` range.

3. **Scheduler signature — `&mut PhaseSource` parameter dropped.** The
   plan's `tick_stream` names `phase: &mut PhaseSource` as its first
   parameter, but the prose explicitly says the tick range is derived
   from `SampleTickConn::ceil/floor`, not from phase. The PLL is
   driven by the audio callback outside this function (Plan 05).
   Adding an unread parameter just to lock API shape is YAGNI;
   removing it keeps the tests simple. If Plan 04's MIDI-clock
   emission needs live phase, add the parameter then with a concrete
   use.

4. **`ChannelMode::MidiCc { cc, range }` uses `u8` instead of the
   spec's `u7`.** `agogo-core` has no MIDI-crate dependency that
   would provide a real `u7` newtype, and introducing one purely for
   this stub variant (which is not rendered in v0.1) would be
   premature. Values are documented as being in the MIDI `0..=127`
   range. If Plan 04 pulls in `midir`, a proper `u7` wrapper comes
   with it.

5. **CLI stays on `clap` (not `bpaf`).** The plan's T5 text said PR #2
   switched the CLI to `bpaf`; the actual PR #2 kept `clap` derive
   (search `62ad3c1` in the sync-trace subcommand — still
   `clap::Subcommand`). `channel trace` follows the existing clap
   pattern. `TBase` parsing is lowercase (`t4`, `t8t`) to match the
   sibling `time schedule` grammar.

### Recommendations for Plan 04 (`out/midi`)

- **MidiClock granularity vs `Channel.divider`.** MidiClock bytes
  fire at PPQN/24 = 8-tick spacing, but `Channel.divider` is a
  musical `TBase` (coarsest = T1 = 768 ticks). Plan 04 will need to
  reconcile: either a dedicated `TBase::Tmidi24` that lives below
  T128t in the lattice, or the MidiClock code ignores `divider` and
  walks the master tick stream at its own cadence. Settle this
  before writing the emitter.
- **Re-introduce `&mut PhaseSource` in `tick_stream` if needed.** If
  the MIDI-emission path wants real-time phase (e.g., to stamp
  sample-accurate timestamps), the parameter can return with a
  concrete consumer. Keep the current shape as the v0.1 default
  since nothing reads phase here yet.
- **Shift-negative ring buffer (§10 open question).** Plan 03 clamps
  `shift_ms` to `[0, 300]`. Plan 05's audio callback will likely
  want the negative-shift case too; spec the ring-buffer budget
  before Plan 06 locks the machine state shape.
