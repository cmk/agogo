# Plan 2026-05-03-04 - Declare MIDI output timing capability

## Goal

Make MIDI output timing truth explicit before broader v0.3 clock-domain
work. The current output path preserves `at_sample` through
`Playhead -> RtProducer -> drain`, but `MidirSink` sends immediately
because `midir` has no native scheduler. This sprint adds capability
metadata and diagnostics so agogo can distinguish best-effort MIDI from
future timestamped backends without changing the realtime render path.

## Tasks

### T1 - Timing capability metadata

Add a small MIDI timing capability API near the sink boundary:

- backend name,
- scheduling class,
- latency-compensation class,
- whether `at_sample` is honored or metadata-only.

`MidiSink::send_at` remains unchanged and non-fallible so the RT path
continues to enqueue and drain fixed payloads without error handling.

### T2 - Midir truthfulness

Implement `MidirSink` capability reporting as best-effort:

- immediate send through `midir`,
- `at_sample` is metadata-only,
- no native sample scheduling,
- no native latency compensation.

### T3 - Diagnostic sink

Add a diagnostic sink/wrapper for tests and tooling that records:

- intended `at_sample`,
- byte payloads,
- observed drain sample/time supplied by the caller,
- jitter/delay summaries computed outside the callback path.

The diagnostic helper must not make the production drain thread do
extra timing work by default.

### T4 - Documentation

Update v0.2/v0.3 notes to mark this as the first timestamped-output
step: truthfulness and diagnostics now, native CoreMIDI/JACK scheduling
later.

## Verification

| Property | Scope | Purpose |
|---|---|---|
| `midir_capability_is_best_effort` | host-midi | `MidirSink` reports immediate best-effort dispatch, metadata-only `at_sample`, and no native scheduling. |
| `rt_producer_preserves_at_sample` | host-cpal SPSC | SPSC messages keep intended sample indices and payloads in FIFO order. |
| `diagnostic_sink_records_intended_order` | core MIDI sink diagnostics | Diagnostic records preserve bytes and intended samples in call order. |
| `diagnostic_sink_reports_drain_delay` | core MIDI sink diagnostics | Synthetic delayed drain records observed delay outside the callback path. |
| `timing_capability_truthful` | current MIDI sinks/wrappers | Every current MIDI backend/wrapper reports a capability and none default to timestamped support. |
| existing callback/playhead scheduling tests | workspace | Existing callback and `Playhead` scheduling contracts still pass. |

## Deferred

- Native timestamped MIDI backends such as CoreMIDI or JACK.
- Backend-specific sample-to-host-time conversion and measured latency
  compensation.
