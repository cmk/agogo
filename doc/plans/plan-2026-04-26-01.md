# Plan 20 — Drop `Channel.snap_to_quantum` (audit P2)

## Context

Audit plan finding **J** (the structural-type audit): `Channel.snap_to_quantum:
Option<Quantum>` (`crates/core/src/channel/transform.rs:53`) is read **once** by
`LinkSession::arm_channel`, which folds it into `Channel.offset` and then
never touches it again. No other code path consumes the field. **And in
production it's even worse than that:** `arm_channel` itself is only called
from tests (the four inline tests in `crates/host-link/src/session.rs` plus
`crates/host-link/tests/bidirectional.rs:213`). `run.rs` doesn't wire the call
at all. So the field is purely arming-time intent stored as persistent
channel state, *never applied at runtime*.

15 `snap_to_quantum: None,` literals across the codebase confirm the
call-site overhead the field forces on construction sites that don't care.

This is **P2 of the structural-type audit**, the smallest pre-P3 cleanup.
P3 (sum-typed `Channel` + per-target role enums) reshapes `Channel` into
`ChannelCommon` + per-target variants — dragging a dead-but-pervasive field
through that reshape would be wasted churn.

## Goal

1. Remove the `snap_to_quantum` field from `Channel`. The 15 `None` literals
   collapse.
2. Retire `LinkSession::arm_channel(&mut Channel)`. Replace with
   `LinkSession::snap_offset_for(Option<Quantum>) -> Micro` — same Galois math,
   but the function takes the snap intent directly and returns the delta the
   caller applies.
3. Keep `ChannelSpec.snap_to_quantum_micro` and the `snap-quantum-us=N` parser
   key (back-compat for any user already specifying it). Expose a new
   `ChannelSpec::snap_intent() -> Option<Quantum>` accessor so the future
   orchestrator wiring (out of scope here) can call
   `session.snap_offset_for(spec.snap_intent())` at startup.
4. Drop `crates/host-link/src/session.rs`'s import of `agogo_core::channel::Channel`
   — the session crate no longer touches `Channel`.

## Tasks

### T1 — `crates/host-link/src/session.rs`: snap_offset_for + retire arm_channel

```rust
impl LinkSession {
    /// Compute the `Micro` delta required to snap the channel's next
    /// tick onto the nearest upcoming `q`-boundary on the Link timeline.
    /// Returns `Micro::ZERO` for `None` (no snap). Stateless: callers
    /// add the delta into their own `Channel.offset` if they want
    /// arming behaviour.
    pub fn snap_offset_for(&self, snap: Option<Quantum>) -> Micro {
        match snap {
            Some(q) => self.clock.snap_offset_micro(q),
            None => Micro::ZERO,
        }
    }
}
```

Remove `arm_channel(&mut Channel)` (line 175). Remove
`use agogo_core::channel::Channel` (line 7). Update the four inline
tests:
- `arm_channel_noop_when_snap_is_none` → `snap_offset_for_none_is_zero`
- `arm_channel_never_reduces_offset` → `snap_offset_for_never_negative_under_realistic_q`
  (re-expressed against the returned `Micro`, not `ch.offset` mutation)
- `arm_channel_is_near_idempotent` → idempotence is inherent to a
  pure function, so this test collapses to a single call check.

### T2 — `crates/core/src/machine/spec.rs`: snap_intent accessor

```rust
impl ChannelSpec {
    /// Parsed `snap-quantum-us=N` intent, if present. Returns
    /// `Option<Quantum>` for the orchestrator to feed into
    /// `LinkSession::snap_offset_for` at startup. The runtime `Channel`
    /// itself no longer carries this field (audit P2).
    pub fn snap_intent(&self) -> Option<Quantum> {
        self.snap_to_quantum_micro
            .map(|m| Quantum(Micro(m)))
    }
}
```

The existing `into_channel` line that populated `Channel.snap_to_quantum`
goes away.

### T3 — `crates/core/src/channel/transform.rs`: drop the field

### T5 — `crates/host-link/tests/bidirectional.rs`: update integration caller

Line 213: `agogo_session.arm_channel(&mut ch);` becomes:

```rust
let delta = agogo_session.snap_offset_for(snap_intent);
ch.offset = ch.offset.saturating_add_signed(delta.0);
```

Where `snap_intent` is the `Option<Quantum>` the test was using to
populate `ch.snap_to_quantum` previously. Net behaviour identical;
the test now exercises the new public API.

## Verification

### Properties (must pass)

| Property | Module | Invariant |
|----------|--------|-----------|
| `snap_offset_for_none_is_zero` | `host_link::session` | `session.snap_offset_for(None) == Micro::ZERO` for any session state. |
| `snap_offset_for_some_matches_clock` | `host_link::session` | `session.snap_offset_for(Some(q)) == session.clock.snap_offset_micro(q)` — pure delegation. |
| `snap_intent_round_trips_through_spec` | `core::machine::spec` | For any `i64`, `ChannelSpec` with `snap-quantum-us=N` parsed back yields `snap_intent() == Some(Quantum(Micro(N)))`. |

The pre-existing `quantum_snap_nonneg` and `quantum_snap_idempotent`
properties on `LinkClock::snap_offset_micro` already cover the
underlying numerical contract; the new tests above just confirm the
`LinkSession` wrapper delegates correctly.

## Out of scope

- **Wiring the orchestrator** (`run.rs`) to call `session.snap_offset_for(
  spec.snap_intent())` and apply the delta to `ch.offset`. This is the
  follow-up that makes `snap-quantum-us=N` actually do something in
  production. Not in this PR — the goal here is structural cleanup, not
  new behaviour.
- **Audit P3** (sum-typed `Channel` + per-target role enums). P2 lands
  the field deletion so P3's `ChannelCommon` doesn't carry the dead
  field; P3 is the next sprint.
- **Audit P0a/P0b** (Conn-discipline / float surface area): blocked on
  upstream `Conn::then`.
- **Audit P5** (host-link decoupling — the `q_f64` arithmetic
  re-isolation in `link.rs:201-214`). Same blocked-on-Conn::then story
  for the float math; the structural decoupling that's done here gets
  us most of the way.
