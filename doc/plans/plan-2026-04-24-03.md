# Plan 14 — `Playhead` + `agogo run` + `bin/agogo`

## Goal

Generalise Plan 13's single-channel demo into an N-channel `Playhead`
runner: `agogo run` accepts repeatable `--ch <spec>` channels,
dispatches across all six `SampleTime` rates, plugs `LinkSession` in
via `PhaseSource::Custom`, drives the v0.1 transport contract
(`Start` at launch, `Stop` on Ctrl-C, with Link-driven transitions
when `--source link`), and ships as the top-level `agogo` binary.

## Context

Plan 14 is the **last v0.1 sprint**. With Plan 12 (`out/midi`,
PR #14) and Plan 13 (`host-cpal` + `host-midi` + RT callback,
PR #15) merged, the remaining v0.1 todo is the third bullet of
`doc/versions/version-0.1.md:51`:

> `control/transport.rs` + `bin/agogo` — N-channel `Playhead`, top-level
> binary, end-to-end CLI run.

Plan 13 ships a single-channel `agogo demo run` that wires
`cpal input → CallbackState::on_buffer → tick_stream_into →
render_channel_block → RtProducer → drain → MidirSink`. Plan 14
generalises that pipeline to N channels, adds the user-facing
`agogo run` subcommand, and lands a top-level `agogo` binary entry.
After this plan the v0.1 acceptance scenario in
`doc/versions/version-0.1.md:82-91` is reachable end-to-end.

Plan 09 (`LinkSession`, transport FSM, `Channel::snap_to_quantum`)
is already on main (`crates/host-link/src/session.rs`,
`crates/host-link/src/transport.rs`,
`crates/core/src/channel/transform.rs:50`). `version-0.1.md`
listing it as in flight is stale; the status update is part of the
T7 docs commit. Plan 14 consumes `LinkSession` directly without
stubs.

## Design decisions

Settled with Chris before drafting:

1. **Channel spec language**: docker-style repeatable
   `--ch key=val,key=val,...`. Global `--bpm` applies to all
   channels; each `--ch` parses one channel into a `Channel` value.
2. **Sample rates**: all six (`S44`, `S48`, `S88`, `S96`, `S176`,
   `S192`). Static match in CLI dispatch.
3. **Link as `PhaseSource`**: `LinkSession` adapts into
   `PhaseSourceImpl`; `--source link` ships in this plan.
4. **Transport (non-Link)**: emit `MidiRtByte::Start` at first
   buffer, `MidiRtByte::Stop` on Ctrl-C with a flush before stream
   teardown. `--source link` reads `LinkSession::is_playing()` and
   emits on transitions.

## Architecture

```
                       ┌──────────────────────────┐
                       │      Playhead             │
                       │ ┌──────────────────────┐ │
                       │ │ channels: Vec<Ch>    │ │
                       │ │ phase_source: PS<R>  │ │
                       │ │ transport_state: TS  │ │  ← prev is_playing snapshot
                       │ │ events_pool: Vec<…>  │ │  ← reused per channel
                       │ │ stc: SampleTickConn  │ │
                       │ └──────────────────────┘ │
                       └──────────────────────────┘
                              │ on_buffer(io)
                              ▼
            ┌─────────────────────────────────────────┐
            │ 1. phase_source.feed_samples(input, n)  │
            │ 2. compute transport: Option<MidiRtByte>│
            │      (transition detect; Some(Start) on │
            │       first buffer if started)          │
            │ 3. for ch in channels:                  │
            │      events_pool.clear();               │
            │      tick_stream_into(...)              │
            │      render_channel_block(ch, events,   │
            │        transport, n, &producer)         │
            └─────────────────────────────────────────┘
```

`Playhead` replaces the bulk of Plan 13's `CallbackState`;
`CallbackState` shrinks to a thin wrapper holding `Playhead<R>` +
`RtProducer`.

### T0 — `agogo_core::control::transport` module

```rust
//! N-channel orchestrator. Owned by host-side runners (host-cpal's
//! callback, the integration tests). Stateless w.r.t. the host —
//! holds only musical + transport state.

pub struct Playhead<R: SampleTime> {
    pub channels: Vec<Channel>,
    pub phase_source: PhaseSource<R>,
    pub stc: SampleTickConn,
    pub transport: TransportState,
    events_pool: Vec<ScheduledEvent>,
}

/// Caller's transport policy. Plan 14 ships three:
///  - `Internal` — emit `Start` on first call to `on_buffer`,
///    `Stop` after `request_stop()`.
///  - `LinkDriven` — read `is_playing` from a callback set by the
///    host; emit `Start`/`Stop` on transitions.
///  - `Scripted` — test fixture: bytes deterministic per buffer.
pub enum TransportPolicy {
    Internal { start_emitted: bool },
    LinkDriven { prev_playing: bool, query: Box<dyn FnMut() -> bool + Send> },
    Scripted { schedule: VecDeque<Option<MidiRtByte>> },
}

pub struct TransportState {
    pub policy: TransportPolicy,
    /// Set by `request_stop()` (control-thread call). The next
    /// `on_buffer` emits `MidiRtByte::Stop` and flips `running` off.
    stop_requested: AtomicBool,
    running: bool,
}

impl<R: SampleTime> Playhead<R> {
    pub fn new(channels: Vec<Channel>, phase_source: PhaseSource<R>,
               sr: u32, bpm: Tempo, ppqn: u32,
               transport: TransportPolicy,
               buffer_frames: usize) -> Self;

    /// Buffer-driven dispatch. RT-safe: no allocations, no locks.
    /// `sink` is `&dyn MidiSink` so the callback's `RtProducer` and
    /// the test's `TestSink` both fit.
    pub fn on_buffer(&mut self, io: &mut AudioIo, sink: &dyn MidiSink);

    /// Control-thread API: signal that the next buffer should emit
    /// `MidiRtByte::Stop`. Idempotent; reads via `Acquire`.
    pub fn request_stop(&self);

    /// Pre-render verification helper exposed for tests + the CLI's
    /// alloc-free pre-flight check.
    pub fn max_events_per_buffer(&self) -> usize;
}
```

The `events_pool` is a single `Vec<ScheduledEvent>` reused across
channels — `tick_stream_into` writes the per-channel buffer, the
renderer consumes it, then the next channel `clear()`s and reuses.
Pool capacity = `max_events_for_buffer(buffer_frames)` from
`agogo_core::channel::scheduler` (moved from `host-cpal` so
`Playhead` can size itself without a host-cpal dep).

`request_stop()`'s `AtomicBool` is the **only** cross-thread
communication in `Playhead`. Control thread sets it via Ctrl-C
handler; audio thread reads with `Acquire` once per buffer.

### T1 — Channel-spec mini-language

File: `crates/core/src/channel/spec.rs` (new submodule).

```rust
/// One channel's parsed CLI form. Lossless: a `Channel` round-trips
/// only if no defaults were inserted.
#[derive(Debug, Clone)]
pub struct ChannelSpec {
    pub id: Option<String>,
    pub dev: ChannelDev,
    pub out: Option<String>,            // device-specific routing
    pub div: TBase,
    pub swing: i32,                     // SwingConfig::amount
    pub swing_mult: u32,                // SwingConfig::multiplier (default 1)
    pub shift_ms: f64,                  // argv boundary
    pub offset_ms: f64,                 // argv boundary
    pub snap_to_quantum_micro: Option<i64>,
}

pub enum ChannelDev { Midi, Audio }    // Audio is reserved for v0.4

#[derive(Debug, thiserror::Error)]
pub enum ChannelSpecError {
    #[error("channel spec: unknown key `{0}`")]            UnknownKey(String),
    #[error("channel spec: missing `{0}`")]                MissingKey(&'static str),
    #[error("channel spec: bad value for `{0}`: {1}")]     BadValue(&'static str, String),
    #[error("channel spec: dev=audio requires v0.4 (out/audio)")]
    AudioDeferred,
}

impl ChannelSpec {
    pub fn parse(s: &str) -> Result<Self, ChannelSpecError>;
    pub fn into_channel(self) -> Result<Channel, ChannelSpecError>;
}
```

Grammar: `key=val[,key=val]*`. Whitespace tolerated; `=` and `,`
separate; values may be quoted `"..."` to embed spaces or commas.
Required keys: `div`, `dev`. Optional keys: `id`, `out`, `swing`,
`swing-mult`, `shift-ms`, `offset-ms`, `snap-quantum-us`. Unknown
keys are hard errors so typos are caught.

`f64` fields carry `// argv boundary` and convert at handler entry
via the existing `F64F06` Conn (per CLAUDE.md float exception 4).
The parser itself is pure-string and float-free; only `into_channel`
performs the boundary cast.

`dev=audio` is a hard error in v0.1 (`AudioDeferred`) — the surface
is reserved for v0.4. We don't silently no-op because the user
expects something to happen.

### T2 — `LinkSession` as `PhaseSourceImpl`

File: `crates/host-link/src/source.rs` (new) + `lib.rs` wire-up.

```rust
/// Adapter: presents `LinkSession` as the trait object Plan 04's
/// `PhaseSource::Custom(...)` consumes. Owns the session inside an
/// `Arc<Mutex<_>>` so the audio callback can borrow it for
/// `phase_at_sample` while the control thread polls transport.
pub struct LinkPhaseSource {
    inner: Arc<Mutex<LinkSession>>,
}

impl LinkPhaseSource {
    pub fn new(session: LinkSession) -> (Self, LinkSessionHandle);
    pub fn handle(&self) -> LinkSessionHandle;
}

impl PhaseSourceImpl for LinkPhaseSource {
    fn phase_at_sample(&mut self, n: u64) -> Phase {
        // Lock is uncontended on the audio thread because the control
        // thread only writes to the session at human-pace boundaries
        // (Ctrl-C, --push-tempo). If contention shows up in profiling,
        // swap to a seqlock pattern in v0.5.
        self.inner.lock().unwrap().clock.phase_at_sample(n)
    }
    fn feed_samples(&mut self, _: &[f32], _: u64) { /* no PCM input */ }
}

pub struct LinkSessionHandle {
    inner: Arc<Mutex<LinkSession>>,
}

impl LinkSessionHandle {
    pub fn is_playing(&self) -> bool;
    pub fn poll_transport(&self);
    pub fn user_start(&self);
    pub fn user_stop(&self);
    pub fn set_tempo(&self, bpm: Tempo);
}
```

A `Mutex` here is acceptable because (a) `LinkSession` already
wraps its internals in interior mutability and is not `Sync`,
(b) the audio thread takes the lock at most once per buffer for a
sub-µs read, (c) the control thread's writes are at human pace.
The seqlock upgrade is v0.5 Sprint 02 per `link.md:23-29`. A
proptest pins the contention bound (T7).

### T4 — Ctrl-C handler

Files:
- `crates/cli/Cargo.toml` — add `ctrlc = "3"` (small, MIT, no
  `signal-hook`/`tokio` baggage; cross-platform).
- `crates/cli/src/run.rs` — wire it inside the `agogo run` handler.

```rust
let stop_flag = Arc::new(AtomicBool::new(false));
let machine_handle = machine_stop_handle.clone();      // Arc<PlayheadStopHandle>
let link_handle: Option<LinkSessionHandle> = link.as_ref().map(|s| s.handle());

ctrlc::set_handler({
    let stop_flag = Arc::clone(&stop_flag);
    let machine_handle = machine_handle.clone();
    let link_handle = link_handle.clone();
    move || {
        machine_handle.request_stop();              // emits Stop next buffer
        if let Some(h) = &link_handle { h.user_stop(); }
        stop_flag.store(true, Ordering::Release);   // breaks main loop
    }
}).expect("ctrlc handler installed once");

while !stop_flag.load(Ordering::Acquire) {
    std::thread::park_timeout(Duration::from_millis(100));
    if let Some(h) = &link_handle { h.poll_transport(); }
}

// Tear down: drop audio Handle (stops cpal stream), then drop drain
// (flushes ring + joins thread). Order is exact — see Plan 13's
// drop comment in control.rs:179-189.
```

### T5 — `agogo run` subcommand

File: `crates/cli/src/main.rs` (extend the existing `Command`
enum) + `crates/cli/src/run.rs` (new module for the handler body).

bpaf parser:

```
agogo run
    --bpm <f64>                    # global tempo, all channels share
    --sr <u32>                     # 44100 / 48000 / 88200 / 96000 / 176400 / 192000
    --buffer-frames <u32>          # default 1024
    --source <internal|external|link>
    --audio-in <device>            # cpal input ("default" allowed)
    --ch <spec>                    # repeatable; at least one required
    [--audio-out-channels <u16>]   # reserved for v0.4
    [--link-quantum <f64>]         # required when --source link
    [--link-enable-start-stop]     # mirrors LinkWriteConfig
    [--max-duration-ms <u32>]      # hidden test-only flag
```

Handler flow:

1. Parse argv. Bpaf `many()` collects `--ch` into `Vec<String>`;
   the handler's first line maps each via `ChannelSpec::parse` →
   `ChannelSpec::into_channel`. `f64`s on `--bpm` /
   `--link-quantum` die immediately at the `// argv boundary` —
   `F64TMP::ceil(...)`, `F64F06::ceil(...)`.
2. Build `PhaseSource<R>` based on `--source`:
   - `internal` → `PhaseSource::Internal { bpm }`
   - `external` → `PhaseSource::External { detector, pll }` (Plan
     02 default tunings)
   - `link` → construct `LinkSession` with the parsed
     `LinkWriteConfig`, wrap in `LinkPhaseSource`, take a
     `LinkSessionHandle` for the control thread, place the source
     in `PhaseSource::Custom(Box::new(...))`.
3. `match args.sr` → `S44 | S48 | S88 | S96 | S176 | S192`. Each
   arm calls a generic `run::<R>(...)` helper. This is the single
   point where rate dispatch happens; everything downstream is
   monomorphic.
4. `let (producer, consumer) = host_cpal::cpal::control::spsc(1024);`
5. Build `MidirSink` from the first `--ch` entry that has
   `dev=midi`. v0.1 supports one MIDI port shared across channels;
   multi-port is in §Deferred.
6. `let drain = consumer.spawn_drain(Arc::new(midir_sink));`
7. Build `Playhead` with the parsed channels, the chosen
   `PhaseSource`, and the right `TransportPolicy`:
   - `--source link` → `TransportPolicy::LinkDriven { prev_playing: false, query: Box::new(move || link_handle.is_playing()) }`
   - else → `TransportPolicy::Internal { start_emitted: false }`
8. `let cb_state = CallbackState::<R> { machine, producer };`
9. `let stream = CpalHost::with_input_name(audio_in)?.run(cfg, Box::new(move |io| cb_state.on_buffer(io)))?;`
10. Install Ctrl-C handler (T4), park the main thread until
    `stop_flag` flips, drop `stream`, drop `drain`, exit 0.

### Outcome

Six commits on top of the sprint-opener — T0+T1, T2, T3,
T4+T5+T6, T7, plus this docs commit. Workspace test count goes
from 234 → 255: +15 in `agogo_core::control::transport` (8 spec + 7
machine), +1 in `host-cpal` (the existing
`callback_emits_expected_clock_schedule` re-pinned against
the Playhead-backed callback), +1 in `host-link` source, +4 in
the CLI `run` smoke tests. Clippy clean across workspace +
host-cpal + host-midi + host-link (all features).
`scripts/check-floats.sh` clean; allowlist gains four entries
(control/transport.rs, channel/spec.rs, host-link/source.rs, cli/run.rs)
documented in CLAUDE.md.

### Design deviations from the plan

1. **`LinkSession::phase_at_sample` shim added.** Plan called
   `inner.lock().clock.phase_at_sample(n)` directly; the
   `clock` field is private, so a thin pub method on
   `LinkSession` delegates. One-liner; preserves encapsulation.
2. **`PlayheadStopHandle::is_stop_requested` added** as a
   test-observability accessor. Plan only specified
   `request_stop`; the proptest for `transport_internal_emits
   _start_then_stop` benefits from being able to assert
   `!machine.is_running()` post-Stop.
3. **`Playhead::is_running` added** as a `#[doc(hidden)]`
   test-only accessor for the same proptest.
4. **`run = ["demo", "link", "dep:ctrlc"]` feature** added
   alongside the existing `core / cpal / midi / link / demo`
   features. The plan implied `--features cpal midi link`; a
   single composite feature is one explicit name to remember.
5. **`bin/agogo` lives alongside `bin/agogo-cli` for one
   release** as a transitional alias. v0.2 removes
   `agogo-cli`. Cargo emits a "multiple build targets" warning
   for the shared `main.rs` — expected, not load-bearing.
6. **`PULSE_PPQ = 24` named in `run.rs`** instead of reusing
   the demo's `DEMO_PPQ` constant (private to the demo
   module). Same value, separate definition; harmonising is a
   refactor for v0.2.
7. **No `--audio-out-channels` flag.** Plan listed it as
   reserved for v0.4. Bpaf doesn't tolerate "exists but does
   nothing" cleanly without test surface; removed. v0.4 adds
   it when CV output materialises.

### `#[ignore]`d properties

None. Every Verification-table property landed green without

### Verification-table property deferred

**`run_help_lists_all_six_rates`** (Verification table, line in
the property list) is replaced by the four `run::tests` smoke
tests that hit the dispatch arms directly:

- `run_rejects_unsupported_rate` — confirms `--sr 22050` errors
  with the allowlist enumerated (44100, 48000, 88200, 96000,
  176400, 192000) in the message body.
- The successful-dispatch arms for all six rates are exercised
  whenever the source file compiles — `run_with_rate::<R>` is
  monomorphised six ways at the `match args.sr` site, so type
  errors in any one rate's pipeline break the build.

Asserting the literal `--help` output text would require either
launching the binary as a subprocess (slow, fragile across bpaf
upgrades) or reading bpaf's internal help-table representation
(unstable). Since the smoke test already enumerates all six
rates in its error-message assertion and the per-rate compile
gate covers the other direction, the named-help-text property
is redundant.
