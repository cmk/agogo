# Plan 2026-05-03-06 - Draw the chan/core/host boundary

## Goal

Make the crate boundary semantic instead of historical:

- `agogo-chan` is the pure music/channel/control-loop library.
- `agogo-core` is the agogo-owned runtime orchestration crate.
- `host-*` crates are concrete external backend adapters.

The rename is intentionally coupled with the module moves that make the new
names true. Old `core::control::transport` and `core::control::event` are
runtime orchestration and move to the new `agogo-core`. Old
`core::control::sync` is pure DSP/control-loop logic and flattens into
`agogo-chan::control`.

## T1 - Rename crates and dependency graph

Problem or motivation: `agogo-core` currently contains both pure domain logic
and runtime-like playhead orchestration, while `agogo-host` contains more
runtime bridge code. The crate names obscure the actual dependency direction.

Solution:

- Rename old `crates/core` to `crates/chan`.
- Rename package `agogo-core` to `agogo-chan`.
- Rename old `crates/host` to `crates/core`.
- Rename package `agogo-host` to `agogo-core`.
- Update workspace members, workspace dependencies, package aliases, docs,
  tests, and imports.
- Preserve the public top-level `agogo` compatibility crate as the consumer
  facade over the renamed crates.

The intended crate graph is:

```text
agogo-chan  (pure)
    ^
    |
agogo-core  (runtime orchestration)
    ^
    |
host-* / cli / facade crates as needed
```

`agogo-chan` must not depend on `agogo-core` or any `host-*` crate.

## T2 - Move runtime event and transport into `agogo-core`

Problem or motivation: `control/event.rs` and `control/transport.rs` are not
the same kind of thing as PLL, peak detection, or phase-source math. They know
about buffer windows, playhead state, transport bytes, stop flags, and runtime
orchestration.

Solution:

- Move old `crates/core/src/control/event.rs` to
  `crates/core/src/event.rs` in the new `agogo-core`.
- Move old `crates/core/src/control/transport.rs` to
  `crates/core/src/transport.rs` in the new `agogo-core`.
- Update imports so these modules consume pure types from `agogo-chan`.
- Keep behavior unchanged: scheduling, event emission, MIDI/audio rendering,
  and transport command application should remain byte-for-byte semantic
  equivalents except for module paths.

## T3 - Flatten pure control-loop modules into `agogo-chan::control`

Problem or motivation: `control::sync` is an extra noun that makes the pure
control loop look like a runtime subsystem. The new `agogo-chan::control`
should mean pure DSP/control-loop logic.

Solution:

- Move old `control/sync/{detect,pll,pulse,source}.rs` up to
  `control/{detect,pll,pulse,source}.rs`.
- Delete the `control::sync` module layer.
- Update re-exports and downstream imports from `control::*` to
  `control::*` or the direct submodules.
- Keep `PhaseSource`, `Pll`, `PeakDetector`, and the pulse generator pure:
  no runtime queues, atomics, host callbacks, driver state, or transport-byte
  policy in `agogo-chan::control`.

## T4 - Proposed new `agogo-core` module tree

The new runtime crate should converge on:

```text
crates/core/src/
  lib.rs
  bridge.rs
  driver.rs
  snapshot.rs
  event.rs
  transport.rs
  runtime.rs      # only if shared runtime glue becomes useful
  command.rs      # only if bridge.rs needs a later split
```

Responsibilities:

- `event`: per-buffer event scheduling orchestration over `agogo-chan` pure
  scheduling primitives.
- `transport`: `Playhead`, transport policy, stop handle, command staging, and
  runtime state that is driven by host callbacks.
- `bridge`: async/control-thread to RT-thread command admission and delivery.
- `driver`: soft-side tool/driver API.
- `snapshot`: runtime snapshot publication and observation state.

## T5 - Standardize `host-*` crate shape

Problem or motivation: backend crates should look similar and should not
silently grow agogo runtime policy.

Solution: document and begin aligning host crates around this optional module
shape:

```text
crates/host-foo/src/
  lib.rs
  backend.rs      # concrete external API adapter, or existing API name
  config.rs       # backend-local config parsing/validation
  error.rs        # backend-local errors
  source.rs       # backend input clock/source adapter
  sink.rs         # backend output sink adapter
  session.rs      # external lifecycle object
  transport.rs    # only for backend-native transport semantics
```

Rules:

- `host-*` crates adapt external APIs into `agogo-core` / `agogo-chan` types.
- `host-*` crates must not define agogo runtime policy.
- A `host-*::transport` module is allowed only for backend-native transport
  semantics, such as Ableton Link transport. It must not duplicate
  `agogo-core::transport`.

This sprint should avoid large backend rewrites; it should add the convention
and make only the path/import changes required by the crate rename.

## T6 - Enforce `check-layers.sh` everywhere

Problem or motivation: the layer gate currently hardcodes
`crates/core/src` and the old six-layer pure crate. After the rename, that
would leave the new runtime crate and host adapter crates outside the import
discipline.

Solution:

- Generalize `scripts/check-layers.sh` so it can enforce multiple crate/module
  layer sets.
- Keep `agogo-chan`'s existing pure partial order:

```text
control  -> sink, channel, time, conn
sink     -> channel, time, conn
channel  -> time, conn
time     -> conn
conn     -> leaf
test     -> leaf
```

- Add an `agogo-core` runtime partial order:

```text
driver    -> bridge, snapshot, transport, event
bridge    -> transport, event, snapshot
transport -> event
event     -> leaf
snapshot  -> leaf
```

- Add minimal host-adapter orders for every `host-*` crate that has module
  roots in this repo. Backend crates with a single backend module may start
  with only the modules they actually have; do not invent empty modules just
  to satisfy a diagram.
- Update `AGENTS.md` so the prose and script agree.

## Deferred

- Deep backend-module reshuffles beyond what is needed for imports and
  documented conventions.
- New runtime helper APIs unrelated to the rename and module ownership move.
- Renaming public user-facing CLI subcommands or JSON fields.
- Renaming detached backend crates (`agogo-host-cpal`, `agogo-host-link`,
  `agogo-host-midi`). They remain backend adapters and already match the
  `host-*` convention.

## Review

- `crates/chan/src/channel.rs` still said the scheduler lived at
  `crate::control::event`; fixed inline when `event` moved to the new
  `agogo-core` runtime crate.
- `channel::time::micro_to_samples` became public so the new runtime crate can
  share the same visible `FD12FD06.inner -> pico_to_samples` composition
  instead of duplicating scheduling arithmetic across the crate boundary.
