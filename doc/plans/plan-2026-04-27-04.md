# Plan 27 — Q3: Float surface-area sweep (audit findings K + L)

## Goal

Eliminate the last public-surface `f64` storage positions: argv
fields on `RunArgs` and the `delay_ms` field on `ChannelSpec`.

across the parser → into_channel boundary.

This is the **final** PR of the four-PR Conn-discipline + float-

### T3 — `ChannelSpec.delay_ms: f64 → delay: Micro`

`crates/core/src/machine/spec.rs`:

```rust
// Field
pub delay: Micro,           // was: pub delay_ms: f64

// Parser body (line ~272)
"delay" => {
    let ms_f64 = v.parse::<f64>().map_err(...)?;  // dies on next line
    delay = Some(micro_from_ms(ms_f64).ok_or_else(|| {
        ParseError::BadValue(format!("delay {ms_f64} out of range"))
    })?);
}

// into_channel (line ~388)
let delay = self.delay;       // already Micro; drop the micro_from_ms call

// Display (line ~572)
if self.delay != Micro::ZERO {
    // Print as ms (decimal) for human readability + parser round-trip.
    // Sub-µs precision was already lost through F064FD06.ceil — nothing
    // changes semantically. Format choice: integer µs / 1000 → ms,
    // suppressing trailing zeros.
    let ms = self.delay.0 / 1_000;
    let frac = (self.delay.0 % 1_000).unsigned_abs();
    if frac == 0 {
        write!(f, ",delay={ms}")?;
    } else {
        write!(f, ",delay={ms}.{frac:03}")?;
    }
}

// arb_spec (line ~984)
(0u32..=300).prop_map(|n| Micro(n as i64 * 1_000)),
```

The Display rewrite preserves round-trip: the parser still accepts
the same `delay=10.5` user-typed input; the printed form is the
same shape. The `arb_spec` strategy now generates `Micro(n × 10³)`
values (0-300 ms in µs), matching the previous `n` values' set.

### T4 — Tighten `tempo_to_f64_bpm` / `pico_to_f64_seconds` Bot/Top arms

`crates/core/src/fxp.rs:325-336, :340-348`:

```rust
pub fn tempo_to_f64_bpm(t: Tempo) -> f64 {
    let widened = I064U032.inner(t.0);
    match F064FD06.inner(Extended::Finite(FD06(widened))) {
        ExtendedFloat::Extend(b) => b,
        // I064U032.inner of any u32 is a finite i64; F064FD06.inner
        // of Extended::Finite(...) is always Extend(_), never
        // Bot/Top. The lift-failure arms are unreachable by
        // construction; if upstream Conn contracts change to make
        // them reachable, fail loudly rather than propagate ±∞.
        ExtendedFloat::Bot | ExtendedFloat::Top => {
            unreachable!("F064FD06.inner of Extended::Finite cannot lift to Bot/Top")
        }
    }
}

pub fn pico_to_f64_seconds(p: Pico) -> f64 {
    match F064FD12.inner(Extended::Finite(p)) {
        ExtendedFloat::Extend(s) => s,
        ExtendedFloat::Bot | ExtendedFloat::Top => {
            unreachable!("F064FD12.inner of Extended::Finite cannot lift to Bot/Top")
        }
    }
}
```

The proptests added in Q2 (`tempo_to_f64_bpm_full_domain`,
`pico_to_f64_seconds_full_domain`) prove the unreachable assertion
holds across the full input domain — they'd panic loudly rather
than silently fail if upstream invariants drift.

## Review

### Implementation deviations

- **Integer-ms exact-parse path** added to `ChannelSpec`'s
  `delay` parser (T3). `micro_from_ms(51.0)` ceils to 51_001 µs
  rather than 51_000 because the f64 representation of `0.051`
  overshoots `51_000 / 10⁶` by ~5e-12, and `F064FD06.ceil`
  faithfully rounds the overshoot up. The `spec_round_trip`
  proptest caught this at the 51 ms shrink; the saved regression
  seed at `delay: FD06(51000)` is now committed as a permanent
  gate. Fix: parser tries `i64`-ms parse first (exact), falls
  back to f64 + `micro_from_ms` only for fractional inputs like
  `delay=10.5`. The user-facing surface is unchanged.

- **bpaf parsers live in `mod run`, not `main.rs`.** I initially
  put `parse_bpm_to_tempo` and `parse_quantum_from_beats` at
  main.rs's top level (`pub(crate) fn`) so future subcommands
  could reuse them. But they're only consumed by `RunArgs` (which
  is feature-gated behind `--features run`), so cargo flagged
  them as `dead_code` for the default-feature build. Moved into
  `mod run` (which is itself `#[cfg(feature = "run")]`) so the
  visibility tracks the use-site exactly.

- **Three subcommand `*Args` structs left at `bpm: f64`.**
  `channel_trace::TraceArgs`, `midi_trace::TraceArgs`, and
  `demo::DemoArgs` each still expose `bpm: f64`. Migrating
  them was out of audit L's scope (which named only `RunArgs`),
  and doing it would have forced parallel migrations of the four
  bpaf-derived subcommand enums (`SyncSub::Trace`,
  `ChannelSub::Trace`, `MidiSub::Trace`, `DemoSub::*`) plus
  their inner-module function signatures — a separate sprint's
  worth of mechanical work. The transitional `parse_cli_bpm`
  helper introduced in Q2 stays in main.rs to serve them.

### `#[ignore]`d properties

None added. The two existing `#[ignore]`s
(`time::swing::tests::swing_is_bar_periodic` + one other)
predate this PR.
