# Plan 2026-05-02-03 — Facade docs polish

## Goal

Tighten the `agogo` facade crate's Rustdoc feature metadata after
external namespace-design feedback, without expanding the public API.

## Dependency Graph

```
T1 docs.rs facade metadata
    |
    v
T2 docs and verification
```

## Tasks

### T1 — docs.rs facade metadata

**Problem.** The facade modules are feature-gated in code, but Rustdoc
does not currently advertise the feature gates when docs are built with
the docs.rs configuration.

**Solution.** Add `doc_cfg` annotations for the gated facade modules
under a `docsrs` cfg and configure the `agogo` package's docs.rs
metadata to build the pure-Rust `core,host` facade documentation. Keep
the backend annotations in place for local or dedicated docs builds that
explicitly opt into those system-dependent backend features.

**Types or API surface.** No runtime API change. The visible Rustdoc
surface gains feature badges for modules included in a selected docs
feature set, including `agogo::core`, `agogo::host`, and the optional
backend namespaces when those backend features are explicitly enabled.

### T2 — docs and verification

**Problem.** The feedback also raised the possibility of a facade
prelude, but adding one now would freeze a convenience import set before
the public surface has settled.

**Solution.** Keep `agogo::prelude` deferred and document that choice in
this plan. Run the facade feature matrix, add a CI docs job for the
docs.rs-style `core,host` rustdoc path, and validate that command
locally with nightly.
