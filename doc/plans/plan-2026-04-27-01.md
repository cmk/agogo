# Plan 24 — Q1a: Vendor decimal/sample types + bump connections rev

## Goal

Vendor `decimal.rs` and `sample.rs` from `doc/notes/` into
`crates/core/src/time/`, bump the `connections` rev to current
`origin/main` HEAD (`6c88862`), and stand up backward-compat
aliases at `agogo_core::fxp` so every existing call site
continues to compile unchanged. **No behaviour change. No
workspace-wide rename. No Conn-discipline fixes yet.**

This is step Q1a of a four-PR sequence executing audit P0a + P0b
(documented in the Plan Mode meta-plan kept outside this repo;
the per-PR sprint plans here are the canonical execution
artifacts). The sequence:

- **Q1a (this plan)** — vendor + rev bump + aliases.
- Q1b — workspace-wide rename `Uni..Pico → FD00..FD12`,
  `S44..S96 → S044..S096`.
- Q2 — Conn-discipline sweep (audit findings M + N — open-coded
  unit arithmetic and lossy `as` casts).
- Q3 — float surface-area sweep (audit findings K + L —
  `ChannelSpec.delay_ms`, `RunArgs.{bpm, link_quantum}`).

- `conn::sample` was deleted (publish-prep T10).
- `conn::std::i64::decimal::FD00..FD12` was added then removed
  on `sprint/remove-decimal` (commit `6c88862`), now merged to
  main. CHANGELOG: *"Domain-specific numeric ladders belong in

  `conn::std::{i8..u128}` per-primitive reorganization (45 new
  Conns), `F064DURN`/`F032DURN` float↔Duration bridges.

Two complete drop-in modules have been staged in agogo's
gitignored `doc/notes/`:

- `doc/notes/sample.rs` (25.9 KB) — `Q48_16` alias, `SampleRate`
  trait, six rate newtypes `S044..S192`, 15 rate↔rate `Conn`s, 6
  `FD12↔Sxxx` pico→sample bridges. Full Galois law battery.
- `doc/notes/decimal.rs` (29.1 KB) — `FD00..FD12` decimal SI
  rungs, 21 intra-decimal `Conn`s, 7 `F064FD??` float→fixed
  bridges. Full Galois law battery.

Both files use the **new 4-character naming** (`FD06` not
`Micro`, `S048` not `S48`). The atomic workspace rename happens
in **Q1b**, not this PR — Q1a only adds the new types and
aliases the old names so call sites keep working.

  - `fixed_fine(prec: i64)` — `i64` strategy biased to multiples

  - `fixed_safe_fine(prec: i64)` — same as `fixed_fine` but

  - `extended_fd00 .. extended_fd12` — seven `Extended<FDxx>`

  - `pico_fine()` — FD12 i64 picosecond bits.
  - `pico_coarse(num: i128, den: i128)` — Sxxx-side i64 bits

  - `pico_safe(num: i128)` — closure-law variant.

### T5 — Rewire `SampleTime` trait blanket impls

`crates/core/src/fxp.rs:46-81` defines an agogo-local `SampleTime`
trait (uniform `from_bits_q48_16`/`to_bits_q48_16`/`sample`/
`from_sample` API) implemented for each rate via a macro.

The staged `sample.rs` defines `from_bits` / `to_bits` /
`from_sample` / `sample` as **inherent methods** on each rate
newtype. The agogo `SampleTime` trait survives — five generic
call sites (`arb::pulse_train`, `Machine<R>`, `Pll<R>`,
`PhaseSource<R>`, `PeakDetector<R>`) depend on it — but each
blanket impl now delegates to the inherent methods:

```rust
macro_rules! impl_sample_time {
    ($Rate:ident) => {
        impl SampleTime for $Rate {
            fn from_bits_q48_16(bits: i64) -> Self {
                <$Rate>::from_bits(bits)
            }
            fn to_bits_q48_16(self) -> i64 {
                self.to_bits()
            }
        }
    };
}

impl_sample_time!(S088);
```

(The macro body is identical; only the rate-name argument

## Deferred

Nothing intentionally deferred for Q1a beyond what's already
sequenced into Q1b (rename), Q2 (Conn-discipline sweep), and
Q3 (float surface area).

Two upstream-removal collateral migrations were folded *into*
this PR rather than deferred to follow-ups, because the rev
bump can't land without them:

- **`Ple` trait migration.** Connections deleted `lattice::Ple`
  in commit `9aa426b` (the lawful framework now uses standard
  `Eq + PartialOrd` directly). Agogo has 73 `.ple(&x)` call
  sites, including `Grid`'s load-bearing **divisibility
  preorder** which is *not* the natural order on its component
  fields. Replacing those with `<=` would either lose the
  semantic distinction or require a wrapper-newtype-per-
  comparison shim. Solution: vendor a one-method `Ple` trait
  locally in `crates/core/src/preorder.rs` and re-route all 73
  imports there. This keeps the call-site syntax unchanged and
  preserves the `Grid` divisibility semantics.

- **`ExtendedFloat::Finite` → `ExtendedFloat::Extend` rename.**
  Six call sites (`spec.rs`, `link.rs`, `cli/main.rs` ×2,
  plus the one already fixed by P5 at `link.rs:211`) updated
  in lockstep with the rev bump.

## Review

### Implementation deviations from the plan

- **`Ple` trait was added to the migration scope** (not in the
  original Q1a plan). Cause: the upstream rev bump deleted the
  trait, leaving 73 call sites broken. Fixing them was strictly
  necessary to land the rev bump in this PR. Documented above
  under Deferred so the rationale is preserved.

- **`ExtendedFloat::Finite` → `ExtendedFloat::Extend` rename**
  added to scope for the same reason — six broken call sites
  blocked the rev bump.

- **`channel/{role,scheduler,transform}.rs` import re-routing**
  through `crate::fxp::{Micro, Pico}` instead of the deleted
  `connections::conn::fixed::*` paths. Mechanical; not in the
  original plan because the original audit assumed the FXP
  re-exports would still resolve through connections.

- **`scripts/check-floats.sh` allowlist** updated to include
  `crates/core/src/time/{decimal,sample}.rs`. The
  `F064FD?? float_conn!` macro body (decimal.rs:160-272) is
  intrinsically f64-internal — it walks the f64-mantissa
  precision plateau to make ceil/floor exact. The same files
  were upstream-allowlisted for the same reason; the file
  move downstream brings the allowlist entry with it.
