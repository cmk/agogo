# Plan 2026-04-30-02 — agogo snapshot observation

## Goal

Land agogo's v0.4 observation seam: define the real
`AgogoSnapshot` v1 schema and publish decimated snapshots through
stdio-core's `agogo-state` observation contract without doing
serialization or dispatch work on the RT thread.

## Dependency Graph

```
T1 AgogoSnapshot schema + strategies
    |
    v
T2 wait-free RT snapshot writer
    |
    v
T3 stdio-core ObservationParams publisher
    |
    v
T4 drop/seq integration tests
    |
    v
T5 docs/schema alignment
```

## Tasks

### T1 — `AgogoSnapshot` v1 schema

**Problem.** v0.4 needs one snapshot type shared by the standalone TUI
and the stdio-core adapter, rather than ad-hoc JSON produced only at
the stdio boundary.

**Solution.** Add an `AgogoSnapshot` type with serde support and a
schema marker:

```json
{
  "schema": "agogo.snapshot.v1",
  "seq": 42,
  "bpm": 120.0,
  "transport": {},
  "sync": {},
  "audio": {},
  "channels": []
}
```

Use typed nested structs for transport, sync, audio, and channel
state. Generated snapshots must keep `channels[*].index` unique and
stable within a snapshot.

### T2 — wait-free RT snapshot writer

**Problem.** The callback can produce human-rate telemetry, but it
must not serialize JSON, call stdio-core, block, or allocate.

**Solution.** Add a wait-free or lock-free snapshot slot. The RT
callback writes compact typed state and increments `seq`; a background
task polls the slot at about 30 Hz. Snapshot writes use only fixed
storage and atomics or a proven wait-free handoff primitive.

### T3 — stdio-core publisher

**Problem.** stdio-core Plan 11 fixes the agogo observation wire
contract; agogo must satisfy that exact contract.

**Solution.** In `agogo-stdio`, serialize snapshots off the RT thread
and publish `ObservationParams` with:

- `FormType::Other("agogo-state")`;
- `stream_id = "agogo.main"`;
- `form_id = "agogo.main"`;
- initial `Create`;
- full-snapshot `Patch` payloads for v1;
- optional `Destroy` on unmount.

Do not add a typed `FormType` variant and do not introduce JSON Patch
diffs in this sprint.

### T4 — seq/drop behavior tests

**Problem.** stdio-core may drop newest observation frames under
pressure. For telemetry this is acceptable only if consumers can
detect gaps and continue parsing later snapshots.

**Solution.** Test the publisher against stdio-core's
`ObservationDispatcher` with forced subscriber lag. Assert delivered
snapshots stay parseable and missing frames are visible as `seq` gaps.

### T5 — schema docs

**Problem.** The snapshot contract is shared by agogo, stdio-core,
and the future renderer.

**Solution.** Add `doc/designs/snapshot.md` with the v1 schema,
cadence, drop policy, and audio-rate event boundary. Keep
`doc/versions/version-0.4.md` aligned with
`../stdio-core/doc/designs/agogo.md` and stdio-core Plan 11. Do not
add absolute local paths or user-home paths.

## Verification

### Properties (must pass)

| Property | Module | Invariant |
|----------|--------|-----------|
| `snapshot_schema_round_trips` | `agogo_stdio::snapshot` | Arbitrary `AgogoSnapshot` values serialize to JSON and deserialize without loss. |
| `seq_monotonic_under_decimation` | `agogo_stdio::snapshot::push` | Published `seq` values are strictly monotonic per `stream_id`. |
| `rt_push_has_no_alloc` | `agogo_stdio::snapshot::push` | The RT snapshot-write path allocates zero bytes; serialization and dispatch happen off-thread. |
| `agogo_snapshot_drop_is_detectable` | `agogo_stdio::snapshot::push` | Forced observation backpressure creates detectable `seq` gaps without corrupting later snapshots. |
| `snapshot_channel_indices_unique` | `agogo_stdio::snapshot` | Generated snapshots never contain duplicate channel indices. |

### Spot checks

| Test | Assertion |
|------|-----------|
| `create_uses_agogo_state_form_type` | Initial create uses `FormType::Other("agogo-state")`. |
| `background_stream_uses_stable_ids` | `stream_id` and `form_id` are both `agogo.main`. |
| `patch_carries_full_snapshot_v1` | Patch payload contains `schema`, `transport`, `sync`, `audio`, and `channels`. |
| `unmount_publishes_destroy` | Graceful unmount publishes a destroy or otherwise terminates the background publisher cleanly. |

## Deferred

- JSON Patch diffs: full snapshots are the v1 wire contract.
- TUI renderer implementation: stdio-core owns renderer registration;
  this sprint publishes the data.
- CV pulse output hardening beyond snapshot visibility: stays with the
  v0.4 CV-output sprint.
- Audio-rate tick/CV/MTC logging: out of scope for `StudioEvent`.

## Review

- **Design deviation:** T3 lands as an agogo-owned
  `ObservationParams` mirror plus `ObservationSink` publisher rather
  than a direct stdio-core dependency, for the same MSRV reason as
  Plan 2026-04-30-01. The wire shape and stable identifiers match
  stdio-core's `ObservationParams`; replacing the mirror with the real
  type is the next integration slice once the dependency boundary is
  resolved.
