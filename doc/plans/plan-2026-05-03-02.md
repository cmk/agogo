# Plan 2026-05-03-02 - Replace SampleTime conversion helpers with explicit Conns

## Goal

Remove hidden Q48.16 sample conversion policy from the `SampleTime`
trait. Define explicit named connections for the standard sample-rate
types and update call sites to use those connections, so rounding
direction is visible where conversions happen.

`SampleTime` should not be the place where whole-sample, raw-bit, or
float conversion semantics are invented. The six `Sxxx` sample types are
a closed family, and the CLI already dispatches by sample rate. Use that
shape directly.

## Context Read

- `crates/core/src/conn/sample.rs` defines `S044`, `S048`, `S088`,
  `S096`, `S176`, and `S192` as Q48.16 sample-time newtypes.
- The same module already defines lawful sample-rate and FD12
  connections.
- Upstream `connections::fixed::i64` provides the Q-format ladder over
  `FixedI64`, including `Q016Q000` and `Q000I064`.
- `connections::compose!` is the intended API for defining local
  composed conversions. A composition that includes a left-sided
  connection remains a lawful left-sided connection; do not invent a
  `floor` arm where the upstream chain only provides `ViewL`.
- `SampleTime::{from_sample, sample, samples_f64}` currently hide
  conversion choices behind trait methods.
- `crates/cli/src/run.rs` already performs a static dispatch from
  runtime sample rate to concrete `Sxxx` type.

## Dependency Graph

```text
T1 bump/verify upstream connections exports
  -> T2 define Sxxx <-> Q016 and Sxxx -> i64 conns
  -> T3 replace SampleTime helper call sites
  -> T4 remove SampleTime
  -> T5 update docs and tests
```

## Tasks

### T1 - Verify upstream fixed i64 conns are available

Problem or motivation: The cleanup should use upstream law-tested
connections rather than reimplementing Q48.16 shifts locally.

Solution / implementation approach: Confirm the pinned `connections`
revision exports `connections::fixed::i64::{Q000I064, Q016Q000}` and
the `compose!` macro. If not, bump the `connections` rev to one that
does.

Types / API surface: No local API changes yet.

### T2 - Define explicit sample conversion conns

Problem or motivation: Call sites need named conversions such as
`S048I064` instead of generic `R::from_sample` / `r.sample()`.

Solution / implementation approach: In `crates/core/src/conn/sample.rs`,
define per-rate connections:

- `S044Q016`, `S048Q016`, `S088Q016`, `S096Q016`, `S176Q016`, `S192Q016`
- `S044I064`, `S048I064`, `S088I064`, `S096I064`, `S176I064`, `S192I064`

Use `connections::iso!` / `connections::compose!` as appropriate:

- `Sxxx <-> FixedI64<U16>` is a transparent newtype iso.
- `Sxxx -> i64` composes through `FixedI64<U16> -> FixedI64<U0> -> i64`.

Because `Q016Q000` is left-sided upstream, the `SxxxI064` family should
be exposed as lawful `ViewL` connections unless the full composed chain
actually supports `ViewR`. Use `.ceil(...)` and `.inner(...)` from
`ViewL`; do not pretend `.floor(...)` exists.

### T3 - Replace hidden conversion call sites

Problem or motivation: Generic DSP code currently calls
`R::from_bits_q48_16`, `R::from_sample`, `to_bits_q48_16`, and
`samples_f64`, obscuring whether the operation is representation access
or a semantic conversion.

Solution / implementation approach:

- Leave raw-bit constructors/accessors only where the code is truly
  manipulating Q48.16 representation.
- Replace whole-sample conversions with the concrete `SxxxI064` conns.
- Where generic code cannot name one concrete conn, pass the needed conn
  as an argument or keep the conversion at the existing runtime
  sample-rate dispatch boundary.
- Prefer small static dispatch helpers over expanding the `SampleTime`
  trait.

Candidate modules:

- `conn/sample.rs`
- `control/sync/detect.rs`
- `control/sync/pulse.rs`
- `control/sync/pll.rs`
- `control/sync/source.rs`
- `control/transport.rs`
- `cli/run.rs`
- `host-cpal/cpal/callback.rs`

### T4 - Remove `SampleTime`

Problem or motivation: If `SampleTime` is only standing in for a closed
set of six concrete types, it should not exist as another abstraction
layer. Leaving a marker-style trait behind would preserve the same
generic shape that made it easy for conversion helpers to accumulate.

Solution / implementation approach: Delete the `SampleTime` trait and
all its impls. Replace generic `R: SampleTime` APIs with one of these
explicit shapes:

- concrete monomorphic functions/types selected by the existing sample
  rate match;
- small enum/static-dispatch helpers where a runtime `sr: u32` boundary
  must choose one of the six rates;
- direct per-rate conns where conversion semantics are needed.

Do not introduce a replacement marker trait in this sprint. If
duplication becomes uncomfortable, prefer explicit macro expansion over
another trait that can grow hidden conversion methods later.

### T5 - Documentation and verification

Problem or motivation: This is a conversion-policy cleanup. The docs
and tests must make clear that sample conversions are named conns, not
trait conveniences.

Solution / implementation approach:

- Update `sample.rs` module docs to describe the new per-rate composed
  conns.
- Remove stale `SampleTime` prose from callback/run docs.
- Add law batteries for the new composed conns where possible.
- Add spot checks around negative fractional samples to pin the intended
  rounding behavior.

## Verification

### Properties

| Property | Module | Invariant |
| --- | --- | --- |
| `sxxx_i064_left_law_battery` | `conn::sample` | Each `SxxxI064` composed conn satisfies the upstream `l_only` law subset. |
| `sxxx_q016_iso_roundtrip` | `conn::sample` | Each `SxxxQ016` transparent iso round-trips raw Q48.16 bits exactly. |
| `whole_sample_roundtrip` | `conn::sample` | For every supported rate, converting an `i64` whole sample into `Sxxx` and back preserves the sample where the left-connection laws allow it. |
| `negative_fractional_rounding_pinned` | `conn::sample` | Negative Q48.16 fractional positions use the documented adjoint/rounding direction, not accidental arithmetic shift behavior. |
| `pulse_train_peak_times_preserved` | `control::sync::pulse` | Replacing `SampleTime` helpers does not change generated peak positions for supported rates. |
| `internal_phase_source_preserved` | `control::sync::source` | Internal phase at representative sample indices matches pre-change behavior for all six rates. |
| `sample_time_removed` | `conn::sample` | No `SampleTime` trait, impl, or public bound remains in the workspace. |

## Deferred

- Generalizing beyond the six standard sample rates.
- Any runtime dynamic `SampleRate` trait object. The current design
  remains static dispatch over known rates.
- New audio/CV renderer properties; this plan only cleans up sample-time
  conversion semantics.
