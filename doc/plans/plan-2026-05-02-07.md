# Plan 07 — Split pre-commit / pre-push by cost

## Goal
Move `cargo test --workspace` + `cargo clippy --all-targets` from
`.githooks/pre-commit` to a new `.githooks/pre-push`, so per-commit
overhead drops from ~50s to <2s and the expensive suite runs once
per push regardless of intra-branch commit count.

## Motivation
Measured: a normal `git commit` in this repo costs ~52s wall, almost
all in `cargo test --workspace` and `cargo clippy --all-targets`. fmt,
PII, floats, and layers together cost <1s. A 5-commit feature branch
pays the full cost five times pre-push. Moving the expensive checks
to `pre-push` charges them once per push (and skips them entirely on
amend/rebase noise commits) while preserving the same gate against
breakage reaching `origin`.

The "every commit must leave the repo green" invariant in AGENTS.md
weakens to "every pushed commit is green" — which is what's actually
verifiable from the published history and what CI enforces. Intra-
branch commits can be transiently red between `git commit` and
`git push`; the autosquash workflow already accommodates this for
`fixup!` commits.

## Tasks

### T1 — Trim `.githooks/pre-commit` to cheap checks
Remove steps 5 (`cargo test --workspace --quiet`) and 6 (`cargo
clippy --all-targets --quiet -- -D warnings`) from the existing
`.githooks/pre-commit`. Keep:

1. `cargo fmt --all -- --check`
2. `scripts/check-pii.sh`
3. `scripts/check-floats.sh`
4. `scripts/check-layers.sh`

Update the file's leading comment to describe the new split (cheap
on commit, expensive on push) and link to the new pre-push hook.

### T2 — Add `.githooks/pre-push`
New `.githooks/pre-push` runs:

1. `cargo test --workspace --quiet`
2. `cargo clippy --all-targets --quiet -- -D warnings`

Stdin contract: git pipes `<local-ref> <local-sha> <remote-ref>
<remote-sha>` lines on stdin per ref being pushed. The hook only
needs to fire if anything is being pushed at all — read stdin to
gate (`if no lines, exit 0`) so a no-op `git push` (e.g. only tag
deletes) doesn't pay the cost. Any push that includes a non-zero
local sha gets the full suite.

`set -euo pipefail`, same shape as pre-commit. Same `step` helper.
Bypass with `--no-verify` only when authorized (consistent with
pre-commit).

### T3 — Update AGENTS.md
Two edits:

1. The **Repository conventions** bullet at AGENTS.md:151 changes
   from "Each commit must leave the repo in a state where `cargo
   test` passes" to "Each pushed commit must leave the repo green
   (`cargo test --workspace` + `cargo clippy --all-targets`)." Note
   that intra-branch commits can be transiently red between commit
   and push and that's by design — the autosquash workflow expects
   it.
2. The **Pre-commit hooks** section (AGENTS.md:624) renames to
   **Pre-commit and pre-push hooks** and is rewritten to describe
   the two-event split. Activation step now says
   `git config core.hooksPath .githooks` (unchanged — `core.hooksPath`
   covers both hooks).

## Verification

### Properties (must pass)
N/A — these are operational shell scripts. Verification is by spot
check; see the next section.

### Spot checks
| Check | Expectation |
|-------|-------------|
| Stub edit (one-line README change) → `git commit` | Hook completes in < 5s wall |
| `git commit` with PII in diff | Hook fails at step 2 (check-pii.sh) |
| `git commit` with naked `f64` outside allowlist | Hook fails at step 3 (check-floats.sh) |
| `git commit` with cross-layer import | Hook fails at step 4 (check-layers.sh) |
| `git push --dry-run` of the same commit | pre-push fires, runs cargo test + clippy, completes successfully on a green tree |
| `git push --dry-run` with a deliberate clippy warning | pre-push fails, push aborts |

### Build gates
- `cargo test --workspace` — passes (no source changes; this sprint is hook-only)
- `cargo clippy --all-targets -- -D warnings` — passes
- `cargo fmt --all -- --check` — passes
- End-to-end: a normal commit on a clean tree returns control in
  under 5s; a push of that commit pays the full ~50s once.

## Deferred
- **Scoped clippy on pre-commit** (`cargo clippy -p <touched>`):
  considered but not done. The cost of the workspace clippy on push
  is acceptable, and a per-crate variant adds complexity (parse
  staged paths → infer crate names) without solving a real pain
  point once the workspace check moves off pre-commit.
- **Skip test+clippy for `doc:`-only commits**: moot once tests
  move to pre-push — the push of a doc-only branch will pay the
  full cost once, which is fine.
- **Port to stdio-core**: tracked separately. Same hook chain,
  same split, but stdio-core's `check-floats.sh` and `check-layers.sh`
  may differ in detail; revisit once this lands.
