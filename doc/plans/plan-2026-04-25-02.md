# Plan 17 — Channel variables + DSL simplification

## Context

Plan 16 shipped the DSL parser with swing/offset modifiers (`~`, `@`)
in the grammar and `TrackSpec` as the output type. During design review
we decided:

1. The DSL should be **pure grid algebra** — swing, offset, and delay
   are timing parameters that belong in the `--ch` spec, not the
   lattice expression.
2. Channels should be able to **reference earlier channels' grids by
   name** (`kick & T16`), unlocking composition without repeating
   expressions.

This sprint simplifies the DSL (fewer types, no modifiers) and adds
channel variables + swing/offset back to `ChannelSpec`.

## Goal

1. Remove `~` (swing) and `@` (offset) from the DSL grammar.
2. Simplify DSL output from `TrackSpec` to `Grid`.
3. Add channel variable references to the DSL (`C1`, `kick`, etc.).
4. Add `swing=` and `offset=` keys back to `ChannelSpec`.
5. Wire `dsl::parse` into `ChannelSpec` so `grid=` accepts full
   DSL expressions.
6. Default grid = `T4` when `grid=` is omitted.

## Grammar (after)

```
expr       := impl_expr
impl_expr  := join_expr ( ('>' | '<') join_expr )*
join_expr  := meet_expr ( '|' meet_expr )*
meet_expr  := unary ( '&' unary )*
unary      := '!' unary | primary
primary    := ident | '(' expr ')'
ident      := grid_name | var_name
```

Grid names: `T16`, `t8q`, `T2p`, etc. (parsed via `Grid::from_str`).
Variable names: any identifier that isn't a valid grid name (`kick`,
`C1`, `hats`). Case-insensitive for grid names; case-sensitive for
variables.

No modifiers, no separators. `dsl::parse` returns `Grid`.

## CLI surface (after)

```bash
# Positional variable (auto-assigned C1):
--ch "dev=midi,grid=T4"

# Named channel + default grid (T4):
--ch "id=kick,dev=midi"

# Reference by name:
--ch "id=hats,dev=midi,grid=kick&T16,swing=T16:80,offset=20"

# Reference by position:
--ch "dev=midi,grid=C1&T16,swing=80"

# Swing with default resolution (T8):
--ch "dev=midi,grid=T16,swing=80"

# Swing with explicit resolution:
--ch "dev=midi,grid=T16,swing=T16:80"
```

### ChannelSpec keys

| Key | Type | Required | Default | Notes |
|-----|------|----------|---------|-------|
| `dev` | `midi` | yes | — | `audio` reserved for v0.4 |
| `grid` | DSL expr | no | `T4` | parsed via `dsl::parse` with env |
| `id` | string | no | `C<N>` (1-indexed) | variable name for later channels |
| `out` | string | no | — | device port name |
| `swing` | `[TBase:]i8` | no | `T8:0` | resolution defaults to T8 |
| `offset` | `i32` | no | `0` | musical offset in ticks |
| `delay` | `f64` | no | `0` | latency compensation in ms |
| `snap-quantum-us` | `i64` | no | — | Link quantum snap |

### Swing key parsing

- `swing=80` → `SwingConfig { resolution: T8, amount: 80 }`
- `swing=T16:80` → `SwingConfig { resolution: T16, amount: 80 }`
- `swing=-40` → `SwingConfig { resolution: T8, amount: -40 }`
- `swing=T16:-40` → `SwingConfig { resolution: T16, amount: -40 }`

Parse rule: if the value contains `:`, split on `:` → `TBase:i8`.
Otherwise parse as bare `i8` with default resolution `T8`.

## Types removed

- `TrackSpec` — DSL returns `Grid` directly
- `Modifier` enum — swing/offset no longer in DSL
- `TrackAst` — DSL top-level is just `Expr`

## Types modified

### `Expr` — add `Var` variant

```rust
pub enum Expr {
    Atom(Grid, Span),
    Var(String, Span),                   // NEW — channel variable
    Neg(Box<Expr>, Span),
    Meet(Box<Expr>, Box<Expr>, Span),
    Join(Box<Expr>, Box<Expr>, Span),
    Imply(Box<Expr>, Box<Expr>, Span),
    Coimply(Box<Expr>, Box<Expr>, Span),
}
```

### `DslErrorKind` — remove modifier variants, add variable error

Remove: `InvalidSwingResolution`, `SwingAmountOutOfRange`,
`DuplicateModifier`, `OffsetOutOfRange`.

Add: `UnknownVariable(String)`.

### `TokenKind` — simplify

Remove: `Tilde`, `At`, `Colon`, `Int(i64)`.
Rename: `Atom(String)` → `Ident(String)` (handles both grid names
and variable names).

### `ChannelSpec` — add swing, offset; grid stays `Grid`

The `grid=` DSL expression is fully resolved to `Grid` during
`ChannelSpec::parse`. The field type stays `Grid`.

```rust
pub struct ChannelSpec {
    pub id: Option<String>,
    pub dev: ChannelDev,
    pub out: Option<String>,
    pub grid: Grid,                     // resolved from DSL expr at parse time
    pub swing: SwingConfig,             // from swing= key (default T8:0)
    pub offset_ticks: i32,              // from offset= key (default 0)
    pub delay_ms: f64,                  // argv boundary
    pub snap_to_quantum_micro: Option<i64>,
}
```

### `dsl::parse` — new signature

```rust
pub fn parse(input: &str, env: &[(String, Grid)]) -> Result<Grid, DslError>
```

`env` maps variable names to previously-resolved grids. Empty env
for the first channel.

## Channel resolution flow

`ChannelSpec::parse` takes an environment and resolves the `grid=`
expression immediately:

```rust
pub fn parse(s: &str, env: &[(String, Grid)]) -> Result<Self, ChannelSpecError>
```

Inside `parse`, the `grid=` value goes through `dsl::parse(value, env)`
→ `Grid`. If `grid=` is omitted, defaults to `Grid::T4`.

A new function processes all `--ch` specs in order, building the env:

```rust
pub fn parse_channels(
    specs: &[String],
) -> Result<Vec<(String, ChannelSpec)>, ChannelSpecError> {
    let mut env: Vec<(String, Grid)> = Vec::new();
    let mut result = Vec::new();
    for (i, s) in specs.iter().enumerate() {
        let spec = ChannelSpec::parse(s, &env)?;
        let id = spec.id.clone()
            .unwrap_or_else(|| format!("C{}", i + 1));
        env.push((id.clone(), spec.grid));
        result.push((id, spec));
    }
    Ok(result)
}
```

`into_channel` stays as-is (reads `self.grid`, now also `self.swing`
and `self.offset_ticks`).

In `run.rs`, the call site changes to:
```rust
let named = parse_channels(&args.ch)?;
let channels: Vec<Channel> = named.into_iter()
    .map(|(_, spec)| spec.into_channel())
    .collect::<Result<_, _>>()?;
```

## Tasks

### T1 — DSL simplification + variables

In `crates/core/src/dsl/`:

1. **ast.rs**: Remove `Modifier`, `TrackAst`, `TrackSpec`. Add
   `Expr::Var(String, Span)`.
2. **lexer.rs**: Remove `Tilde`, `At`, `Colon`, `Int` tokens. Rename
   `Atom` → `Ident`. Extend identifier recognition from `T/t` to any
   ASCII letter + alphanumeric continuation.
3. **parser.rs**: Remove `parse_track`, `parse_swing`, `parse_offset`,
   modifier parsing. Top-level becomes `parse_expr`. In
   `parse_primary`: try `Grid::from_str` on ident text — if it
   succeeds, emit `Expr::Atom`; otherwise emit `Expr::Var`.
4. **eval.rs**: Remove `eval_track`. Change `eval_expr` to take
   `&[(String, Grid)]` env. `Expr::Var` looks up the name in env
   (case-sensitive), returns `DslError::UnknownVariable` if missing.
5. **display.rs**: Remove `Modifier`/`TrackAst` Display impls.
   Add `Expr::Var` Display (just the name).
6. **error.rs**: Remove `InvalidSwingResolution`, `SwingAmountOutOfRange`,
   `DuplicateModifier`, `OffsetOutOfRange`. Add `UnknownVariable(String)`.
7. **dsl.rs**: Change `parse()` signature to
   `parse(input: &str, env: &[(String, Grid)]) -> Result<Grid, DslError>`.
   Update all tests.

Tests:
- `parse("T16", &[])` → `Grid::T16`
- `parse("kick", &[("kick", Grid::T4)])` → `Grid::T4`
- `parse("kick&T16", &[("kick", Grid::T4)])` → `meet(T4, T16)`
- `parse("C1", &[("C1", Grid::T8)])` → `Grid::T8`
- `parse("unknown", &[])` → `Err(UnknownVariable)`
- `parse("C2&C1", &[("C1", Grid::T4)])` → `Err(UnknownVariable)`
  (C2 not defined — strict monotonicity)
- All existing lattice proptests updated (pass `&[]` as env)
- `display_parse_round_trip` with variables in env
- `parser_never_panics` still holds

### T2 — ChannelSpec: swing, offset, grid, resolve_channels

In `crates/core/src/machine/spec.rs`:

1. `grid` stays `Grid`. `parse()` takes `env: &[(String, Grid)]` and
   resolves the `grid=` DSL expression at parse time. Defaults to
   `Grid::T4` when `grid=` is omitted.
2. Add `swing: SwingConfig` field (default `T8:0`).
3. Add `offset_ticks: i32` field (default `0`).
4. Accept keys: `swing=<[TBase:]i8>`, `offset=<i32>`.
5. Make `grid` optional (default `Grid::T4` when omitted).
6. `into_channel` reads `self.grid` (already resolved), plus
   `self.swing` and `self.offset_ticks` for the Channel.
7. Add `parse_channels(specs) -> Result<Vec<(String, ChannelSpec)>>`.
8. Update `Display` impl for round-trip with new keys.
9. Parse swing key: split on `:` if present, default resolution `T8`.

Tests:
- `parse("dev=midi", &[])` → grid = `Grid::T4` (default)
- `parse("dev=midi,grid=T16", &[])` → grid = `Grid::T16`
- `parse("dev=midi,grid=kick&T16", &[("kick", T4)])` → grid = `Grid::T16`
- `parse("dev=midi,swing=80")` → swing = `SwingConfig { T8, 80 }`
- `parse("dev=midi,swing=T16:80")` → swing = `SwingConfig { T16, 80 }`
- `parse("dev=midi,swing=T16:-40")` → swing = `SwingConfig { T16, -40 }`
- `parse("dev=midi,offset=20")` → offset_ticks = `20`
- `parse("dev=midi,offset=-5")` → offset_ticks = `-5`
- `resolve_channels([spec_T4, spec_C1_AND_T16])` → two channels,
  second grid = `meet(T4, T16)` = `T16`
- `resolve_channels` with named refs (`kick` → `T4`, `kick&T16`)
- `resolve_channels` with forward ref → error
- `spec_round_trip` proptest updated for new fields

  Variables are strictly channel IDs.
- **Grid default configurability**: T4 is hardcoded. A `--default-grid`
