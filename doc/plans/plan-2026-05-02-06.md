# Plan 2026-05-02-06 - Audio metronome test feature

## Goal

Add a minimal generated-tone `dev=audio,mode=click` metronome path for
internal user testing without exposing click-shaping CLI parameters.

## Dependency Graph

```text
T1 audio role + channel shape
  -> T2 parser/lowering
  -> T3 core audio renderer
  -> T4 Playhead dispatch/counters
  -> T5 cpal output/run plumbing
  -> T6 tests + docs finalization
```

## Tasks

### T1 - Audio role + channel shape

Problem or motivation: `Channel` is currently sum-typed by MIDI, DIN,
and CV targets. The old MIDI click plan deferred audio click until a
real audio target existed.

Solution / implementation approach: Add `AudioRole::Click` and
`Channel::Audio { common, role }`, preserving the existing
`ChannelCommon` scheduler contract. The role carries no public sound
parameters; fixed test-feature constants live with the renderer.

Types / API surface: `AudioRole` is re-exported from `channel`, and
`Channel::common` / `common_mut` gain the audio arm.

### T2 - Parser and lowering

Problem or motivation: `dev=audio` currently returns `AudioDeferred`,
which blocks a standalone audio metronome even though MIDI click
scheduling already exists.

Solution / implementation approach: Parse `dev=audio,mode=click` into
an audio-target spec. Keep the CLI narrow: no tone, envelope, waveform,
amplitude, duration, or accent keys are accepted for audio. MIDI-only
keys (`note`, `vel`, `mch`, `accent-*`) stay valid only for
`dev=midi,mode=click`.

Types / API surface: Make `ChannelSpec` carry the target role shape
needed to lower into `Channel::Midi` or `Channel::Audio`. Display emits
`dev=audio,mode=click` for audio specs.

### T3 - Core audio renderer

Problem or motivation: `AudioIo.output` exists but no renderer writes
audible scheduled output.

Solution / implementation approach: Add a generated PCM click renderer
that writes a short fixed click at each scheduled event's sample offset.
The renderer clips to the `f32` PCM range, writes only within the
current buffer, and has fixed normal/accent constants private to core.

Types / API surface: Add a core `sink::audio` helper consumed by
`Playhead`; no CLI-facing sound config.

### T4 - Playhead dispatch and counters

Problem or motivation: Playhead currently renders only MIDI channels;
DIN/CV are visible no-ops.

Solution / implementation approach: Dispatch `Channel::Audio` to the
audio renderer, using the same scheduled event pool and existing
`bars=N` pre-render filter. Add an audio click counter parallel to the
MIDI click counter so accent cadence starts at zero, advances per
emitted audio click, and resets on transport stop.

Types / API surface: `Playhead` remains the host-facing orchestration
type; `on_buffer` continues to take `AudioIo` plus MIDI sink.

### T5 - cpal output and `agogo run`

Problem or motivation: `agogo run` opens cpal input-only and opens a
MIDI port unconditionally, so an audio-only metronome cannot run without
MIDI hardware.

Solution / implementation approach: Add cpal output-only support for
internal-source audio click testing. `agogo run` opens MIDI only when
MIDI channels exist, opens cpal output when audio channels exist, and
keeps the existing input path for external or Link use.

Types / API surface: Add output-device selection/listing to `CpalHost`
as needed by `Config::output_device`; keep the CLI minimal and reuse
`out=default` as the audio output selector.

## Verification

| Test | Area | Invariant |
| --- | --- | --- |
| `audio_click_events_write_nonzero_samples` | `sink::audio` | A scheduled audio click writes nonzero PCM inside the buffer. |
| `audio_click_ignores_out_of_buffer_events` | `sink::audio` | Events outside the current buffer leave the output untouched. |
| `audio_accent_lands_every_n_emitted_clicks_from_zero` | `sink::audio` | Accent cadence starts at emitted-click counter zero. |
| `audio_click_counter_advances_across_buffer_boundaries` | `sink::audio` | Split rendering matches one combined render. |
| `audio_click_counter_resets_on_transport_stop` | `control::transport` | A stop/reset makes the next audio accent land at counter zero. |
| `spec_round_trip` | `channel::spec` | Parser/display round-trips both MIDI and audio click specs. |
| `run_accepts_audio_click_internal_spec` | `cli::run` | Bounded internal-source run accepts an audio click-only spec. |
| `run_audio_only_does_not_require_midi_port` | `cli::run` | Audio-only channel setup does not enumerate/open MIDI. |

## Deferred

- CLI sound-design controls such as attack, decay, sustain, release,
  waveform, frequency, amplitude, and duration.
- WAV sample playback.
- CV pulse, LFO, heterogeneous output calibration, and product-level
  audio-output UI.
