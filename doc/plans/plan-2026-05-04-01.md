# Plan 2026-05-04-01 - Reshape CLI module tree

## Goal

Make `crates/cli` read as a CLI shell instead of a kitchen sink. Keep
`main.rs` as the application root, keep `command.rs` as the top-level parser
and dispatcher, and move command implementations under `command/`.

## Context

The CLI crate currently mixes several concepts at its source root:

- `command.rs` is the top-level router.
- `parsers.rs` is the argv conversion boundary.
- `run.rs` is the primary end-to-end product workflow.
- `demo.rs` is an optional demo command.
- `link/probe.rs` and `trace/*` both hold telemetry-style commands.

The new `agogo-chan` / `agogo-core` / host boundary made this internal CLI
drift more visible. This plan is a mechanical module-layout cleanup only; it
does not move runtime orchestration out of CLI yet.

## Target Tree

```text
crates/cli/src/
  main.rs
  command.rs
  parse.rs

  command/
    time.rs
    channel.rs
    midi.rs
    sync.rs
    link.rs
    link/
      commands.rs
      probe.rs
    run.rs
    demo.rs

  log.rs        # add only if shared output/logging helpers justify it
  test.rs       # add only for tiny generic unit-test helpers, if needed

crates/cli/test/
  demo.rs
  run.rs
  link.rs
```

`crates/cli/src/test.rs`, if added, must stay limited like `chan::test`: small,
generic helpers only. Command-surface and integration-style coverage belongs in
`crates/cli/test/*.rs` wired by explicit `[[test]]` sections.

## Tasks

### T1 - Rename argv parser module

- Rename `crates/cli/src/parsers.rs` to `crates/cli/src/parse.rs`.
- Keep only argv-boundary conversions there.
- Update imports from `crate::parsers::*` to `crate::parse::*`.

### T2 - Keep `command.rs` as the top-level router

- Keep top-level `Cli`, `Command`, and `dispatch` in `command.rs`.
- Declare command implementation modules from `command.rs` using modern Rust
  layout:

```rust
mod channel;
mod demo;
mod link;
mod midi;
mod run;
mod sync;
mod time;
```

### T3 - Move command implementations under `command/`

Move current implementation files without behavior changes:

```text
time/schedule.rs       -> command/time.rs
trace/channel.rs       -> command/channel.rs
trace/midi.rs          -> command/midi.rs
trace/sync.rs          -> command/sync.rs
link/mod.rs            -> command/link.rs
link/commands.rs       -> folded into command/link.rs or command/link/commands.rs
link/probe.rs          -> command/link/probe.rs if still separate
run.rs                 -> command/run.rs
demo.rs                -> command/demo.rs
```

Delete the old `time/`, `trace/`, and `link/` roots once callers are updated.

### T4 - Separate integration-style command tests

- Add `crates/cli/test/` for command-surface tests that do not belong under
  `src`.
- Add explicit `[[test]]` sections in `crates/cli/Cargo.toml` for any moved or
  newly split integration tests, gated with `required-features`.
- Do not add `src/test.rs` unless a tiny generic helper is actually needed.

### T5 - Defer runtime extraction explicitly

Keep `command/run.rs` behaviorally identical for this sprint. If it remains
large after the move, document the remaining issue in Review: the primary
runtime assembly still belongs in `agogo-core` eventually, not in CLI.

### T6 - Add CLI layering to the gate

Extend `scripts/check-layers.sh` to include `crates/cli/src`:

```text
command -> parse, log, test
parse   -> leaf
log     -> leaf       # only if created
test    -> leaf       # only if created
```

The gate should account for only module roots that exist; do not create empty
`log.rs` or `test.rs` just to satisfy a diagram.

Update `AGENTS.md` so the script and convention agree.

## Deferred

- `command/run.rs` remains large and still owns runtime assembly. This sprint
  only moved the module; a later plan should move typed runner config and
  execution into `agogo-core`.
- Many tests still live inline in command modules because they exercise private
  helpers. New command-surface tests now live under `crates/cli/test/*.rs`;
  moving the private-helper tests out cleanly likely requires a library target
  or a smaller public test surface.
- No `log.rs` or `src/test.rs` was added. There was no shared logging/output
  helper or generic test helper that justified a new root module.

## Review

- `AGENTS.md` and `scripts/check-floats.sh` had stale CLI path prose/allowlist
  entries for `parsers.rs`, `trace/*`, `time/schedule.rs`, and `link/probe.rs`.
  Fixed inline with the module move so the drift gate and convention match the
  new tree.
