# Plan 2026-05-05-02 - Multi-channel offline render and inter-channel proptests

## Goal

Generalize the deterministic offline render path from hardcoded mono to
1..=16 explicitly-assigned output channels, replace the implicit
`audio_index % 2` lane policy with explicit per-channel assignment via
`out=N` on the channel spec, validate at the boundary that no two audio
channels share a lane (no mix bus), expose per-lane PCM through a new
`render_offline_capture` entry point, and cover the whole pipeline with
an end-to-end proptest battery that asserts inter-channel sample-perfect
timing for arbitrary polyrhythms.

This sprint preserves the no-mix-bus invariant from plan
2026-05-05-01 while removing its `n_audio <= 2` constraint. The 2-
channel default (ch1 left, ch2 right) remains the CLI default; users
opt in to wider configurations via `--output-channels N` and explicit
`out=N` on each audio channel.

## Tasks

### T1 - Multi-channel offline render config

Add `output_channels: u16` to `OfflineRenderConfig` and validate it is
in `1..=16` via a new `OfflineRenderError::UnsupportedChannelCount`
variant. Update `render_offline_with_rate` to allocate
`frames * usize::from(output_channels)` PCM samples per buffer and pass
`output_channels` to `AudioIo::with_output_channels`. Aggregate audio
stats across the interleaved buffer.

Add `--output-channels` flag (`u16`, fallback `2`) to the `render` CLI
subcommand and plumb it through to `OfflineRenderConfig`.

### T2 - Explicit per-channel lane assignment via `out=N`

Extend the channel spec parser so `out=` accepts a bare integer
(`out=0`, `out=1`, ...) when `dev=audio`. The parser stays
string-typed for `out`; per-`dev` interpretation happens at the
channel constructor or validation step. For `dev=audio`, `out=N` is
required; `out=diag` is rejected with a clear message ("audio without
a destination is silence - use `out=N`"). For `dev=midi` and `dev=cv`,
`out=` semantics are unchanged.

Surface the parsed lane on `ChannelSpec` as
`audio_lane: Option<u16>` (`None` for non-audio channels).

Replace `audio_index % 2` in `transport.rs` with the explicit lane
drawn from each channel's spec. Callers that omit `out=N` on an audio
channel hit a typed error instead of silently round-robining.

### T3 - Lane validation at the config boundary

Add `OfflineRenderError` variants (internal naming uses "lane" for
clarity even though the user-facing field is `out=`):

- `LaneOutOfRange { channel: usize, lane: u16, output_channels: u16 }`
- `LaneCollision { lane: u16, channels: (usize, usize) }`

A missing `out=N` on an audio spec is rejected one layer earlier by
the spec parser / `into_channel`; `Channel::Audio.lane` is a total
`u16`, so the offline boundary never sees an "audio channel with no
lane" — no `LaneMissing` variant is needed.

Validate at the top of `render_offline` once `output_channels` is
known: every assigned lane is in range, no two audio channels share a
lane. Errors are clean `Result::Err`s, never panics. `Display` impls
reference the user-facing `out=` field name so CLI errors stay
grounded in what the user typed.

Share the validation helper between the offline path and the live
`run` path so they cannot diverge.

### T4 - `render_offline_capture` entry point

Add `OfflinePcm { lanes: Vec<Vec<f32>>, sample_rate: u32, frames: u64 }`
and `render_offline_capture(cfg) -> Result<(OfflineRenderReport,
OfflinePcm), OfflineRenderError>` to `crates/core/src/transport.rs`.
The implementation reuses the existing per-buffer loop but additionally
splits each interleaved buffer by lane and appends to `lanes[i]`.

Re-export through the `agogo` facade so the test crate imports through
the same surface a downstream consumer would use. `render_offline`
itself stays a thin wrapper; the CLI's existing JSON-aggregate path is
byte-identical.

The future WAV-render CLI feature is the motivation for the lane-split
return shape; it is out of scope for this plan.

### T5 - Proptest strategies and end-to-end battery

Extend `crates/chan/src/time/arb.rs` with:

- `arb_polyrhythm_pair() -> impl Strategy<Value = (Grid, Grid)>` -
  bias toward small-LCM pairs (3:2, 2:3, 4:3, 5:4, 7:5) plus a
  boundary-bias 1:1 case.
- `arb_n_channel_polyrhythm(n: u16)` - N distinct grids, one per
  channel, for N up to 16.
- `arb_bounded_render_cfg()` over (bpm, sr, buffer_frames,
  duration_bars, output_channels) with bpm in [60, 240] (weighted
  toward 120/128/170), sr in {44_100, 48_000, 88_200, 96_000},
  buffer_frames in {64, 128, 256, 1024, 4096}, duration_bars in [1, 4],
  output_channels in {1, 2, 4, 8, 16}.

Create a new integration test `crates/agogo/test/inter_channel_accuracy.rs`
with the property battery and spot checks listed in Verification.

### T6 - CLI parity smoke test

Extend `crates/cli/test/render.rs` with one deterministic 4-channel
case using `--output-channels 4` and four `out=N` audio channels.
From the same test, call `render_offline_capture` directly with the
equivalent config and assert the JSON aggregates the CLI emits agree
with the aggregates derived from the captured PCM.

### End-to-end manual scenario

```
cargo run -- render --source internal --bpm 120 --sr 48000 \
  --duration-bars 4 --buffer-frames 1024 --output-channels 4 \
  --ch 'id=ch1,dev=audio,mode=click,grid=...,out=0' \
  --ch 'id=ch2,dev=audio,mode=click,grid=...,out=1' \
  --ch 'id=ch3,dev=audio,mode=click,grid=...,out=2' \
  --ch 'id=ch4,dev=audio,mode=click,grid=...,out=3'
```

Confirm `audio.nonzero_samples` is consistent with the per-lane
footprint sum. Bumping `--output-channels 8` with the same 4 channels
yields 4 silent lanes plus the same 4 active lanes (no shift in
active-lane indices). A deliberate collision (`out=0` on two audio
channels) fails fast with `LaneCollision` mentioning both channel ids.

## Deferred

- WAV-render CLI feature (`agogo render --wav-out FILE`). Builds on
  `render_offline_capture` plus `hound` re-interleaving; separate
  small plan once this lands.
- Multi-channel live render. The live `run` path passes
  `output_channels: 2`. Lane validation introduced in T3 will refuse
  3+ channel configs there until the live path is updated to honour
  `--output-channels`. If that is a regression for current live
  users, the Review section will record it and either widen T3 or
  carry a follow-up.
- MIDI/CV `out=N` namespace cleanup. The `out=` field grows integer
  semantics for `dev=audio` only this sprint; MIDI port routing and
  CV channel routing keep their current semantics until those
  subsystems grow multi-port support.
- Multi-tail click continuation. `AudioClickState.pending_samples`
  preserves only the latest truncated click across a buffer
  boundary; configs where >= 2 clicks of the same channel straddle
  one boundary (fine grids like `T256` / `T512P` at high BPM where
  event spacing drops below `click_len`) silently lose the earlier
  tails. Proper fix needs a queue of pending tails plus decoupling
  state advancement from output writing so the unsplit-rendering
  order is preserved (shared filter / RNG state currently
  interleaves between overlapping clicks). Acceptable for this
  sprint because the proptest battery's polyrhythm pairs all keep
  event spacing >= `click_len`; covered by Copilot review on PR #81.

## Review

- `crates/core/src/transport.rs` (line 391 in main at sprint start) -
  `audio_index % 2` is a silent mix bus when `n_audio > 2`, violating
  the no-mix-bus imperative for any future >2-channel work. Folded
  into this plan as T2/T3 (replacing the implicit policy with
  explicit per-channel `out=N` plus boundary validation).
- Renderer correctness fix (`crates/chan/src/sink/audio.rs`) -
  `prop_buffer_boundary_invariance` exposed that audio clicks were
  truncated at buffer boundaries instead of continuing in the next
  buffer. Pre-existing latent bug, not introduced by this sprint;
  fixed in scope because the proptest battery's whole point is to
  pin sample-perfect timing under arbitrary buffer sizes.
  `AudioClickState` gained `pending_samples` / `pending_accent`
  fields and `render_audio_click_block` now resumes the truncated
  tail at output offset 0 of the next buffer before processing new
  events. Limitation: only the most-recently-truncated click is
  preserved; rapid overlapping clicks that all straddle a single
  boundary lose earlier tails (acceptable for musical configs where
  events are spaced more than `click_len` apart).
- `AudioClickState::new` seeding switched from audio-channel ordinal
  to lane index (`crates/core/src/transport.rs`), making per-lane
  PCM bit-identical regardless of co-channels. Required by
  `prop_n_channel_independence` and consonant with the lane-as-
  identity model.
- Pre-existing `audio_accent_lands_every_n_emitted_clicks_from_zero`
  test was implicitly relying on the truncation bug + filter state
  staying near zero between truncated clicks. Rewrote it to compare
  per-click peak magnitudes over the `click_len` window instead of
  raw first samples, so the test passes under correct continuation
  behaviour.
- Live `run` path's `audio_output_request` selection now sources
  the device name only from CV channels (audio's `out=` is the
  integer lane, not a device name). Audio-only configs default to
  the host's default audio device. The `run_rejects_multiple_audio_outputs_until_routing_exists`
  test was reframed from "audio + cv with different device names"
  to "two CV channels with different device names" since audio
  no longer participates in audio-device naming.
- Test-the-test (per AGENTS.md): reverted the lane policy back to
  `audio_index % 2` in a dirty worktree and confirmed
  `prop_unused_lane_silence`, `prop_n_channel_independence`, and
  `spot_16_channel_unique_lanes` all fail. Restored, all green.
- Initial draft of the plan promised an `OfflineRenderError::LaneMissing`
  variant; the shipped implementation makes `Channel::Audio.lane: u16`
  total (parser rejects `out=` missing, `into_channel` requires
  `audio_lane: Some`), so the boundary never sees a missing-lane
  audio channel and the variant is unnecessary. Plan + review docs
  updated to remove `LaneMissing` references; PR #81 review caught
  the discrepancy.
- Initial Verification table over-promised properties that didn't
  ship under those names. Updated to list the 12 properties the test
  file actually defines (added `prop_onset_sample_exact`,
  `prop_footprint_length_constant`, `prop_sample_rate_doubling`
  during PR #81 review-round; renamed coincident /
  lane-separation properties to match their shipped identifiers;
  dropped the unimplemented `prop_lane_missing_rejected`).
- `AudioClickState.pending_samples` preserves only the latest
  truncated tail across a buffer boundary (Copilot flagged on PR
  #81). For fine grids where event spacing drops below `click_len`,
  earlier tails are silently lost. Acceptable for the polyrhythm
  set this sprint exercises; deferred to a follow-up plan that
  needs a queue of pending tails plus decoupling state advancement
  from output writing.
