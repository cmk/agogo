# Plan 2026-04-28-06 — Split machine/spec.rs into 5 single-concern files

## Goal

`crates/core/src/channel/spec.rs` is 1325 lines doing five jobs:

1. **`ChannelSpec` struct + accessor** (`snap_intent`) — lines 56–88 + 461–466
2. **`ChannelSpecError` enum** — lines 91–104
3. **Parser** — `ChannelSpec::parse` (107–407), `parse_channels` (471–501),
   `parse_swing` (504–532), `micro_from_user_ms` (534–541),
   `tokenize` (635–703)
4. **Display** — `Display for ChannelSpec` (543–624) + `quote_if_needed`
   (626–633), inverse of the parser; used by round-trip proptest
5. **Validation** — `ChannelSpec::into_channel` (411–444), the
   spec→runtime-`Channel` lowering with cross-key checks

This is the T9 deliverable from PR #35's audit
(plan-2026-04-28-03 §What's actually disorganized). Same kitchen-sink
shape just demolished for `cli/main.rs` in PR #37.

After this PR:
- Parent `crates/core/src/channel/spec.rs` shrinks to ~30 lines:
  module-level doc + `pub mod` declarations + `pub use` re-exports.
- Each of the five concerns lives in its own file under
  `crates/core/src/channel/spec/`.
- Tests stay colocated with their module:
  - `parse_*` tests + `parse_channels_*` tests → `parser.rs::tests`
  - `display_*` tests + `arb_*` proptest helpers + `spec_round_trip`
    proptest → `display.rs::tests`
  - `into_channel_*` tests + `snap_intent_*` tests → `validate.rs::tests`
    (snap_intent itself lives in `types.rs` but its tests assert
    parser→snap_intent integration so they fit better with
    validate-style end-to-end checks)
- Public API surface unchanged: `crate::channel::spec::{ChannelSpec,
  ChannelSpecError, parse_channels}` continues to resolve via the
  parent `spec.rs`'s `pub use` re-exports.

No functional changes. Pure file-layout work, like PR #37.

## Dependency Graph

```
T1  types.rs       (struct + snap_intent — base types other modules need)
T2  error.rs       (depends on nothing; could ship before T1)
T3  parser.rs      (depends on types, error)
T4  display.rs     (depends on types)
T5  validate.rs    (depends on types, error, parser-via-tests)
T6  spec.rs parent (becomes thin re-export hub; deletes the now-empty body)
```

Smallest first to keep each commit reviewable: T2 (error, ~20 lines) → T1 (types, ~70) → T5 (validate, ~120) → T4 (display, ~200) → T3 (parser, ~600).

T6 is the final consolidation: once all five concerns have moved out of `spec.rs`, what remains is the doc + imports + nothing else; replace with `pub mod` decls + re-exports.

## Tasks

For each Tn the recipe matches PR #37's pattern:

1. Create the new file with its imports + body extracted verbatim
   from `spec.rs`. Include a `#[cfg(test)] mod tests` for any tests
   that target that concern.
2. In `spec.rs`, remove the extracted code. Add `pub mod foo;` and
   the corresponding `pub use foo::*` (or specific re-exports) so
   external `crate::channel::spec::{ChannelSpec, ...}` paths keep
   resolving.
3. `cargo build --workspace --all-features` + `cargo test --workspace
   --all-features` + `cargo clippy --workspace --all-targets
   --all-features -- -D warnings` + `scripts/check-floats.sh`. Commit.

The test redistribution is the trickiest piece — the existing
`#[cfg(test)] mod tests` block at lines 705–1325 has 50+ tests
interleaved by topic. Sort during T3/T4/T5; spot-check that no
test references state that didn't move with it.

### T2 (smallest first) — `error.rs` (~20 lines)

`ChannelSpecError` enum. Pure type definition; no methods, no tests
specifically for the error variants (errors are tested indirectly
via parser tests).

### T1 — `types.rs` (~70 lines)

`ChannelSpec` struct + `snap_intent` accessor. The struct needs the
field types (Grid, MidiRole, SwingConfig, Micro, NonZeroU16) but no
behaviour beyond `snap_intent`. The `snap_intent_*` tests stay with
`validate.rs` (T5) because they exercise parser→struct→snap_intent
integration, which is more validate-shaped than type-shaped.

### T5 — `validate.rs` (~120 lines)

`ChannelSpec::into_channel` + 5 tests:
- `into_channel_clamps_delay`
- `into_channel_bars_round_trips_via_nonzero`
- `into_channel_click_maps_mch_to_zero_based`
- `into_channel_click_no_accent_when_accent_every_absent`
- `snap_intent_none_when_key_absent`
- `snap_intent_round_trips_through_spec` (proptest)

### T4 — `display.rs` (~200 lines)

`Display for ChannelSpec` + `quote_if_needed` + 6 spot-check tests
(`display_round_trip_*`, `display_swing_*`, `display_quotes_*`) +
the `arb_*` proptest strategies (`arb_grid`, `arb_tbase`, `arb_mode`,
`arb_bars`, `arb_spec`) + the `spec_round_trip` proptest.

The arb_ helpers live with the round-trip test that uses them; if a
future T7 needs them elsewhere they can move up to a shared module.

### T3 — `parser.rs` (~600 lines, biggest)

Everything else: `ChannelSpec::parse`, `parse_channels`, `parse_swing`,
`micro_from_user_ms`, `tokenize` + ~40 `parse_*` tests +
`parse_rejects_*` tests + `parse_channels_*` tests.

### T6 — Shrink `spec.rs` parent (~30 lines)

```rust
//! Channel-spec mini-language for `agogo run --ch <spec>`.
//! ... (existing module doc) ...

pub mod display;
pub mod error;
pub mod parser;
pub mod types;
pub mod validate;

pub use error::ChannelSpecError;
pub use parser::parse_channels;
pub use types::ChannelSpec;
```

External callers (`crate::control::ChannelSpec`, etc., re-exported
from `machine.rs`) continue to resolve unchanged.

## Review

### What this PR ships

T1–T5 split the five concerns out of spec.rs. T6 (the planned
"shrink the parent" step) collapsed into T3 since after the
previous four extractions, what remained in spec.rs was just the
parser body + tokenizer + parse tests + the parent-module
imports they needed; moving those into `parser.rs` left the
parent at the desired thin shell shape immediately. Final
parent: 39 lines (target ~30, small overage from the doc
comment).

### Design deviations

- **T3 + T6 collapse** as noted above — same shape as PR #37's
  T3 + T8 collapse.
- **check-floats allowlist swap, not addition.** The plan
  expected an addition (new file added); reality was a swap
  (`machine/spec.rs` → `machine/spec/parser.rs`) since the
  parent file no longer holds the f64 surface.

### Notes on test redistribution

Three tests interleaved between concerns took judgment to
classify:

- `parse_rejects_negative_delay`: stays in `parser::tests`. It
  asserts that the parser path rejects negative delay at parse
  time (vs. into_channel clamping); that's a parse contract.
- `into_channel_clamps_delay`: moved to `validate::tests`. It
  asserts the `MAX_DELAY` clamp inside `into_channel`.
- `snap_intent_*`: moved to `validate::tests`. Even though
  `snap_intent` lives in `types.rs`, the tests exercise the
  parser→struct→snap_intent integration path, which is closer
  to validate's end-to-end shape than to types's data-only
  surface.

### Recommendations for follow-up

The two big mechanical kitchen-sink demolitions (T11 / T9) are
done. Substantive backlog items:
1. **T6 `LpfPid`** — the Link-follower controller borrow from the
   `clocked` review. Real DSP behaviour change in PLL critical
   path; deserves its own focused PR.
2. **`compose!` / `ceiling1` body cleanups** — small dedicated
   plan to apply the upstream lifters to `pico_to_samples` and
   the `boundary::finite_or_unreachable` pattern.
3. **host-link 4-layer wrapping cleanup** — accidental layering
   audit-flagged in PR #35; needs a planning round before code.
