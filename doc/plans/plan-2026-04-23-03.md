# Plan — Fixed-point refactor of agogo DSP core

## Goal

Eliminate `f32` / `f64` from stored state and public APIs across
`agogo-core` and `agogo-cli` in favour of the rate-typed sample tier
(`S44 / S48 / S88 / S96 / S176 / S192`) and decimal time ladder
(`Uni / Deci / … / Pico`) just landed in the sibling `connections`
crate. One explicit exception: the PI controller's gains and
internal control-law state (`PllSettings { kp, ki, clamp_hz, interp }`
plus `PllState { phase, freq_hz, integrator }` in `sync::pll`) stay
`f64` — that's genuine analog-DSP arithmetic.

## Context

The current `Peak.sample_index: f64` and `PllOutput.{ bpm, phase }:
f32` conflate integer sample identity with sub-sample precision in
lossy floats. Mixing sample rates is a runtime bug rather than a
compile error. With the decimal + rate tiers in `connections` now
providing Galois-connected integer types for every relevant
conversion, agogo can flip its public surface to them and let the
type system enforce rate correctness while retaining sub-sample
precision via Q48.16.

Upstream (connections) PR with the ladder + rate tier has merged at
rev `15d3791e281e30c4eacaa4e499ee5788894d9ab6`; agogo's workspace
`Cargo.toml` bumps to that rev as part of T1 below.

### T1 — `crates/core/src/fxp.rs`

New module; re-exports the ladder and rate tier from `connections`,
adds agogo-local types and conversion helpers.

**New types**:

```rust
// Phase accumulator — Q0.32 cycles; wrapping_add IS modular reduction.
#[repr(transparent)]
#[derive(Copy, Clone, Debug, PartialEq, Eq, Default)]
pub struct Phase(pub u32);

impl Phase {
    pub const ZERO: Self = Self(0);
    pub fn wrapping_add(self, rhs: Self) -> Self { Self(self.0.wrapping_add(rhs.0)) }
    pub fn wrapping_sub(self, rhs: Self) -> Self { Self(self.0.wrapping_sub(rhs.0)) }
}

// BPM × 10⁶ as u32. Range 0..≈4295 BPM, resolution 10⁻⁶ BPM.
#[repr(transparent)]
#[derive(Copy, Clone, Debug, PartialEq, Eq, PartialOrd, Ord, Hash, Default)]
pub struct Tempo(pub u32);
```

**PI-boundary f64 → fxp conversions** (one cast per PLL step):

```rust
pub fn f64_phase_to_phase(p: f64) -> Phase;          // (p.rem_euclid(1.0) * 2^32).round()
pub fn f64_bpm_to_tempo(b: f64) -> Tempo;     // (b * 1e6).round()
```

**CLI argv-boundary f32 → fxp conversions** (one cast per parse):

```rust
pub fn f32_bpm_to_tempo(b: f32) -> Tempo;
pub fn f32_jitter_us_to_sigma(us: f32) -> connections::fixed::Pico;
pub fn f32_threshold_to_q15(t: f32) -> u16;
```

**Integer smoothstep / linear ramp** (inputs `u32`, output `u8`; used
by `envelope.rs` in T2):

```rust
pub fn linear_u8(t: u32, n: u32) -> u8;
pub fn smoothstep_u8(t: u32, n: u32) -> u8;
```

Implementation: `x = ((t as u64) << 24) / (n as u64)` (Q0.24), then
Hermite `3x² − 2x³` in `u128`, shift to u8. Bit-exact, no float.

**Re-exports**:

```rust
pub use connections::fixed::{Uni, Deci, Centi, Milli, Micro, Nano, Pico, HasResolution};
pub use connections::sample::{S44, S48, S88, S96, S176, S192, SampleRate};
```

### T3 — `crates/core/src/arb.rs` pulse_train

Signature flip: `pulse_train<R: SampleTime>(bpm: Tempo, ppq: u32,
jitter_sigma: Pico, n_pulses: u32, seed: u64) -> (Vec<f32>, Vec<R>)`.
Sample rate is derived from `R::HZ`, so the explicit `sr` argument is
dropped — callers pick a rate by choosing the `R` type parameter.
Swap the custom xorshift+Box-Muller for
`rand_pcg::Pcg64::seed_from_u64` + `rand_distr::Normal`. Hann-bell
waveform synthesis continues to write into a `Vec<f32>` PCM buffer
(that's the cpal ABI; documented exception).

Proptest strategies in `arb.rs` flip to `arb_bpm() -> Tempo` and
`arb_jitter_sigma() -> Pico` with `prop_oneof!` boundary bias.

### T6 — `crates/core/src/sync/source.rs`

```rust

    Internal { bpm: Tempo },
    External { pll: Pll<R> },

impl<R: SampleRate> PhaseSource<R> {
    pub fn phase_at_sample(&mut self, n: u64) -> Phase;
```

Internal branch: integer NCO via `inc_q32 = bpm.0 as u128 * 2^32 /
(60_000_000 * R::HZ)` with truncation on multiplication = modular
wrap. External branch: encapsulate the f64 phase projection inside a
`Pll::predicted_phase_at(elapsed: R) -> Phase` method so f64 stays
in the PI-exempt zone.

## Review

### Deviations from the plan

1. **`sync trace` pinned to 48 kHz rather than multi-rate dispatch.**
   The plan's T7 talked about `PhaseSource<R>` for any rate; the CLI
   consumer, however, pins `R = S48` in this sprint and rejects
   `--sr` values other than 48000 with a clear error. Reason:
   runtime-dispatch-on-rate requires a `match sr { 44100 => work::<S44>,
   48000 => work::<S48>, … }` shim that introduces its own design
   questions (enum over monomorphised trace helpers? trait objects?).
   Deferred to the v0.1 binary-runtime sprint where the audio device
   forces a rate selection anyway.

2. **Detect proptests dropped `arb_sample_rate`.** The plan's T4
   kept the strategy; the implementation pins `R = S48` for the
   same reason as #1 (rate-generic proptest requires per-rate
   monomorphisation or a dispatch helper). The detector algorithm
   itself is rate-agnostic — it operates on `&[f32]` and emits `Peak<R>`
   without consulting `R::HZ` — so multi-rate coverage was
   cosmetic. Listed as a follow-up.

3. **`integrator_clamp_keeps_bpm_positive` assertion shape.** The plan
   implied preserving the `out.bpm > 0` assertion. After the flip,
   `Tempo` can legitimately round to zero when the smoothed BPM
   is below 0.5 µBPM — which is not the regression the test is
   guarding against. Switched to asserting the PI-exempt
   `state().integrator > -1.0` and `state().freq_hz > 0.0`
   directly. Captures the original regression more faithfully.

4. **`source_internal_is_linear` tolerance ±1 ULP.** The plan treated
   the per-sample increment as constant. The implementation keeps
   `n · bpm · 2⁃³²` together in u128 to avoid a precomputed-inc
   rounding accumulation — the per-sample difference at u32-integer
   boundaries varies by ±1 ULP around the ideal. More accurate at
   large n than the alternative. Noted.

5. **`PULSE_WIDTH_SECS: f64` → `PULSE_WIDTH_PS: Pico`.** Plan spelled
   the constant's type as the new fxp form; done.

### `#[ignore]`d properties

None added. One pre-existing ignore (`swing_zero_mean_over_beat`)
carries over from PR #2 unchanged.

### Recommendations

- **Multi-rate dispatch shim** (blocks #1 and #2). Add a helper
  `sync_trace::trace_dispatch(sr, …)` that monomorphises the typed
  variant per rate, and reinstate `arb_sample_rate` coverage in the
  detect proptests via macro-generated per-rate test modules.
  Candidate for v0.1 Sprint 5 (the binary-runtime sprint).
- **`SampleTickConn` is still f64.** Orthogonal to this sprint's
  scope (it's in `time/conn.rs`, unrelated to `sync/*`). Channel/
  work (PR #4) consumes it with an f64 bpm argument at the CLI. A
  future pass could flip `SampleTickConn::new(sr, bpm: f64, ppqn)` to
  take `Tempo`, deriving all internal arithmetic from that
  integer. Track separately.
- **Extend the `SampleTime` trait upstream.** The `from_bits_q48_16`
  / `to_bits_q48_16` methods in agogo-core/fxp exist because
  `connections::sample::SampleRate` doesn't expose them. Once the
  API stabilises, push this trait into `connections` so downstream
  users don't re-derive it.
