# Plan 15 — PPQN 192→960 + `Grid` Heyting lattice + `TBase`/`Grid` split + SwingConfig cleanup

## Goal

Retrofit the time core to **960 PPQN**, split the lattice type
into **`TBase`** (the 9-variant binary axis: T1, T2, T4, …, T256)
and **`Grid`** (the full 36-element lattice as a product struct
`{ n: TBase, t: bool, q: bool }` with named consts), and
**clean up `SwingConfig`** to a signed `i8` tick offset with
the resolution typed as `TBase` — replacing v0.1's flat
14-variant enum, hardcoded-T16 detector, and `(amount, multiplier)`
shape with one coherent product representation that matches both
the LM-1 / MPC / TR-909 hardware vocabulary
(`doc/notes/note-2026-04-24-01.md`) and the polyrhythm DSL
(`doc/designs/dsl.md`).

## Context

`doc/versions/version-0.2.md` lists three sprint slots:

> 01 (this) — `time/` types & consts: bump PPQN to 960, add
>     quintuplet variants, relax lattice invariant from `2^i·3^j` to
>     `2^i·3^j·5^k`, re-prove LCM/GCD closure.
> 02 — Lattice & Conn laws at 960.
> 03 — Integer-exactness properties at 48k/96k.

This plan folds Slot 01 (PPQN + lattice) and the **`SwingConfig`
cleanup** together with the **`TBase`/`Grid` type split**. The
split is what would otherwise be a separate Plan 16; doing it
now avoids two back-to-back migrations that touch every
TBase-using site.

The product representation `Grid { n: TBase, t: bool, q: bool }`
makes the lattice's structure explicit: meet/join factor
component-wise, square-free becomes a type-level guarantee
(`t, q: bool`), and `tick_count` collapses from a 36-arm match
to one expression. The `TBase` enum (binary axis, 9 variants)
becomes the natural type wherever the model wants a binary
subdivision specifically — `SwingConfig.resolution: TBase`,
the "next-coarser binary" predicate, etc. Named consts like
`Grid::T16Q` survive on the struct so pattern matching and
human-readable code keep working; the morphism between consts
and `Grid` values is the same parser/printer
`doc/designs/dsl.md` needs.

The `SwingConfig` cleanup itself is **direct tick offset, no
division on the hot path**: the hardware drum-machine
vocabulary (`+80` = 66.6% shuffle at 960 PPQN, `-40` =
early-pushed off-beat) maps 1:1 onto an `i8`. With
`resolution: TBase`, the detection unifies to a single rule
`t.0 % r.tick_count() == 0 && (t.0 / r.tick_count()) & 1 == 1`
that works for every binary level — `TBase::T16` is MPC /
hip-hop 16th-note swing, `TBase::T8` is jazz / blues 8th-note
swing, and coarser levels are type-allowed but musically rare.
Rate-independence is moot now that 960 PPQN is final.

The non-binary `Grid` variants (triplet, quintuplet, p-track)
stand on their own — they extend the channel-divider grid
(e.g. `Channel.divider = Grid::T8Q` gives 20 quintuplet steps
per bar at exactly 192 ticks per step), independent of swing.
Swing's resolution is `TBase`, so `Grid::T8Q` cannot type-check
as a swing resolution by construction.

### T2 — Split into `TBase` (binary) + `Grid` (full lattice)

The v0.1 flat 14-variant `TBase` enum is replaced with two

#### Type shapes

```rust
/// Binary subdivision axis. 9 variants, each a power-of-2
/// fraction of the bar. Used wherever a binary subdivision is
/// required (swing resolution, "next-coarser binary" predicates).
#[derive(Copy, Clone, Debug, PartialEq, Eq, Hash, PartialOrd, Ord)]
pub enum TBase {
    T1, T2, T4, T8, T16, T32, T64, T128, T256,
}

impl TBase {
    /// Power of 2 in the bar/tick_count denominator.
    /// `T1.exp() = 0`, `T16.exp() = 4`, `T256.exp() = 8`.
    pub const fn exp(self) -> u32 { /* match */ }
    /// `bar >> self.exp()`. `T16.tick_count() = 240` at 960 PPQN.
    pub const fn tick_count(self) -> u32 { BAR >> self.exp() }
    pub const ALL: [Self; 9] = [Self::T1, Self::T2, /* ... */ Self::T256];
}

/// Lattice element. Product of `TBase` and two square-free
/// flags for the 3- and 5-axes. 36 named consts cover every
/// element; `Grid::ALL` enumerates them coarsest-first.
#[derive(Copy, Clone, Debug, PartialEq, Eq, Hash)]
pub struct Grid {
    pub n: TBase,
    /// Factor of 3 absent from tick count (triplet or p-track).
    pub t: bool,
    /// Factor of 5 absent from tick count (quintuplet or p-track).
    pub q: bool,
}

impl Grid {
    // 9 binary consts (t=q=false): coord_n = name_exp.
    pub const T1:   Self = Self { n: TBase::T1,   t: false, q: false };
    pub const T2:   Self = Self { n: TBase::T2,   t: false, q: false };
    // ... through T256
    // 9 triplet consts (t=true,  q=false): coord_n = name_exp − 1.
    pub const T2T:  Self = Self { n: TBase::T1,   t: true,  q: false };
    pub const T16T: Self = Self { n: TBase::T8,   t: true,  q: false };
    // ... through T512T (n = T256, t = true)
    // 9 quintuplet consts (t=false, q=true).
    pub const T16Q: Self = Self { n: TBase::T8,   t: false, q: true  };
    // ... through T512Q
    // 9 p-track consts (t=true, q=true).
    pub const T2P:  Self = Self { n: TBase::T1,   t: true,  q: true  };
    pub const T512P: Self = Self { n: TBase::T256, t: true,  q: true };

    /// One expression — no per-variant match.
    /// `tick_count = bar / (2^n.exp() · 3^t · 5^q)`.
    pub const fn tick_count(self) -> u32 {
        let denom = (1u32 << self.n.exp())
            * (if self.t { 3 } else { 1 })
            * (if self.q { 5 } else { 1 });
        BAR / denom
    }

    pub const ALL: [Self; 36] = [/* coarsest-first, see below */];
}
```

The 36 consts are enumerated coarsest-first so
`nicest_from_tick_count` (now a loop over `Grid::ALL`) keeps
picking the largest divisor.

#### Lattice at 960 PPQN — 36 elements

The closed set is the 36 divisors of `bar = 3840 = 2⁸·3·5`,
split by prime-factor structure into the four tracks the suffix
flags select:

| Track | `(t, q)` | Factor structure | Cardinality |
|-------|----------|------------------|-------------|
| Binary | `(false, false)` | 2^k · 3 · 5 | 9 |
| Triplet | `(true, false)` | 2^k · 5 | 9 |
| Quintuplet | `(false, true)` | 2^k · 3 | 9 |
| 15-tuplet | `(true, true)` | 2^k | 9 |

Concrete variants (named-const ↔ tick count):

| Track | Variants |
|-------|----------|
| Binary | T1 (3840), T2 (1920), T4 (960), T8 (480), T16 (240), T32 (120), T64 (60), T128 (30), T256 (15) |
| Triplet | T2T (1280), T4T (640), T8T (320), T16T (160), T32T (80), T64T (40), T128T (20), T256T (10), T512T (5) |
| Quintuplet | T2Q (768), T4Q (384), T8Q (192), T16Q (96), T32Q (48), T64Q (24), T128Q (12), T256Q (6), T512Q (3) |
| 15-tuplet | T2P (256), T4P (128), T8P (64), T16P (32), T32P (16), T64P (8), T128P (4), T256P (2), T512P (1) |

Lattice **top = `Grid::T1` = 3840** (1 bar). Lattice **bottom =
`Grid::T512P` = 1 tick** (~0.5 ms at 120 BPM). T128/T256 binary
and the entire quintuplet/p tracks are new beyond v0.1; T512T,
T512Q, T512P each extend their tuplet track past the binary
parent floor (the parent `T512` would be 7.5 ticks, non-integer
— "ghost parent" stored as `n: TBase::T256, t/q: true`).

**No upward extension** — top stays at the bar pending a
separate Heyting-laws check on multi-bar variants.

#### Lattice algebra factors component-wise

In coords `(n, t, q)` (with `n = TBase::exp`):
- `meet = (max(n_a, n_b), t_a ∨ t_b, q_a ∨ q_b)` (gcd of tick
  counts ↔ max of denom exponents).
- `join = (min(n_a, n_b), t_a ∧ t_b, q_a ∧ q_b)` (lcm).
- `top  = (0, false, false) = Grid::T1`.
- `bot  = (8, true, true)   = Grid::T512P`.
- `meet` and `join` are integer max/min plus boolean or/and —
  no per-variant table.

Heyting implication and pseudo-complement factor the same way:
`(a → b) = (a.n → b.n, a.t → b.t, a.q → b.q)` where each
component uses its own algebra (chain on the `n`-axis, two-element
Boolean on `t` and `q`). Square-free is enforced by the `bool`
typing — there is no way to express `i = 2`.

#### DSL morphism

`Display` and `FromStr` for `Grid` ARE the atom parser/printer
that `doc/designs/dsl.md` requires. `Display` writes the canonical
name from `(n, t, q)`:

```rust
impl Display for Grid {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        // Plan-name index: binary uses n.exp(); non-binary
        // tracks use n.exp() + 1 (because Tnt = (2/3) · Tn
        // shifts the denominator by one factor of 2).
        let plan_exp = self.n.exp() + (self.t || self.q) as u32;
        let plan_idx = 1u32 << plan_exp;
        let suffix = match (self.t, self.q) {
            (false, false) => "",
            (true,  false) => "t",
            (false, true)  => "q",
            (true,  true)  => "p",
        };
        write!(f, "t{plan_idx}{suffix}")
    }
}
```

`FromStr` is the inverse: parse `"t16q"` → `(plan_exp=4, suffix='q')`
→ `Grid { n: TBase::T8, t: false, q: true }`. Upper-case suffixes
(`"T16Q"`) accepted at parse for DSL ergonomics; canonical
`Display` is lower-case (matches the `agogo run --ch div=…` /
`agogo time schedule --grid …` shell-friendly form).

### T3 — `SwingConfig` cleanup to `i8` + `resolution: TBase`

File: `crates/core/src/time/swing.rs`.

#### Rationale

Current shape: `SwingConfig { amount: i32, multiplier: i32 }`
(displacement = `amount × multiplier`), with `is_swung_step(t)`
hardcoded to T16. The module's own plan-deviation comment
(`swing.rs:7-11`) flags the hardcoded grid as a known smell.

New shape: signed `i8` tick offset with `resolution: TBase`
typing the swing grid directly. Direct tick semantics — `+80`
is the full 66.6% shuffle at 960 PPQN (the 1st off-16th lands
two-thirds of the way to the next on-beat), `-40` pushes the
off-beat early — matching `note-2026-04-24-01.md`. Detection
unifies to one rule for any binary level: `t.0 % r.tick_count()
== 0 && (t.0 / r.tick_count()) & 1 == 1`. The two musically
common cases — MPC 16th-note swing and jazz 8th-note swing —
are just `r = TBase::T16` and `r = TBase::T8` under this rule.

`Grid::T8Q` and other non-binary `Grid` consts cannot type-check
as a `SwingConfig.resolution` because the field type is `TBase`,
not `Grid`. Square-free is at the lattice; binary-only is at the
swing.

The API stays tick-in / tick-out (`fn effective_tick(cfg, t) →
Tick`). A step-index API was considered but `scheduler.rs:123-127`
iterates master ticks and never maintains a step counter, so
threading one through would just relocate the existing
`t / r.tick_count()` division.

#### Code

```rust
use crate::time::tbase::TBase;

#[derive(Copy, Clone, Debug, PartialEq, Eq, Hash)]
pub struct SwingConfig {
    /// Binary subdivision the swing grid lives on.
    /// `T16` = MPC / hip-hop 16th-note swing; `T8` = jazz /
    /// blues 8th-note swing; coarser levels (T4, T2, T1) are
    /// type-allowed but musically rare.
    pub resolution: TBase,
    /// Signed tick offset for swung steps. Positive = delay
    /// (off-beat plays later), negative = push (off-beat plays
    /// early). The musically-sensible bound is ±(resolution.tick_count()/2);
    /// at `T16` that's ±120 ticks at 960 PPQN.
    pub amount: i8,
}

/// True when `t` is on a swung position under `cfg.resolution`.
/// One unified rule for every binary level: `t` must be aligned
/// to the resolution grid AND its step index must be odd.
pub fn is_swung_step(t: Tick, cfg: &SwingConfig) -> bool {
    let tc = cfg.resolution.tick_count();
    t.0 % tc == 0 && (t.0 / tc) & 1 == 1
}

pub fn effective_tick(cfg: &SwingConfig, t: Tick) -> Tick {
    if !is_swung_step(t, cfg) {
        return t;
    }
    let shifted = i64::from(t.0) + i64::from(cfg.amount);
    Tick(shifted.clamp(0, i64::from(u32::MAX)) as u32)
}

/// `Tick`-side alignment check. `g: Grid` lets this work for
/// any lattice element, not just binary.
pub fn is_aligned(t: Tick, g: Grid) -> bool {
    t.0 % g.tick_count() == 0
}
```

The unified rule reproduces v0.1's behaviour for the two cases
v0.1 actually used:
- `T16` resolution: `t.0 % 240 == 0 && (t.0 / 240) & 1 == 1` —
  swings ticks {240, 720, 1200, 1680, …} (every odd 16th).
  Identical to v0.1's hardcoded T16 detector.
- `T8` resolution: `t.0 % 480 == 0 && (t.0 / 480) & 1 == 1` —
  swings ticks {480, 1440, 2400, 3360} (every odd 8th = the
  "and" of each beat). The off-8ths a v0.1 caller couldn't
  reach without modifying the hardcoded T16 detector.

#### Knock-on changes

1. `is_swung_step` regains a `cfg: &SwingConfig` parameter
   (v0.1 dropped it for Haskell parity; resolutional dispatch
   needs it back). The plan-deviation comment in `swing.rs`
   becomes obsolete and is removed.
2. **Sign convention flips.** Positive `amount` now *delays*
   the off-beat (drum-machine convention). v0.1 subtracted on
   off-beats; the new code adds. The scheduler's `swing_d`
   computation (T4) flips correspondingly.
3. `is_aligned`'s second argument widens to `Grid` (was the
   v0.1 `TBase` lattice element).
4. `swing_zero_mean_over_beat` stays `#[ignore]`d. Still
   one-sided; the `#[ignore]` Review note carries forward.
5. `arb::arb_swing` becomes `(arb_tbase, arb_i8_amount)` — see

resolution. `T16` resolution reproduces v0.1's detection

#### Algebraic structure

The unified `resolution: TBase` ties cleanly to agogo's `Time`
/ `ticks` / `quantize_at` primitives in
`crates/core/src/time/tick.rs:42` and
`crates/core/src/time/conn.rs:56`. Six structural invariants
fall out of the unified rule, each parameterised over the
resolution `r: TBase`:

- **Set-difference characterisation.** For any binary `r`, the
  detector identifies the event set `r \ next_coarser(r)` (firings
  on `r`'s grid that aren't on the next-coarser binary grid).
  Equivalently: `quantize_at(Grid::from_tbase(r)).floor(t).beats`
  is odd. Each `TBase` value corresponds to exactly one set-difference
  layer in the binary chain.
- **Coarse-binary invariance.** For any `r' ⊑ r` in the binary
  chain (i.e., `r'.exp() < r.exp()`, so `r'` has more ticks per
  step), `is_aligned(t, Grid::from_tbase(r')) ⟹ ¬is_swung_step(t, &{r, _})`.
  The bar (`T1`) is always an on-beat at every resolution.
- **Detection factors through `quantize_at(r)`.**
  `is_swung_step(t, cfg)` depends only on
  `quantize_at(Grid::from_tbase(cfg.resolution)).floor(t)`. Non-`r`-aligned
  ticks (those on triplet / quintuplet / p grids) get the swing
  decision of their floor — swing never crosses tracks.
- **Bar-periodicity.** `effective_tick(cfg, t + k·bar) =
  effective_tick(cfg, t) + k·bar`. The bar = `2^(8 - r.exp())`
  resolution-steps, always an even multiple, so the parity
  bitmask is bar-invariant.
- **Density halves per level.** Within one bar, the count of
  swung positions = `bar.tick_count() / (2 · r.tick_count())`.
  At `r = T16` that's 8; at `T8` that's 4; at `T4` that's 2; at
  `T2` that's 1. Density halves with each step up the binary
  axis — a direct readout of `r.exp()`.
- **Order-preserving within the safety bound.** For
  `|amount| ≤ r.tick_count() / 2`, `effective_tick` is monotonic
  on `Tick`. Composing with `time_to_tick`, monotonicity lifts
  to `Time` — the same shape `ticks()` already satisfies via
  `ticks_monotonic` (`conn.rs:521`). `effective_tick` isn't a
  Galois connection (it's a self-map, not an adjoint pair), but
  its monotonicity is *compatible* with the `Tick` ↔ `Time`
  adjunction, so swung ticks flow through `from_ticks_floor` /
  `time_to_tick` without disturbing the order structure.

All six are listed as proptests in the Verification table —
parameterised over `r: TBase` rather than enumerated per
musical case.

### T7 — Heyting-algebra laws for `Grid`

| Property | Invariant |
|----------|-----------|
| `grid_lattice_top_bottom` | `Grid::T1` is the unique top (lcm-identity = 3840 ticks = bar); `Grid::T512P` is the unique bottom (gcd-identity = 1 tick). |
| `grid_meet_join_closure` | For all `(a, b) ∈ Grid × Grid`, `lcm(a,b)` and `gcd(a,b)` are themselves `Grid` consts (closure). Trivially true under the product representation: `meet(a, b) = (max(a.n, b.n), a.t ∨ b.t, a.q ∨ b.q)`, all components stay in their factor's range. |
| `grid_distributive_lattice` | `a ∧ (b ∨ c) = (a ∧ b) ∨ (a ∧ c)` (and dual) for all triples. Falls out of `TBase` being a chain (distributive) and `bool` being distributive — the product of distributive lattices is distributive. |
| `grid_heyting_pseudo_complement` | For each `(a, b)`, the relative pseudo-complement `a ⇒ b = max{c : a ∧ c ⊑ b}` exists in `Grid`. Factors component-wise: `(a ⇒ b) = (a.n ⇒ b.n, a.t ⇒ b.t, a.q ⇒ b.q)`. |
| `grid_factors_as_product` | `Grid::ALL` enumerates `TBase::ALL × {false, true} × {false, true}` exactly (cardinality 9 × 2 × 2 = 36, no duplicates). Confirms the product structure. |

Closure is structural: every `Grid` value is `(n, t, q)` with
`n ∈ TBase` (9 levels) and `t, q: bool`. Meet/join in the
product `n × bool × bool` cannot escape — `max(n_a, n_b)` stays
in `TBase`, `t_a ∨ t_b` stays in `bool`. Heyting falls out of
`TBase` being a chain and `bool` being a Boolean algebra —
products of Heytings are Heyting.

## MR split

Recommend **one PR**. PPQN bump + `TBase`/`Grid` split + lattice
extension + SwingConfig cleanup all touch the same module tier
(`crates/core/src/time/`). Splitting risks intermediate states
where the type names mean different things, or where `SwingConfig`
still has the v0.1 `(amount, multiplier)` shape but the proptests
run at 960. The diff is large but mechanically uniform — most of
it is `s/TBase/Grid/` at sites holding any-subdivision values, and
the new `time/grid.rs` module. Single commit window keeps the time
core coherent.

## Reuse / do not duplicate

  T1's bump is a one-line change because every call site already

### Design deviations from the plan

1. **`SwingConfig` field rename: `swing-mult` → `swing-res`.** Plan
   T3 didn't spell out a CLI rename for the `swing-mult` key, but
   the v0.1 `multiplier: i32` field is gone — the new shape uses
   `resolution: TBase`. The channel-spec mini-language (`agogo run
   --ch …`) drops `swing-mult` and adds an optional `swing-res`
   key that defaults to `t16`. Documented in the spec module's
   header comment and tested by `parse_swing_res_default_t16` /
   `parse_swing_res_explicit` / `parse_rejects_non_binary_swing_res`.

2. **`quantize_at` dispatch is an if-chain, not a `match`.** Plan
   T2 said "match on the const and dispatch to the per-const fn
   pair". Rust's `match` doesn't accept associated `Grid::T16`-style
   pattern arms (Grid is a struct, not an enum), so the dispatch is
   a 36-arm `if g == Grid::T16 { … }` chain. Equivalent semantics,
   slightly more verbose; the macro that generates the per-variant
   `_ceil` / `_floor` fns still handles the body.

3. **CLI flag rename `--tbase → --grid` only on `time schedule`.**
   The `channel trace` and `midi trace` commands already used
   `--divider`, which keeps its name and just parses to `Grid`
   instead of `TBase`. Only `time schedule`'s explicit `--tbase`
   flag was renamed to `--grid` (the value parses to a 36-element
   `Grid`, so the new name reflects the new semantics).

4. **Demo divider value shifts at the PPQN bump.** The plan's
   build-gate listed `--divider t32t` carrying forward from v0.1.
   At 192 PPQN, `t32t` = 8 ticks = PPQN/24 = MIDI clock cadence.
   At 960 PPQN, that role shifts to `t64t` (= 40 ticks). The
   build-gate line above is now updated; the CLI / runtime is
   unchanged.

5. **`Grid::tick_count` formula bug fixed in the migration.** The
   pre-existing worktree had `let three_factor = if self.t { 1 }
   else { 3 };` — backwards relative to the doc comment and the
   plan's formula `tick_count = BAR / (2^n.exp() · 3^t · 5^q)`.
   Spot-check tests (e.g. `tick_count_spot_checks`,
   `from_ticks_240_is_one_sixteenth`) caught this once they were
   able to run; fixed inline. Worth flagging because the lattice
   tests in the worktree's first draft would have appeared green
   only because the lib didn't compile end-to-end (so no tests
   ran at all).

### `#[ignore]`d properties — re-enablement plan

- `time::swing::tests::swing_zero_mean_over_beat` carries forward
  from v0.1 with the same `#[ignore]` annotation. Reason: the
  current swing semantics is one-sided (positive `amount` always
  delays off-beats), so the sum across one beat at T16 is
  `2·amount`, non-zero in general. To re-enable, swing would need
  to alternate signs across consecutive off-beats so they cancel
  pairwise. That's an API/semantics change with no current call-
  site demand — re-enable when bidirectional swing lands as its
  own plan.

### Recommendations for v0.3+

- **CLI auto-snap at non-divisor BPMs.** The new `time::exact_rates`
  proptests pin which `(sr, bpm)` pairs are integer-exact at 960
  PPQN. The natural follow-up is the deferred "auto-snap channel
  offsets to fixed BPMs at 48k/96k" item — surface a CLI warning
  when the user picks a non-divisor BPM (e.g. "BPM 137 → ~350.36
  samples/tick — not exact at 48k / 960 PPQN; nearest exact is
  BPM 125 or 150").
- **Heyting algebra → biheyting.** Plan T7 ships the Heyting laws.
  The dual co-Heyting subtraction (`a \\ b = min{c : a ⊑ b ∨ c}`)
  also factors component-wise on `(TBase × bool × bool)` and would
  give us the full biheyting structure for free. Useful for
  channel-divider arithmetic where "what's left after removing
  the binary contribution from a triplet grid" is a natural query.
- **Multi-bar lattice extension.** Top is currently `Grid::T1`
  (= 1 bar). The plan deferred upward extension pending a Heyting-
  laws check for multi-bar variants. Now that the laws are tested
  on the 36-element product, extending to `T1/2` (2 bars), `T1/4`
  (4 bars) etc. is a structural addition: just widen the `n`
  axis. Defer until the channel scheduler or DSL needs it.
- **Time-resolution invariant under `swing-res` change.** The new
  `swing-res` key opens up "what does it mean for a channel to
  have `divider = T8Q` (quintuplet) and `swing-res = T8` (binary)?"
  Currently swing fires only when the divider tick happens to land
  on the resolution grid — for `T8Q × T8` that's once per bar at
  tick 0, almost never. Worth documenting (or tightening the type
  to forbid mismatched divider/resolution combinations) before a
  user trips on the surprise.
