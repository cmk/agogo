# Plan 2026-04-28-07 — Three-mess cleanup

## Goal

Three intertwined cleanups in `crates/core/`:

1. **Widen `Tick` from `u32` to `u64`.** The current `u32` overflows in
   `time_to_tick` (`beats: u32 × tick_count: u32`); `checked_mul().expect()`
   defends arithmetically and `arb_time` defends by clamping `beats`
   to `0..=100_000` — the proptest-coverage-faking anti-pattern. With
   `Tick = u64`, `time_to_tick` is panic-free and `arb_time` can use
   `any::<u32>()` honestly. `from_ticks` becomes partial
   (`Option<Time>`) because `Time.beats` stays `u32`.

2. **Remove the `Ple` trait and `crates/core/src/preorder.rs`.**
   Upstream `connections` removed `Ple` because the lawful framework
   now consumes `Eq + PartialOrd` directly. agogo kept it because
   `Grid`'s divisibility preorder isn't the natural order on its
   fields — but `PartialOrd for Grid` is already defined via `ple()`,
   so `<=` already means divisibility. The only conflict is `TBase`,
   whose derived `PartialOrd` runs in the *opposite* direction of its
   `Ple` (declaration order vs. divisibility). Replacing `TBase`'s
   derive with a custom `PartialOrd` that mirrors divisibility (same
   shape `Grid` uses) lets the ~75 `.ple(&x)` call-sites collapse to
   `<= x`.

3. **Rename the four single-type `Conn`s in `time::conn` to the
   8-char convention.** `ticks → ticktime/TICKTIME`,
   `rat_tick → wholtick/WHOLTICK`, `time → timetime/TIMETIME`,
   `grid → gridgrid/GRIDGRID`. `quantize_at` is documented as a Conn
   *constructor* (parametric family) — exempt from the 8-char rule.

Single sprint because (1) and (2) both touch `tick.rs` and the
combined diff is small enough that splitting would just spend three
PRs of branch ceremony.

## Dependency Graph

```
T1 (Widen Tick → u64)
    │
    └──> T2 (Remove Ple + preorder.rs)

T3 (Rename 4 Conns; quantize_at exempt) — independent of T1, T2
```

Strict ordering: T1 → T2 (both touch `tick.rs`). T3 is independent;
do it last so its commit is easy to revert if scope drifts.

## Tasks

### T1 — Widen `Tick` to `u64`

**Problem.** `Tick(pub u32)` is the master counter. `time_to_tick`
does `beats: u32 × tick_count: u32` which overflows u32. The
`checked_mul().expect()` defends arithmetically; `arb_time` defends
by clamping `beats` to `0..=100_000` — the
"bound the generator to keep arithmetic safe" anti-pattern called
out in `feedback_proptest_coverage_faking.md`.

**Solution.**

- `pub struct Tick(pub u32)` → `pub struct Tick(pub u64)` in
  `crates/core/src/time/tick.rs:28`.
- `time_to_tick`: drop `checked_mul`, use
  `Tick(u64::from(t.beats) * u64::from(t.base.tick_count()))`. Remove
  the `# Panics` paragraph; add a "Why u64" comment referencing the
  `u32 × u32 → u64` arithmetic.
- `from_ticks` / `from_ticks_floor` / `nicest_from_tick_count` take
  `u64`. Return `Option<Time>` — `None` when no `(beats, base)` pair
  fits with `beats ≤ u32::MAX`. The horizon for `Some(_)` is
  `n ≤ u32::MAX × Grid::T1.tick_count() = ~1.65×10¹³`.
- **Conn API tension.** `Conn::ceil` is total `fn(Tick) -> Time`.
  Resolution: `ticks_ceil` calls `from_ticks(n).expect("...")` with a
  documented precondition `n.0 ≤ u32::MAX × Grid::T1.tick_count()`.
  Cap `arb_tick` at that bound so proptests never hit the partial
  region. Runtime callers (transport, scheduler) call `from_ticks`
  directly and handle `None` per their semantics — for transport
  state, "loop back to 0:00.00" is a sensible default.
- `arb_time` and `arb_small_time` (`crates/core/src/arb.rs`) use
  `any::<u32>()` (full domain) and `0u32..=50` respectively. Drop
  the `arb_time bounds beats well inside that` comment from
  `tick.rs:56`.
- `arb_tick` (`arb.rs:184-191`): cap the upper bound at
  `u32::MAX as u64 * Grid::T1.tick_count() as u64`. Add a
  `Just(...)` arm at the boundary; keep `Just(Tick(0))` and
  `Just(Tick(Grid::T512P.tick_count()))` and
  `Just(Tick(Grid::T1.tick_count()))` as named edges. Drop the
  `Just(Tick(u32::MAX))` arm since `u32::MAX` is no longer the
  type maximum and not on a meaningful boundary either.
- Update the ~30 cast sites that touch `Tick.0`. Categories:
  - **Simple `as u32` → `as u64`** (`tick.rs:83`, `conn.rs:73`,
    `conn.rs:269, 799, 809`).
  - **i64 arithmetic on tick + amount** (`swing.rs:60, 275, 311,
    391, 402`): `i64::from(t.0)` no longer compiles for u64.
    Switch to `i128::from(t.0)` and clamp to `[0, u64::MAX]`.
  - **u128 arithmetic** (`sync/sample_tick.rs`): `u128::from(tick.0)`
    already accepts u64.
  - **f64 conversions** (`time/float.rs:123`, `sample.rs:658`): past
    `2^53 ≈ 9×10¹⁵` lose precision. Verify those paths don't see
    ticks that large; if they could, replace with rational/i128
    arithmetic.
- `swing.rs:218-219` test literals using `u32::MAX` — keep them as
  named "u32 boundary" cases (those tests assert overflow-clamping
  behavior); don't auto-widen to `u64::MAX`.

### T2 — Remove `Ple` trait and `preorder.rs`

**Problem.** `Ple` is a single-method trait whose 6 impls collapse
to `<=` for 5 of the 6 types under existing `PartialOrd`. It exists
because `TBase`'s derived `PartialOrd` runs opposite of its
divisibility preorder.

**Pre-step: per-type semantic-equivalence audit.**
- `Tick` (`tick.rs:30`): `Ple == derived PartialOrd`. ✓
- `U7`, `U4` (`midi.rs:38, 72`): `Ple == derived PartialOrd`. ✓
- `Time` (`tick.rs:143`): `Ple` chains through `time_to_tick`; `Ord`
  (`tick.rs:131-135`) also goes through `time_to_tick.cmp`. ✓
- `Grid` (`grid.rs:190`): `PartialOrd for Grid` (`grid.rs:200-208`)
  is literally defined via `ple`. ✓
- `TBase` (`tbase.rs:96`): derived `PartialOrd` is opposite of `Ple`
  (declaration order vs. divisibility). **Conflict.**

**Solution.**

1. Replace `derive(PartialOrd, Ord)` on `TBase` with a custom impl
   mirroring divisibility (`a <= b ⟺ a.exp() >= b.exp()`). Keep
   `derive(Eq, PartialEq, Hash)`. Add `impl Ord` since divisibility
   on `TBase` is total. Unit-test `T256 < T128 < … < T1`.
2. **Verify no caller relies on the old declaration-order direction.**
   Grep `TBase::ALL.*<|TBase::T\w+.*<|min|max|sort|cmp` and audit
   each hit. Most `TBase` use is via `.exp()` / pattern matching, not
   ordering — but verify.
3. Replace all `.ple(&x)` call-sites with `<= x`. ~75 total across
   `tbase.rs` (16), `grid.rs` (55+), `conn.rs` (30+), `midi.rs` (3),
   `tick.rs` (1).
4. Remove the 6 `impl Ple for ...` blocks.
5. Remove the 5 `use crate::preorder::Ple` imports.
6. Remove `pub mod preorder;` from `crates/core/src/lib.rs`.
7. Delete `crates/core/src/preorder.rs`.
8. Update `conn.rs` module-level doc (lines 22-26) to drop the `Ple`
   reference. The `div_le` ad-hoc helper discussion is unaffected
   (it's about pair-divisibility on lattice tests, not `Ple`).

### T3 — Rename 4 Conns to the 8-char convention

**Problem.** `pub fn ticks() -> Conn<Tick, Time>` and 3 sibling
Conns in `conn.rs` violate the 8-char Conn naming rule. Examples
in upstream + agogo (`F032F016`, `F064FD06`, `FD12S048`) confirm
4+4 = 8 with zero-padding.

**Mapping.**

| Current | Target accessor | Sides | Notes |
|---------|-----------------|-------|-------|
| `ticks` | `ticktime` / `TICKTIME` | `Tick → Time` | clean 4+4 |
| `rat_tick` | `wholtick` / `WHOLTICK` | `Whole → Tick` | `Whole` is a 5-char alias for `Rational64`; the 4-char short is `Whol` (matches upstream `DURN` for `Duration`, `DATE` for `Date`). |
| `time` | `timetime` / `TIMETIME` | `(Time, Time) → Time` | pair-Conn; duplicate the side name. |
| `grid` | `gridgrid` / `GRIDGRID` | `(Grid, Grid) → Grid` | pair-Conn; duplicate the side name. |
| `quantize_at` | (unchanged) | `Tick → Time` per `Grid` | parametric Conn family — exempt. |

**Solution.**

1. `ticks → ticktime`. `pub fn ticktime() -> Conn<Tick, Time>`.
   Helpers `ticktime_ceil`, `ticktime_inner`, `ticktime_floor`. Tests
   `ticktime_adjoint` etc. Doc-table entry updated.
2. `rat_tick → wholtick`. `pub fn wholtick() -> Conn<Whole, Tick>`.
3. `time → timetime`. `pub fn timetime() -> Conn<(Time, Time), Time>`.
4. `grid → gridgrid`. `pub fn gridgrid() -> Conn<(Grid, Grid), Grid>`.
5. `quantize_at` keeps its name. Document the exemption in the
   `conn.rs` module-level comment: "parametric Conn families are
   exempt from the 8-char rule, since each instance is named by the
   parameter."
6. Workspace-wide ripgrep for old names. Explore agent found
   references confined to `conn.rs`, but verify with
   `rg '\b(ticks|rat_tick)\(\)'` and inspect every hit.

## Resolved decisions

- **Conn rename scope:** all 5 — `ticks`, `rat_tick`, `time`, `grid`
  (renamed), plus `quantize_at` (exempt as a Conn-constructor).
- **`from_ticks` totality:** return `Option<Time>`. Conn API unwraps
  under a documented precondition; runtime callers handle `None`
  per their semantics ("loop back to 0:00.00" for transport).
- **Pair-Conn names:** duplicate the side name (`TIMETIME`,
  `GRIDGRID`).

## Review

All three tasks landed green. No `#[ignore]`'d properties were added;
the pre-existing `swing_is_bar_periodic` ignore (T1 off-by-one bug)
was preserved and its proptest was widened to u64 alongside the rest
of `swing.rs`.

**Design deviations.**

- `quantize_at` keeps its name as a Conn-constructor (parametric
  family); the 8-char rule applies to constants/accessors, not
  builders. The exemption is documented in the `conn.rs` module
  doc.
- `Tick` widening rippled to ~30 cast sites — `swing.rs` switched
  to i128 throughout (the existing i64 arithmetic on `tick + amount`
  no longer fits when `tick: u64`); `envelope.rs::linear_u8` /
  `smoothstep_u8` widened from u32 to u64 with u128 internal Q-frac
  math; `sample_tick.rs::to_tick` clamps at `u64::MAX` instead of
  `u32::MAX`. No precision regressions reachable from `arb_tick`'s
  capped horizon.
- `from_ticks` and `from_ticks_floor` now return `Option<Time>`. The
  `ticktime` Conn unwraps under a documented precondition so
  `Conn::ceil` stays total. Runtime callers (none yet) handle `None`
  themselves.
- `TBase` lost `derive(PartialOrd, Ord)` and gained custom impls
  mirroring divisibility. Audited via grep that no external caller
  relied on the old declaration-order direction (none did).
- The `Heyting` and `Coheyting` impls on `Grid` keep working: their
  bodies use `meet`/`join` and `<=` (which after T2 means
  divisibility on `Grid`), so the lattice connections in `conn.rs`
  remain adjoint-lawful.

**Recommendations.**

- A future `BoundedTick` newtype could encode the
  `u32::MAX × Grid::T1.tick_count()` precondition at the type level,
  removing the `expect(...)` from `ticktime_ceil` / `ticktime_floor`.
  Out of scope for this sprint.
- The transport / scheduler caller-side handling of
  `from_ticks(...) == None` ("loop back to 0:00.00") is not
  exercised yet — no current code path accumulates ticks past the
  horizon. When such a path appears, the wrap semantics needs an
  explicit decision (and a test).
