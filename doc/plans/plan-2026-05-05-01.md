# Plan 2026-05-05-01 - Stereo metronome cleanup

## Goal

Tighten the generated audio metronome path so the README 3:2 example is
recordable on normal stereo ch1-2 without opening wide multichannel streams or
clipping coincident pulses.

This sprint intentionally avoids a general mix bus. Generated audio metronome
output supports one or two audio-click channels only: the first is left-only,
the second is right-only, and a third errors at the CLI boundary.

## Tasks

### T1 - Make generated audio output explicitly stereo

Add explicit output-channel metadata to `AudioIo`, route output-only cpal
streams as interleaved stereo, and reject mono-only or multichannel-only output
configs instead of silently fanning mono out.

### T2 - Replace the click timbre and lower gain

Replace the square-wave click with deterministic low-pass filtered white noise.
Each audio-click channel owns stable render state, including a cutoff in
`[200, 8000]` Hz, fixed-point filter state, PRNG state, and click counter.

Keep the implementation allocation-free in the audio callback and avoid stored
floats outside the existing PCM ABI boundary.

### T3 - Hard-pan one or two metronome channels

Route the first parsed audio-click channel to stereo left and the second to
stereo right. Reject more than two audio-click channels before opening devices.
Preserve CV pulse output as dual-mono stereo until a later dedicated CV routing
feature exists.

### T4 - Remove audio-only MIDI SPSC allocation

Split callback MIDI sink ownership so MIDI-capable runs use the existing SPSC
producer/drain thread, while audio-only generated output uses a no-op MIDI sink
and allocates no SPSC ring.
